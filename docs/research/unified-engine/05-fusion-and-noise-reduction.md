# 05 - Evidence fusion and noise reduction (unified diff engine research)

Research date 2026-10-14. Extends, does not repeat: `01-patchtrace-build.md` (L1 correspondence, L2 change significance), `02-bindiff.md`, `03-ghidriff-rizin.md` (engine behaviour, measured), `04-structural-matching-prior-art.md` (L1 cascade, propagation, assignment, normalisation ladder, Windows pitfalls), SPEC-27 (`../../specs/multi-engine-evidence-calibration.md`), SPEC-28 (`../../specs/calibration-corpus-and-model.md`: identity calibration, corpora, abstention), SPEC-30 (`../../specs/patch-intent-localization-engine.md`).

## 0. Bottom line
1. "Not reported modified" is not evidence of "unchanged" [src S3, S1]. Ghidriff diffs a matched pair only if body size or reference count differs (its third clause needs `min_func_len` < 10; default 10), skips pairs matched by BulkBasicBlockMnemonicHash or decompiled-text equality outright (main and pinned 4f5d895; PyPI 1.0.0 lost the skip to a missing comma, 03 s0), and sets `code` only if the text differs AND the mnemonic or block list differs. BinDiff identifies instructions by mnemonic prime and never sets flag O. Constant, mask, struct-offset and callee-target edits, the typical shape of a security fix, can pass both: on zlib 1.3 -> 1.3.1 Ghidriff reported `modified` = 0 for constant-only edits (`cmp esi,0x100` -> `0x200`) and one of three genuine code changes (`shl` -> `shr`, same size) was invisible [run 03 s3]. Best value per cost: an operand-delta channel (R1, F2-F3).
2. The `modified` list is also noisy: 6 of the 11 modified functions in Ghidriff's own README run (ntoskrnl 22621.1344 -> 1413) have no code diff, only address, refcount, length or called/calling rows [src S3]. Typed downgrade rules (R3, F4, F6) remove that class using data PatchTrace already stores (slice 0, section 8).
3. Fusion rule: group evidence into independence components by shared D_* dependency tags, max-pool inside a component (idempotent, like the cautious rule), add learned weights across components, calibrate, abstain. Reject Dempster's rule (assumes distinct bodies of evidence [doc S6]), naive-Bayes products, majority votes and score averaging. Ghidriff already embeds BSim and VT-style correlators and a Ghidra-exported BinExport shares function boundaries, thunks and names, so "three engines agree" is mostly one opinion [src S3, `calibration/features.py`].
4. L1 (pairing) stays probabilistic per SPEC-28. L2 (materiality) should be proof-tiered: `cosmetic` only when a named, sound normalisation proves equality (the bucket then cannot hide a change), `material` only for a semantic-class delta corroborated by a second channel, everything else `review`.
5. Semantic tiers: cheap (masked hash, operand classes, canonical pseudo-code, CFG/callee/constant multisets; 57k insn/s in Python+capstone, about 35 s per side for 8 MB of .text [own, inf]) removes most compiler noise; medium (Ghidra p-code/BSim-style features, Apache-2.0) adds register, stack and instruction-order invariance but BSim does not encode callee identity [src S2], so the callee/constant channel must stay; expensive (bounded SMT on residual small blocks) is optional and off by default.
6. Avoid as core: neural embeddings (PyTorch/TensorFlow wheels 124-351 MB, CUDA and IDA assumptions, mixed licences), pyvex/angr in the product (libVEX is GPL), trace-based equivalence (executes the target), LLM suppression of findings, copying Diaphora (AGPL) or Ghidriff (GPL-3) code.
7. Evaluate with A/A null rebuilds, planted mutations, source-diff-labelled open-source patch pairs and local-only PDB-labelled Windows pairs; headline metric = changed-set false-positive rate with lineage-cluster intervals, plus risk-coverage curves (section 7).

## 1. Engine behaviour that drives the design [src unless marked]
- Ghidriff `VersionTrackingDiff` order (S3): SymbolsHash, ExactBytes, ExactInstructions (operands masked), StructuralGraphExact (only counts of blocks, edges, calls), ExactMnemonics, BSim (seeded with exact matches, on by default), BulkInstruction, SigCallingCalled, StringsRefs, StrUniqueFuncRefs, SwitchSig, StructuralGraph and BulkBasicBlockMnemonic (one-to-many allowed), implied matches, decompiled-text equality. Each stage sees only still-unmatched functions; a code comment says the order "has major impact on accuracy". Sequential elimination is its only anti-double-counting device, so corroboration is discarded once a pair is accepted.
- Implied matches (S3 `implied_matches.py`) take any accepted caller pair and add the call-site-aligned callee pair with no vote or conflict test; Ghidra AutoVT defaults to >= 2 votes and 0 conflicts (S2 `VT_AutoVT.html`). A callee swapped at the same call site can be implied onto the wrong partner [inf].
- Change decision (S3 `ghidra_diff_engine.py` L1364-1404, L1666-1769; `version_tracking_diff.py` L266): as in section 0 item 1, plus `address` is appended whenever the entry moved and `called`/`calling` compare function-name strings (default `FUN_<address>` names of unnamed callees change every rebuild [inf]). `normalize_ghidra_decomp` (L1413) renames LAB/DAT/SUB/UNK/EXT/FUN_/OFF_ labels by first appearance, one label per type per line (TODO in code), and leaves `local_`/`uVar`/`param_` names. L440 stores `str(code.getMnemonicString)` without a call; on Ghidra 12.0.4 that is one constant string for every instruction, so `m_ratio` is only an instruction-count ratio and `code` really rests on `b_ratio` or size [run 03 s2].
- README run (S3): 60,664 functions over both sides, 99.997 % matched, 11 modified = 5 code + 6 non-code; matches by 27,893 SymbolsHash, 693 StructuralGraphHash, 123 ExactInstructions, 100 ExactBytes, 2 BulkInstruction; diff stage 86.5 s; known answer CVE-2023-23420. Second anchor: afd.sys 22621.1028 -> 1415, CVE-2023-21768, `AfdNotifyRemoveIoCompletion`, a one-line change. Open issue #121 "Small function changes are not captured" (maintainer suggests lowering `min_func_len` because too-short minimums "create too many matches"; no fix merged).
- BinDiff (S1 `differ.cc`, `change_classifier.*`, `bindiff.json`; 02 s7): confidence = sigmoid(10 x (histogram-mean step confidence - 0.5)), an evidence-quality index, not a probability; similarity = (structural fractions + MD-index closeness)/2 x confidence, exactly 1.0 when every block and instruction pairs; flags G I O J E L C with O never set (`TODO: Check for changes in operands`); C only when a paired callee is unmatched or mismatched; the `function` table stores similarity, confidence, flags and algorithm per match.
- Diaphora (S4, AGPL, ideas only): 50 heuristics = 12 Best (5 are `NO_FPS` rules, commented "results without false positives"), 30 Partial, 8 Unreliable; ratio minimums 0.2-0.8; several Partial rules need rarity (hash, MD index or constant seen <= 2 times across both databases) and size gates (nodes > 5, instructions > 5); pseudo-code is cleaned by blanking `vNN`/`aNN`/`sub_` names (cheaper than consistent renaming, hides variable swaps).
- BSim (S2 `FeatureWeight.html`, `BSimOverview.html`, `IngestProcess.html`): features are SSA/p-code graph fragments from the decompiler; names, types, storage locations, instruction order and callee identities are not encoded; weights come from corpus counts; similarity = cosine (default threshold 0.7, false positives on small functions); confidence = log-likelihood ratio, approximate false-positive rate 1 in 4,000 (10), 1e5 (26), 1e6 (43), 1e9 (93), halving per 4-5 points, capped by function size ("self significance"). Old and new should use identical analyzer settings (Call-Fixup, Decompiler Parameter ID, No-Return, Shared Return Calls) or noise appears. Local H2 databases work on all platforms.
- rz-diff (SPEC-27, 03 s4): raw-byte Levenshtein in function mode, no confidence, no masking. [run 03 s4] it flags the constant-only edits Ghidriff misses (0.969, 0.993), but 46 of 50 correct PARTIAL pairs were pure address noise (0.80-1.0, mean 0.979) while real changes scored 0.58-0.87, so no threshold separates them: complementary as a detector, unusable as an L2 verdict without masking.

## 3. Fusion-method recommendation
**L1 pairing (probabilistic; SPEC-28 owns calibration and display levels)**
1. Normalise every engine record to `PairEvidence{engine, step or bucket, native values kept raw, D_* tags, rank, margin}`. Missing or unsupported = unknown, never a negative vote (SPEC-27/28 invariant, kept). Native scores are incommensurable (BinDiff confidence = evidence-quality index, Diaphora ratio = text similarity, BSim confidence = corpus-dependent log-likelihood ratio): never average them.
2. Make the masked-byte comparator (R1) a first-class in-house engine tagged D_bytes. `independence_index` is 0 for G+B with a Ghidra-produced BinExport and 1 for G+R and G+B+R, but rz-diff's raw Levenshtein is dominated by address noise (section 1); a masked variant is the independent corroboration SPEC-28 lacks. Function extents from `.pdata` keep it independent of Ghidra for non-leaf functions; leaf functions have no unwind entry and need Ghidra extents (then add D_ghidra) [inf].
3. Hard accept only unique exact or operand-masked keys (min length 10) or equal non-default symbol names with no engine disagreeing; BinDiff steps with confidence <= 0.75 (02 s14 tier C) are candidates only.
4. Score the rest with pooled components (R4), L2 logistic across components, Platt/isotonic per profile; margin (best minus second best) and function size are features (SPEC-28 M3, lineage-grouped CV). Resolve globally: greedy one-to-one by (p, margin), neighbour re-scoring once anchors exist (R6), abstain below margin or on OOD.
5. Keep SPEC-27: an engine pairing an endpoint differently => `contested`, manual, no number.
```text
comp = union_find(families, joined_if=lambda a, b: deps[a] & deps[b])       # same rule as independence_index
z = bias + sum(w[c] * max(pooled_feature[f] for f in c if f in pair) for c in comp)   # idempotent inside c
p = calibrate(z); decide = abstain if margin < m0 or ood(pair) or contested(pair) else threshold(p)
```
**L2 materiality (rule-based, sound by construction)**
- Channels, each returning equal or a typed delta with provenance: C0 masked bytes; C1 operand-masked instruction stream; C2 operand classes (R1); C3 layout-independent CFG; C4 callee set mapped through L1 pairs with thunks resolved; C5 constants and strings, address-like values masked, rarity-weighted; C6 canonical pseudo-code; C7 BSim/p-code features (medium tier); C8 BinDiff flags G I J E L C.
- Verdicts, first match wins. `unchanged` = C0 equal. `cosmetic` = (C1 equal, C2 all cosmetic, C4 and C5 equal) or (C3, C4, C5 equal) or (C6, C4, C5 equal), recording the normalisation ID.
- `material` = an unexplained semantic-class delta (callee changed to an unmatched or new target; non-address immediate in a compare, size, shift or mask context; condition or call added or removed; struct-offset change; new block holding a store or call) AND a second channel agreeing (C6 differs, C7 residual, or BinDiff G/C). `review` = everything else (single-channel delta, size or refcount only): collapsed, ranked, never auto-hidden.

**Rationale**
- (a) Correlated inputs: Ghidriff, Ghidra-exported BinExport and Ghidra-side features share boundaries, names and decompiler. Two engines at 9:1 odds multiply to 81:1 (98.8 %) under independence, but if their errors coincide the truth stays 9:1 (90 %) [inf, arithmetic]; additive evidence overcounts, idempotent pooling cannot.
- (b) Existing tools never add correlated evidence: Ghidriff/VT eliminate matched functions from later stages; BinDiff takes a histogram-weighted mean; Diaphora routes each pair to one tier and re-scores it with an independent text ratio; VT/BSim weight by corpus counts; QBinDiff optimises one objective [src S1-S5].
- (c) Stacking learns correlation only where labelled data cover it; pooling is a structural guard when data are thin. (d) L2 normalisations are provable, so `cosmetic` is a proof class and its only failure mode is an unsound normaliser, which the leakage test targets (section 7). (e) Ranking orders, it does not accept.
- (f) Abstention thresholds come from a lower confidence bound on dev out-of-fold data, frozen before the locked test [S15, SPEC-28 s9]. Rejected: Dempster's rule, naive-Bayes product, majority vote, mean of native scores.

- Fit: these models solve cross-compiler retrieval among millions. A version-to-version diff needs exact correspondence (99.997 % matched by cascades in the README run) and detection of one-instruction deltas, where whole-function similarity is too coarse (BinXray frames patched and vulnerable functions as highly similar [doc, S13]).

## 7. Evaluation plan
- **Labels.** L1 identity per SPEC-28 s5 (symbols hidden). L2 per matched pair: `unchanged-bytes`, `cosmetic` (semantics preserved), `edited` (function body changed in source), `induced` (changed only through an edit elsewhere: inlining, callee, layout; acceptable only when attributed to its root edit group, F10), `unknown`. Tier R truth comes from a token-level diff of each function body between commits.
- **Metrics.** Changed-set false-positive rate = reported `material` (and separately `material`+`review`) pairs labelled cosmetic or unchanged over reported pairs; noise ratio of each legacy output (Ghidriff `modified`, BinDiff similarity < 1 or flags != 0, rz-diff non-identical) against the unified output; planted-mutation recall per class (constant, comparison operator, bound, callee, struct offset, removed check, added block); cosmetic-bucket leakage (planted or edited pairs landing in `cosmetic`; target 0; each hit is a normaliser bug and becomes a fixture); review rate and false leads per verified finding (SPEC-30); one-to-one match precision/recall/F1 (L1); risk-coverage curves with abstention [S15].
- **Corpus without Microsoft binaries** (publish source pins, recipes and expected SHA-256 only; SPEC-28 Tier R): adjacent tags and CVE-fix commits of zlib, libpng, sqlite, lua and mbedTLS built with clang-cl, mingw-w64 and MSVC on Windows runners. Precedent: QBinDiff built several zlib/libsodium/OpenSSL versions with symbols, stripped them, took truth from source history [S5 doc]. First fixture already exists in 03 s3-s4: zlib 1.3 -> 1.3.1 stripped, 138 functions, 81 byte-identical, 51 address-noise-only, 3 genuine changes plus 1 padding variant [run 03].
- **A/A perturbation classes.** P0 control: same commit, same flags, two builds (toolchain determinism; `/Brepro`). P1 nuisance, no inlining change: timestamp, GUID and path, link order, `/ORDER`, `/OPT:ICF` toggle; expected `cosmetic` only. P2 stress, inlining and scheduling change: `/O1 /O2 /Ox /Ob /GL /Gy /Gw`, clang levels, BinTuner-style searched flag sets [S8 doc]; expected `induced`, reported, not gated to zero [inf].
- **Planted mutations and unit fixtures.** Scripted source edits (flip a comparison, change a constant or bound, remove a check, swap a callee, change a struct field offset). Unit fixtures are hand-assembled x86-64 byte snippets embedded in tests, with cosmetic variants (register renaming, RIP-displacement shift, block reorder, thunk insertion) and material variants (constant, comparison, callee); no Microsoft code.
- **Tier W (local only, labels keyed by relocation-masked body hash, SPEC-28 s3.3).** Winbindex pairs with PDB truth plus the two public anchors from S3's README: ntoskrnl 10.0.22621.1344 -> 1413 (CVE-2023-23420) and afd.sys 10.0.22621.1028 -> 1415 (CVE-2023-21768). Anchor acceptance: the patched function lands in `material`; each of the 5 code-diff functions is adjudicated; the 6 non-code rows are reclassified with a recorded reason or promoted to `review`.
- **Metamorphic checks (no labels).** X vs X yields zero changes; swap symmetry (added <-> removed, same modified set); transitivity of `cosmetic` along an N-way chain (cosmetic(A,B) and cosmetic(B,C) imply cosmetic(A,C)); cross-tier consistency (a cheap-tier `cosmetic` must not be refuted by medium-tier features).
- **Existing benchmarks and limits.** BinKit and TikNib (MIT, ELF; S9), BinaryCorp-3M (ELF; S12), Cisco-Talos dataset (MIT repo, ELF, IDA databases; S10), REFuSe-Bench (Windows PE, retrieval, deduplication protocol, raw-bytes control; S11). All score retrieval or presence; none scores cosmetic-vs-material on Windows patch pairs, so the corpus above is still needed (agrees with SPEC-28 s15).
- **Method and gates.** Lineage-grouped splits, cluster bootstrap, thresholds frozen before the locked test (SPEC-28 s2, s9); ablations leave-one-tier-out and leave-one-engine-out; controls Ghidriff-as-is, BinDiff-flags-as-is, raw rz-diff, raw-bytes M0b. Proposed gates [inf, to preregister]: leakage into `cosmetic` = 0 on dev and locked sets; P0 and P1 pairs produce no `material`; the `material` set has >= 20 % fewer false leads than the best single legacy output at non-decreasing planted recall (SPEC-30 gate); review rate reported, not gated.

## 8. Adopt / avoid
Adopt, in order (each a small slice with red/green tests):
0. Slice 0, no new extraction: typed downgrade from the stored `diff_types`, `m_ratio`, `b_ratio` and `match_types` of the raw Ghidriff JSON (01 s1d: present, unused) plus the F1 symmetry guard; test on the README sample.
1. R1 operand-delta channel and masked hash (needs the extraction layer of 02 s14).
2. R7 canonical pseudo-code with L1 pair-ID substitution, F5 thunk collapse, F6 callee mapping.
3. R4 component pooling with SPEC-28 stacking and abstention; R2 cascade and R6 vote/conflict thresholds for any propagated pair in an in-process L1 matcher.
4. A/A and planted corpus plus metamorphic checks before any model work (they gate 1-3).
5. Medium tier (BSim/p-code export script) once SPEC-12/16 extraction exists; SMT only on evidence of residual noise.
6. R10 review ranking after labels exist.

Avoid: Dempster's rule, naive-Bayes products, majority or mean "consensus" over Ghidra-derived engines; trusting `modified` = empty as "unchanged"; neural embeddings in the core; pyvex/angr in the bundle; Diaphora code (AGPL) and Ghidriff code (GPL-3, keep as subprocess); QBinDiff as a dependency; BinXray reuse (licence [unv]); BinSim and other execution-based equivalence; LLM triage as a filter (it may explain, never suppress); numbers shown to users before SPEC-28 gates pass.

## 9. Open questions [unv]
1. Share of real MSRC fixes that are operand-only (constant, mask, size, callee target) and invisible to Ghidriff and BinDiff: run R1 over the two README anchors plus five further pairs and count masked-equal pairs with non-address operand deltas.
2. Decompile and p-code export cost for all functions of a 10-50 MB driver or DLL on target hardware; decides whether the medium tier is per pair or on demand.
3. Fraction of Ghidriff `modified`, BinDiff-flagged and rz-diff changed rows that the cheap tier proves cosmetic on large pairs (feature updates, not cumulative updates).
4. Soundness of F15 idiom handling (CFG dispatch, `/GS`, `$cold`, ICF folds) across MSVC versions; needs the MSVC documentation (unreachable here) and a clang-cl/MSVC build matrix.
5. Licence and NOTICE review for porting BinDiff steps or BSim ideas (02 s12); data licence of REFuSe-Bench and of any Windows corpus.

# 04 - Structural matching prior art (classical techniques) for the unified diff engine

Scope: function and basic-block (BB) matching for older-vs-newer Windows PE x64 builds; no ML embeddings. Researched 2026-10-14. Siblings: `02-bindiff.md` (BinDiff internals), `../phase3/binexport-bindiff.md`, `../phase-c/matching-calibration-ground-truth.md` (ICF and static-name ground-truth pitfalls).

## 0. Findings that change the design
1. One skeleton everywhere: ordered passes, strongest key first; a pair is accepted only if its key is unique on BOTH sides among unmatched items (D&R: a selector returns nothing on ties [P]); ambiguity is deferred (drill down inside the bucket, or drop a tier); accepted pairs seed call-graph and CFG propagation; loop to a fixpoint. Seen in BinDiff, PatchDiff2, Diaphora, Ghidra AutoVT, binkit [C].
2. The only real accuracy numbers readable here, all 2004-05 x86 Windows [P]:
   - Flake: unique (BB count, edge count, call-tree edge count) tuple plus callee propagation on link-time-fragmented DLLs: wininet.dll XP SP1->SP2 1522 of 2310 functions mapped in 183 s; msgsvc.dll MS03-48 pre/post 100 of 134 in <5 s. No unchanged-but-flagged pair seen across many programs; constant/buffer-size-only patches are the known false negative.
   - Dullien-Rolles: H323ASN1.DLL patch reduced to 8 changed functions of 1655 in <5 min; Bagle.X vs Bagle.W all but 6 functions matched, 1514 of 1524 comments ported, <30 s.
   - Instruction-level diffing (Sabin, quoted by both) flags 3-5% of instructions as changed between builds: the noise floor that structural matching exists to avoid.
3. Noise budget. ghidriff README run, ntoskrnl 10.0.22621.1344->1413 with PDB names: 60,664 functions, 60,662 matched, 11 modified, only 5 with code changes [D]. A 0.1% false-modified rate adds ~60 rows against 5 real ones, so uniqueness gates, size gates and cosmetic-change classification outrank recall from weak matches. Itemized non-name stages there: ExactBytes 100, ExactInstructions 123, StructuralGraphHash 693 (it ran after the exact stages and still found ~3x their sum) [D]: masked-byte keys alone miss most moved or edited functions.
4. Gap in BinDiff over BinExport2: both string-reference steps (function conf 0.7, BB 0.8) cannot fire. The reader sets `string_references_=1` and `string_hash_=0` with TODO "we don't export string references" although BinExport2 carries `string_reference[]`; operand changes are unclassified (TODO in `change_classifier.cc`) [C]. The unified engine must compute string, import and constant features itself.
5. Scale limits seen by authors: Diaphora ships its Unreliable tier OFF (`DIFFING_ENABLE_UNRELIABLE=False`) and by default disables SLOW rules at >=4001 functions; QBinDiff warns against >10k functions unless sparsity is 0.99 [C]. Windows kernel images reach ~60k functions [D]: use blocked candidate generation, never all-pairs matrices.
6. Windows-only structure that none of the differ sources read here mentions: the dynamic value relocation table lists load-time-patched sites and function-override variants selected by CPU/OS capability conditions [C System Informer]; variants have no static callers and would read as orphan added/removed functions (section 6).

## 3. Anchor ranking [I ordering, evidence as tagged]
1. Export name or ordinal, import (dll, name), PDB public name: BinDiff name hash conf 1.0, "false matches highly unlikely" [D]; QBinDiff pins same-name imports at similarity 1 [C]; Ghidra Exact Symbol, unique both sides, min length 3 [D][C]. PDB-less images offer exports and imports only.
2. Unique strings (decoded content, hashed as a set): Ghidra Exact Data conf 1.0 when unique, min length 5 [D][C]; BinDiff: good for error-handling code with little structure [D]. Weak when sibling paths share messages.
3. Class anchors (MSVC RTTI TypeDescriptor names, vtable slot index): layout verified in LLVM's MS C++ ABI code (section 6) [C]; PatchDiff2 class nodes [C]; Ghidra Data Reference Correlator [D]. Only for images built with RTTI [I].
4. Unique callee or import sets, and (caller, callee) edges, once any neighbour is matched [C].
5. Rare constants: Diaphora filter plus rarity gate; weak alone [C].
6. Section-relative offsets and RVAs: Diaphora's "Same RVA" is a Best-category rule only with compatible names and min ratio 0.7; its "same address" fast path needs >=99% identical addresses [C], which servicing builds never meet [I]. Use the piecewise-constant RVA delta between anchors as a soft ranking prior [I].
7. Never anchor on: trivial thunks, CRT/CFG/GS stubs, N:M duplicates, tiny functions (<=5 instructions). BinDiff: trivial library functions match by name only; Ghidra: min lengths; Diaphora: `nullsub` exclusions [C].

## 4. Pipeline-ordering insights
1. Order by key reliability, strict to loose; remove matched items from both pools after every tier; accept only keys unique on both sides [C][P].
2. Propagate after every tier, not once at the end. BinDiff restarts the attribute list at the next level only after drilling into callers/callees of all fixed points until nothing new appears [C]; PatchDiff2 recurses into preds/succs at the same strictness [C]; Diaphora loops best/partial rescoring, related-match and local-affinity passes until the total stops growing [C].
3. Prefer edge keys (caller signature, callee signature) over node keys when both ends have signatures: BinDiff calls edge matching the stronger criterion but slow (call edges grow super-linearly); its proximity variant ships disabled [D][C].
4. Weak keys run only inside structurally pre-constrained sets: instruction count 0.4, address sequence 0.4, loop count 0.6, call sequence 0.1/0, BB entry/exit 0.2/0.1, single-neighbour propagation 0 [C]. Address sequence needs equal-size classes already equal in MD index; call sequence needs matched parents [D].
5. Size gates are the false-positive governor: Diaphora skips <=5 instructions and most rules need 3-5 nodes; BinDiff BB hash/prime need >=4 instructions and trivial library functions match by name only; Ghidra exact functions >=10, duplicates >=25 [C]. Small functions are least matchable because tuples collide [P].
6. Isomorphism pruning in practice = cheap necessary conditions, never exact isomorphism: equal node and edge counts ("if they do not match, no isomorphism exists", Flake 4.1 [P]), MD index, KOKA/SPP [C]. QBinDiff ships a Weisfeiler-Lehman feature but leaves it out of its default set [C].
7. Second opinion before accepting a key hit (Diaphora): every SQL hit is rescored (pseudo-code, assembly, AST-prime, MD, microcode similarities; max, plus a deep ratio); 1.0 is refused when MD indices differ; non-exact is capped at 0.99; a same non-auto name forces 1.0; +0.01 when derived from known-good neighbours [C].
8. Tier ceiling by rule reliability (Diaphora): Best- and Partial-category rules emit Best only at ratio 1.0 and Partial at ratio >= rule minimum (default 0.5); Unreliable-category rules emit at most Partial (at 1.0) and otherwise Unreliable. Context discount: candidates derived from known-good pairs need only ratio > 0.3 [C].
9. Confidence is per step and aggregated: BinDiff = mean step confidence through sigmoid(10*(c-0.5)), multiplied by similarity (0.55 edges + 0.30 BBs + 0.15 instructions, averaged with MD closeness) [C]. Ghidra: scores are not comparable across correlators; Duplicate matches get log10(10/N) < 0.7 [D]. Treat all as priors and recalibrate on the SPEC-28 corpus [I].
10. N:M is a result, not an error: Ghidra Duplicate correlators and Diaphora's multimatch list return groups instead of picking [D][C].
11. Two matching modes (Flake section 8 [P]): relaxed matching for name/comment porting vs strict matching that feeds "modified" verdicts. Auto-accept only exact tiers; show the rest as probable (Ghidra auto-applies exact matches only [D]; Diaphora Best/Partial/Unreliable [C]).
12. Fast path for patch pairs: Diaphora accepts exact-name matches when >=90% of functions share names and brute-forces only the leftovers at ratio >=0.6; >=99% same address means "same binary, stripped" [C]. PDB-less analogue: tier-1 hashes should absorb unchanged functions before anything expensive runs [I].
13. Aligned-operand implied matches: once a pair is matched, align its two instruction streams and pair the call/data targets sitting at aligned positions. Ghidra implied matches (apply at >=2 votes, 0 conflicts) [D][C]; BinDiff call-reference matching per matched BB [C]; Diaphora diffs the cleaned text of matched pairs and pairs callee names found in aligned changed hunks, then requires BB counts within 4x, >=3 BBs, ratio > 0.3 and adds +0.01 [C].
14. Re-hash after anchors [I]: replace call/xref targets by matched-pair ids and rerun the masked hashes, so a function whose only change is a moved or renamed callee becomes an exact hit (the mechanisms in item 13 get there indirectly).
15. BB-level signature inside a matched pair (D&R 4.5.6 [P]): (blocks on shortest path from entry, to exit, calls) with an offset delta recomputed from existing fixed points, so one inserted block does not skew every dominated block; BinDiff approximates this with top-down/bottom-up MD levels [C].
16. Proposed order [I]: T0 identity anchors (user-confirmed matches as in Ghidra's manual correlator and QBinDiff's user pass [D][C]; export name/ordinal, import thunks, PDB names, RTTI vtable slots; unique only) > T1 masked-byte and operand-masked hashes > propagate > T2 multiset + topology (rare, size-gated) > propagate > T3 string/import/constant sets > T4 reference vectors + implied-match voting (>=2 votes, 0 conflicts) > T5 BB-first voting for leftovers + guarded layout gaps > T6 assignment with rejection per blocking bucket (<=300) > T7 classify: exact, changed(kind), ambiguous group, probable inline/outline, added, removed.

## 5. Normalization checklist
Ladder, computed in one streaming pass into one compact record per function: L0 raw bytes; L1 bytes with address-bearing fields masked; L2 opcode + operand classes, registers kept; L3 register-agnostic (opcode + operand kinds); L4 mnemonic multiset; L5 topology (MD index, KOKA, shape tuple). Prior art: BinDiff hash = L0 and breaks on any shift [C]; Ghidra FID full hash = L2, VT Exact Instructions = L3, Exact Mnemonics = ordered L4 [C][D]; binkit BB hash = (itype, operand type, dtype) per instruction, conditional jumps dropped, entry hot-patch `mov r,r` skipped = L3 [C].
- Address-bearing fields -> typed placeholders (code, data, import, string, jump table): rel32 call/jmp/jcc, RIP-relative disp32, imm64 with a base-reloc entry, table entries. FID masks relocated scalars and address operands (0xfeeddead) [C]; PatchDiff2 drops bytes of instructions with data refs and calls [C]; binkit ignores near/mem values [C]. Most x64 references are RIP-relative and carry no base relocation, so decode instructions instead of trusting the reloc table [I].
- Immediates: ignore large scalars; keep small ones (|v|<256 inside larger operands, or whole non-address scalars) only in a "specific" tier [FID C]. Constant FEATURES use Diaphora's filter (>=0x1000, no FF..00 masks, no single bits) [C]. Mask frame sizes and local offsets (`sub rsp,N`, `[rsp+X]`); they shift with any new local [I].
- Registers: keep (FID), drop (VT Exact Instructions, binkit) or alpha-rename per function [I]. Register allocation, instruction reordering and branch inversion are the three standard compile-to-compile changes [P].
- NOP/padding: 90, 66 90, 0F 1F /0 forms, self-moves `mov r,r` (incl. `mov edi,edi`), `lea r,[r+0]`, `xchg r,r`; skip in hashes and counts (Ghidra X86InstructionSkipper [C], PatchDiff2 `x86_is_nop` [C]); drop int3 fill between functions.
- Branches: collapse jcc rel8/rel32 (PatchDiff2 keeps only the first byte [C]); drop conditional jumps from the block hash (binkit [C]); inverted condition with swapped successors is cosmetic (BinDiff branch-inversion flag [C]); collapse jmp-to-jmp chains and fake jumps (PatchDiff2 [C]).
- Block restructuring: merge a block with a single predecessor into it, undoing splits by unconditional jumps ("a specialty of Microsoft's optimizing linker", Flake 4.3 and footnote [P]); the BinDiff differ does not do this (see 02-bindiff.md).
- Instruction order: multiset key (BinDiff, Diaphora SPP) [C]; binkit has a def-use canonical reorder but ships it disabled (`if (0)`) [C]; prefer the multiset.
- Thunks and wrappers: collapse caller->thunk->target (QBinDiff `normalize`/`follow_through`, optional because it can cause partial matching [C]); BinDiff matches trivial library functions by name only [C]; Diaphora export excludes library thunks [C].
- Names: demangled names (BinDiff: stable across compilers [C]); drop auto-names (`sub_`, `FUN_`, `nullsub_`) and `_address` suffixes (Ghidra [D]); compiler-generated names are classes, not identities [I].
- Strings: compare decoded content, hash the SET, ignore very short strings (Ghidra data min 5, symbol min 3 [C]).
- Jump tables: compare as (case count, per-case target BB matches), never table bytes (Diaphora "Switch structures" [C]; Ghidra Duplicate Data finds switch tables [D]).
- Function extent from `.pdata`; merge chained chunks; exclude padding [I]. Idioms (`xor r,r` vs `mov r,0`, `test r,r` vs `cmp r,0`, `lea` as add): no studied tool canonicalizes them beyond mnemonic multisets [I]; measure before adding. Compiler stubs (CFG dispatch call, GS cookie pattern, `__chkstk`) become tokens [I].

## 6. Windows pitfalls
- **ICF (COMDAT folding).** `/OPT:ICF` is on by default with `/OPT:REF` in release links and "can cause the same address to be assigned to different functions" [S Learn]. Node = distinct RVA with an alias list; a changed fold set is "changed", never "added/deleted" [I].
- **Thunks, delay-load stubs, forwarders.** Trivial high-fan-in nodes: name-only matching (BinDiff), thunk collapsing (QBinDiff), exclusion (Diaphora) [C]. Key imports as (dll, name or ordinal).
- **CFG and XFG.** x64 indirect calls go through the loader-filled `__guard_dispatch_icall_fptr` (target in RAX); other architectures use `__guard_check_icall_fptr` [C LLVM CFGuard.cpp]. XFG images carry an 8-byte prototype hash immediately before each protected function and use `_guard_xfg_dispatch_icall_*` thunks [C angr `cfg_fast.py`, which cites a Quarkslab article, unread]: keep the hash out of byte keys, but use it as a free prototype-class filter between candidate pairs [I]. The load config's GuardCF table lists address-taken functions [U, PE docs unread].
- **/GS.** Prologue loads `__security_cookie` and XORs it with the frame; epilogue calls `__security_check_cookie` [S MSDN Magazine]. It adds a hub callee and shifts frame offsets: cap fan-in (e.g. >64 callers [I]) in call-graph features and tokenize the pattern.
- **Hot-patch padding.** x64 compiles as if `/hotpatch` (first instruction >=2 bytes) and `/FUNCTIONPADMIN` pads before functions [S Learn]; Ghidra FID's skipper drops VS-emitted NOP forms [C]. Take extents from `.pdata`; padding length is not a feature.
- **PGO and LTCG.** PGO groups co-used functions, splits hot/cold code into different sections and inlines hot call sites [S MS devblog]; `/GL` + `/LTCG` enable cross-module inlining [S Learn]. So address-order priors fail; one logical function can be several chunks (x64 unwind data can be split into chained regions, which LLVM emits via `.seh_splitchained` [C]; whether MSVC PGO uses the same for cold parts [U]); callees vanish into callers (N:1). Detect inlining by BB containment: all old BBs found inside one new function, not at its entry => "inlined into", not "removed" [I]. Flake already worked on heavily fragmented link-time-optimized Windows DLLs [P].
- **Dynamic value relocation table (DVRT).** Recent Windows images list load-time-patched sites by type: return-flow prologue/epilogue, import control transfer (IAT index, call or branch), indirect control transfer (call, REX.W, CFG flags), switch-table branch (register), and **function overrides** (type 7: OriginalRva, overriding RVAs, a BDD over capability numbers such as CPU vendor/family/model, AVX2, ERMSB, kernel/user mode, CFG optimization; 4-byte rel32 patch sites; "OS special function" when ntdll supplies the body) [C System Informer `phnt/include/ntimage.h`, `tools/peview/pedynrelocprp.c`, MIT]. Implications [I]: override variants have no static callers, so they surface as orphan added/removed functions: add synthetic edges OriginalRva -> variant and match variants by capability condition; mask listed patch sites in byte keys and read the IAT index as import identity; the table itself changes between builds and is diff-worthy.
- **PDB-less or partial names.** Diaphora's fast path assumes >=90% shared names [C]; stripped Windows images give exports and imports only; coverage of Microsoft public PDBs is unknown [U]. Every tier must work without names; names are tier-0 anchors and tie-breaks.
- **RTTI/vtables.** MSVC x64 RTTI: a CompleteObjectLocator (image-relative pointers to a TypeDescriptor and a ClassHierarchyDescriptor) occupies the vtable slot just before the first virtual-function pointer when RTTI data is on; the TypeDescriptor name is '.' + the decorated type name (`.?AVFoo@@`), replaced by an MD5 form beyond 4095 characters [C LLVM `MicrosoftCXXABI.cpp`, `MicrosoftMangle.cpp`]. That yields class-qualified, build-stable anchors for virtual functions in stripped images; RTTI is absent in `/GR-` code [I]. Model vtable-like data objects as graph nodes: PatchDiff2 does [C], Ghidra's Data Reference Correlator does via matched data [D].
- **Jump tables.** x64 MSVC tables hold 32-bit image-relative entries in `.rdata` [I]; contents shift with layout: structural compare only (section 5).
- **Toolset drift.** A compiler bump changes instruction selection wholesale; exact-hit rates drop and the register-agnostic, multiset and topology tiers carry more [I].

## 7. Python cost model [I unless tagged]
- Tiers 0-3 are dictionary joins over per-function keys: O(n) time, ~0.5-1 KB per function record, ~30-60 MB for the 60k-function ntoskrnl [D for the count]. Extract in one streaming pass; never hold per-instruction objects for a whole image.
- Propagation touches each call edge a few times per round; edge keys (BinDiff) sort E keys per step, so restrict them to neighbour sets. BB-first voting indexes every BB hash once.
- Assignment and network alignment only on residue after blocking (size bucket, shared callee/string/import tokens, MinHash bands) with k<=300: LAP is ~k^3 = 2.7e7 inner steps worst case, seconds to tens of seconds in CPython. QBinDiff's dense NxM float32 plus squares matrices are out of reach at 60k [C]. Optional numpy/scipy would lift limits but is not a PatchTrace dependency today.
- MD index needs deterministic float summation (BinDiff sorts terms first, "summation is not commutative for doubles" [C]): quantize or use `math.fsum` so the key is stable across platforms.

## 8. Adopt / avoid
Adopt:
- Data-driven ordered step list with a confidence per step (BinDiff `bindiff.json` style); every pair carries step name and confidence.
- Unique-in-both plus size and rarity gates everywhere; N:M reported as groups.
- BinDiff cascade, propagation to fixpoint and call-reference matching; D&R up/down alternation and unique-nearest selector over (#BB, #edges, #calls) inside neighbour sets (4.5.5 [P]).
- Ghidra reference vectors with IDF weights, margin test, implied-match voting (>=2 votes, 0 conflicts).
- Diaphora best/partial/unreliable groups with per-rule minimum ratio, second-opinion rescoring, fixpoint cleanup, patch-diff fast path.
- DarunGrim-style BB-first voting for leftovers and ICF/inline-aware 1:N and N:1 function mapping.
- Assignment with rejection on small residual blocks; layout and RVA-drift priors only as guarded tie-breakers [I].
- Native string, import, constant and RTTI anchors; post-match change classification to demote cosmetic changes.
- Library recognition by masked-operand hashes (Ghidra FID, built from Visual Studio libraries [C]) to tag CRT/STL code and keep it out of change lists [I].

Avoid:
- Whole-binary QAP/belief propagation or dense similarity matrices in stdlib Python (QBinDiff's own memory warning [C]).
- Exact semantic equivalence (symbolic execution + theorem proving, BinHunt; IR lifting + I/O sampling, Pewny et al.) and cross-architecture feature work (discovRE) on the default path: cost and motivation do not fit same-ISA x64 pairs [S, not among the 15 sources].
- Address order, call sequence, instruction count or loop count as primary evidence (BinDiff confidences 0-0.6) [C].
- Forced 1:1 pairing of leftovers; hub callees (CRT, cookie check, CFG stubs) driving propagation [I].
- Treating step confidences as probabilities (Ghidra: incomparable across correlators [D]); copying Diaphora's SQL or threshold table (tuned for IDA exports).
- Copying GPL/AGPL code (Diaphora AGPL-3.0, PatchDiff2 GPL-2.0, Turbodiff GPL-3.0, ghidriff GPL-3.0). PatchTrace is MIT: port from Apache-2.0 sources (BinDiff, Ghidra, QBinDiff, LLVM) with notices; reimplement the rest from ideas.
- Trusting names alone on PDB-less or ICF-folded images.

## 10. Gaps
- No paper-level accuracy tables beyond Flake and D&R were readable. A human with access should read the evaluation tables of Karamitas SANER 2018 (xul.dll vs Diaphora), BinSlayer, the QBinDiff ASE 2021 and CAID 2024 papers before fixing any target recall or precision.
- BinDiff step confidences and Diaphora thresholds are authors' design priors, not calibrated probabilities; calibrate on the SPEC-28 corpus.
- Windows ABI facts (DVRT, RTTI, XFG, CFG symbols, chained unwind) come from open-source readers (LLVM, System Informer, angr), not Microsoft documents; the GuardCF table and MSVC PGO function chunking remain unverified.
- QBinDiff, PatchDiff2, Turbodiff and binkit were read from default branches without SHAs; SHAs for Diaphora and BinDiff came from a read-only remote ref listing.

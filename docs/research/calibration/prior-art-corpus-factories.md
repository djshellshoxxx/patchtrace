# Prior art for the known-answer corpus factory (R2): what to reuse instead of rebuilding

Status: research note, 2026-10-14, docs only. Audience: builder D (`tools/calibration/tier_r/`, SPEC-32 draft), SPEC-28 sections 3-5, SPEC-31 `unified-engine/08-evaluation.md` section 2. PatchTrace is MIT ([LICENSE](../../../LICENSE)), so vendored code must be permissive and carry a NOTICE.

**Answer.** No public resource offers redistributable Windows x64 PE old/new pairs with exact per-function answer keys. Closest: Assemblage/DeepHistory (Windows builds, but no LICENSE file), BinPool and ARVO (vulnerable+fixed pairs, Linux ELF), cb-multios (`_patched` Windows builds, 32-bit). What is reusable is the plumbing: pins and patch series (Ubuntu source archive, ARVO-Meta, DeepHistory), toolchains (LLVM 18 already here, zig via pip), mutation and transform engines (universalmutator, stock `opt`), extractors (llvm-pdbutil, lizard). The factory should orchestrate these, not become a build farm.

Verdicts: **EXT** run as a separate dev-only process or pip package, never vendored; **VEND** copy with NOTICE (permissive only); **DATA** take pins, metadata or expected numbers only; **REF** read for design, never copy code (copyleft, unclear or no licence). Effort: S < 0.5 day, M 1-2 days, L > 3 days.

Sourcing: each row cites its repo URL; licence cells quote the licence text and link the raw file; "last commit" is the first entry of `<repo>/commits/HEAD.atom` and stars come from the repo page, both read 2026-10-14 (stars are a signal only). Access was read-only to public pages (nothing pushed, no API writes, no repo attached). Reachable: raw.githubusercontent.com, github.com pages, PyPI, archive.ubuntu.com, local LLVM 18.1.3. Blocked **[unv]**: arxiv.org, usenix.org, dl.acm.org, ieee.org, samate.nist.gov (SARD), zenodo.org, huggingface.co, readthedocs, hexhive.epfl.ch, llvm.org, learn.microsoft.com, ziglang.org, codeberg.org, snapshot and security-tracker.debian.org, repairbenchmarks.cs.umass.edu, panda.moyix.net, assemblage-dataset.net. Numbers known only from search-result summaries of papers are marked [unv].

## 1. ADOPT NOW (ranked; V1-V8 are sandbox checks in section 3)
1. **LLVM tools as the ground-truth extractor plus a directory-independent flag set** - EXT, S. Steps: in the `msvc-free` profile add `-gno-codeview-command-line -fdebug-prefix-map=$B=/src -Xclang -object-file-name=x.obj` to the clang argv and `/pdbaltpath:x.pdb /map:x.map` to the `lld-link` argv (keep `/Brepro /OPT:NOREF /OPT:NOICF`). Truth = parse `llvm-pdbutil dump -symbols x.pdb` (`S_GPROC32|S_LPROC32 `name`` then `addr = SSSS:OOOO, code size = N`), `dump -section-headers` (RVA to file offset), `dump -l` (source file MD5, line ranges); cross-check names and RVAs against the `/map` "Publics by Value" list; `/usr/lib/llvm-18/bin/llvm-debuginfo-analyzer --compare=scopes a.obj b.obj` is a free second opinion on added/removed. Evidence V1-V3. Check on the Windows runner: `where llvm-pdbutil` [unv].
2. **Source hunk to function mapping with `lizard` (MIT) or clang JSON AST, with masked body equality as the arbiter** - EXT/pip dev dependency, S. Steps: `git diff -U0` hunks to functions via `lizard.analyze_file(path).function_list` (start_line/end_line) or `clang -fsyntax-only -Xclang -ast-dump=json` (walk statefully: the dumper elides repeated `line`/`file`). Label `changed(kind)` only when the masked body also differs; text changed but masked bytes equal = `cosmetic`; masked bytes differ with no hunk in that function (`__LINE__` immediates, inlined callee) = `induced`. Never use raw byte equality as the key (V6: one CVE patch, 151 of 339 functions differ raw, 2 masked).
3. **universalmutator as the planted-mutation engine** - EXT, S-M. Steps: `pip install universalmutator==1.14.1` in a throw-away venv (it pulls `python-Levenshtein`, GPL-2.0-or-later: keep it out of repo requirements and out of any package); put our own `.rules` files under `tools/calibration/mutations/rules/` covering the G-U2 classes (comparison `<`->`<=` and `==`->`!=`, constants, removed check `if(c)`->`if(0==1)`, deleted statement, custom regex for swapped callee); always run with `--cmd "<clang -fsyntax-only ...>"`; per surviving mutant build the profile, map the mutated line to its function (step 2) and keep it only if exactly that function's masked body changed. V4: 155 raw mutants on a 21-line file, 103 invalid (`int32_t` became `int0_t`), 3 equivalent, 49 valid, 49/49 changed the function that contains the mutated line.
4. **Stock LLVM `opt` passes for N1/N2/N4/N10 transforms** - EXT, S. Steps: `clang -Xclang -disable-llvm-passes -emit-llvm -S`, then `opt -passes='function(mem2reg,loop-simplify),loop-extract'`, `'function(mem2reg),hotcoldsplit'` or `'function(mem2reg),mergefunc'`, then compile the IR with the profile; the new symbols are the key (`looped.extracted`, `checked.cold.1`, merged twin). Record transform and expected extra symbols in `mutation-case/1`. V5. Replaces every obfuscator fork (section 2).
5. **zig cc from the PyPI `ziglang` wheel as a hermetic mingw cross compiler that emits PDBs** - EXT, S-M. Steps: add profile `zig-mingw`: `pip install --require-hashes ziglang==<pin>` (MIT, 96 MiB wheel), `python -m ziglang cc -target x86_64-windows-gnu -O2 -g -shared ...` with `ZIG_GLOBAL_CACHE_DIR`/`ZIG_LOCAL_CACHE_DIR` in scratch; truth with the same `llvm-pdbutil` code as step 1. Gives libc-dependent real projects (zlib, expat, lua) PE+PDB without apt mingw or MSVC. V7: expat lib gives 839 function records including `static storeAtts`; same-dir rebuild bit-identical. `-target x86_64-windows-msvc` fails ("unable to provide libc"), so it is not an MSVC substitute.
6. **Ubuntu source-package CVE series as hash-pinned fix pairs (BinPool method)** - DATA + `patch`, M. Steps: pin = `.dsc` `Checksums-Sha256` for `*.orig.tar.gz` and `*.debian.tar.xz` from `http://archive.ubuntu.com/ubuntu/pool/main/<x>/<pkg>/` (old versions stay, `old-releases.ubuntu.com` too); each prefix of `debian/patches/series` is one state; one patch = one `cve-fix` case whose hunk context names the function; build states k and k+1 with explicit argv. Needs a SPEC-32 pin type `tarball+patch` (sha256s) next to 40-hex commits, a licence read of each project, and no vendored `debian/` files. V8: expat_2.2.9-1ubuntu0.8 carries a 30-entry series (27 CVE) on `expat_2.2.9.orig.tar.gz` sha256 c341ac8c...; CVE-2021-45960 applied cleanly and both hunks fall in `storeAtts`.
7. **DeepHistory `packages.json` as a pin shortlist** - DATA hint, S. Steps: filter to permissive C packages with >= 3 versions (132 permissive packages have >= 3 versions; zlib 5, expat 10, lua 7, libpng 11, sqlite3 28, cJSON 7, libdeflate 11, pcre2 9), then re-derive every pin with `git ls-remote` plus a licence read as `corpus/README.md` requires; the file has no LICENSE, so ask the maintainers and treat it as a hint list, not a dependency.
8. **ARVO-Meta v3.0.0 (BSD-2-Clause) for CVE-fix stubs** - DATA, M. Steps: a person downloads the release asset (name not visible: asset list failed to load [unv]) into `PATCHTRACE_CALIB_ROOT`; a script filters `project` to recipe projects with permissive C licences and emits `case-card/1` stubs into `corpus/catalog/`; the old-schema sample record has `repo_addr`, `fix_commit`, `project`, `crash_type`, `sanitizer`, `severity`; parent commit, diff and function list are then verified with git like every card.
9. **BinDiff `fixtures/libssl` truth file as an oracle fixture** - DATA/VEND (Apache-2.0, NOTICE), S. Steps: take only `libssl.0.9.8g.x86.gcc.4.3.3.a_vs_libssl.0.9g.x86.gcc.3.4.6.a.truth` (737 lines `addrA addrB nameA nameB`, 40 KB) as a format example and a unit-test oracle for the BinDiff adapter; the BinExport inputs stay in the live job via the pinned BinDiff checkout; x86 ELF, so not Windows evidence.
10. **Juliet C/C++ 1.3 (CC0) through arichardson's CMake** - DATA/EXT, M. Steps: fetch at a pinned commit into `PATCHTRACE_CALIB_ROOT`; the CMake builds one `-good` (`OMITBAD`) and one `-bad` (`OMITGOOD`) executable per test case; use bad/good flow variants (`*_bad` vs `*_goodB2G`) as `changed(bounds-check-added | null-check-added ...)` sources compiled with explicit argv (no CMake run). Public domain: no NOTICE needed, still cite NIST. Unix-only build per README.
11. **Tier W regression sentinels from ghidriff tests** - DATA, S. Steps: for afd.sys 10.0.22621.1028 to .1415 (CVE-2023-21768, already an anchor in `08-evaluation.md`) record ghidriff's published expectations as sentinels, not truth: modified 12 (full diff) or 14-15 (simple diff), added 28, deleted 0, `AfdNotifyRemoveIoCompletion` among modified. Binaries come from Winbindex identity only; never copy `ghidriff-test-data` (Microsoft binaries, no licence file).
12. **cb-multios `-DPATCHED` pairs** - EXT/DATA, L, defer. Steps after 1-10: compile challenge sources twice (with and without `-DPATCHED`, `-DPATCHED_n`) via explicit argv; blockers: `libcgc` shims, upstream Windows build is `cmake -A Win32` (32-bit), excludes `win_msvc.txt` (50 lines) and `win_clangcl.txt` (8 lines).

## 2. DO NOT USE
- **Diaphora** (AGPL-3.0), **ghidriff code** (GPL-3.0; already an external tool only), **LAVA** (GPL-2.0), **srcML** (GPL-3.0), **rebuilderd / reprotest / diffoscope** (GPL), **Winbindex repo** (GPL-3.0, confirmed), **universal-ctags** (GPL-2.0): copyleft, REF only.
- **dwarf2json**: Volatility Software License 1.0 extends copyleft to "any software designed to execute the software and parse its results, such as a wrapper".
- **No LICENSE file / unclear (REF, never copy)**: Magma, Assemblage code and DeepHistory builder, Quarkslab obfuscation datasets, BinPool repo, Vul4C, rizin-testbins (the `.reuse/dep5` covers only hexagon paths), angr/binaries ("different licenses").
- **Obfuscator forks** (O-LLVM on LLVM 4.0, Hikari deprecated with a wiki-only licence, Pluto on 14.0.6, Polaris on 16.0.6, Arkari on 23.x): each needs a full LLVM fork build and cannot load into the installed clang 18; use stock `opt` (ADOPT 4).
- **DiffRays**: an IDA Pro diff engine (PyPI 2.0, MIT), not a corpus. **LIEF** for PDB: DWARF/PDB sits under "Extended features" (`extended.lief.re`, GitHub OAuth).
- **Drift Corpus labels**: `security_relevant`/`cosmetic` flags are produced by an automated agent, which SPEC-28 section 2.6 forbids as label input; it holds Microsoft assembly diffs. At most take KB and binary identifiers for pair choice [unv: schema not inspected].
- **AIxCC**: public material is an OSS-Fuzz fork and a Linux kernel exemplar. **OSS-Fuzz / ARVO images**: Docker and ELF, Dockerfiles clone HEAD (unpinned). **CVEfixes / CyberGym / SEC-bench**: NVD, Zenodo or Docker dependencies, no PE.
- **Hosts unreachable here** (BinaryCorp cloud, LAVA-M, ManyBugs/IntroClass, SARD): treat as unavailable until a human fetches them and reads the licence.

## 3. Verified in this sandbox (Ubuntu 24.04, clang 18.1.3, lld-link 18, llvm-pdbutil 18, mingw-w64 11, ziglang 0.17.0; scratch scripts not committed)
```
clang --target=x86_64-pc-windows-msvc -std=c11 -ffreestanding -fno-stack-protector -fno-ident -O2 -g -gcodeview -ffunction-sections \
  -gno-codeview-command-line -fdebug-prefix-map=$B=/src -Xclang -object-file-name=x.obj -c x.c -o x.obj
lld-link /dll /noentry /nodefaultlib /debug /pdb:x.pdb /pdbaltpath:x.pdb /Brepro /OPT:NOREF /OPT:NOICF /map:x.map /out:x.dll x.obj
```

|---|---|---|
| V1 | Same source built in two directories | `x.obj` bit-identical only with the three flags above (without `-gno-codeview-command-line` the cc1 line with the directory is stored in `.debug$S`; without `-object-file-name` S_OBJNAME is absolute). DLL still differs in 20 bytes (PE timestamp, debug-directory timestamp, PDB GUID, derived from a PDB that embeds paths): hash function bytes or use one canonical work directory. Same-directory rebuild: DLL and PDB identical. |

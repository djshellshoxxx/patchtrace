## P00-P19: actual executable table

Table order is execution order. Stage numbers are executable `PassSpec.stage`, not tier rankings. After each stage the engine propagates to a fixpoint. Ambiguous global buckets drill into later same-stage keys. A/B accepts consume endpoints; C proposals wait until final conflict resolution. Content gates mean normal, not oversize, ≥10 body bytes and >5 instructions; P06-P09 additionally require ≥10 instructions. Hub access is limited to P01-P05; propagation excludes hubs and trims neighborhoods to 64.

Correlation shorthand: **K0** analyst; **K1** names/PE/structure/Ghidra/callgraph joined component; **K2*** byte family only when every key in the drill-down chain is byte-derived and both extents are `.pdata` confirmed, otherwise K1. Propagated pairs are structural K1/E-CALL even when a local body key helped.

## Extraction, facts, persistence and calibration seams

`extract/runner.py` supervises external Python/JVM work with private absolute inputs, artifact/program hash checks, a verified script and producer metadata. GZF reuse and fresh analysis are distinct modes; retained decompilation is on demand, not assumed present. `ir/records.py` validates strict rows before `ingest.py` constructs SQLite sidecars; `reader.py` verifies and exposes compact function columns plus bounded instruction blobs. Unsupported/missing masks become unavailable fields/flags rather than invented confidence.

Hash implementation details matter: h0 hashes raw function bytes; h1/h2 mask progressively broader operand fields while skipping recognized NOP/trailing padding; h3 uses instruction masks and is unavailable when masks are incomplete; hm/hms hash mnemonic sequence/multiset. These are signed BLAKE2b-64 fingerprints, not collision-free semantic identities. CFG MD sorts summands and preserves documented BinDiff quirks; dominators supply loop counts, not a separate matching pass. No active WL/KOKA/global QAP implementation is hidden behind these fields. [Source: `ir/{features,operands,mdindex,cfg,ingest}.py`; 02/03.]

Fusion consumes immutable source observations, checks ordered artifact identity, normalizes VA/RVA basis from each PE layout, and creates rows with indexed support/contest and per-atom source/step/class/tier/native/ref. Component union-find joins Ghidriff/BinDiff/structural/symbol evidence into K1 and byte/Rizin evidence into K2. A single A or analyst M can establish a pairing; B acceptance needs different components **and** classes, excluding unknown evidence. Any differing endpoint proposal contests an automatic pair; missing/one-sided observations do not. R2 preserves a complete B witness under the cap, canonicalizes native ties, and fails insufficient caps explicitly. These are evidence/accounting fixes, not new precision claims. [Source: `registry.py`, `fusion/*`, `contracts.py`; 04.]

`facts/` judges materiality after correspondence. Raw/masked bodies, operand/CFG/call/reference/EH/decompiler/secondary channels can provide bounded deltas and structural proofs; unavailable channels remain unknown. Change classification does not feed back into L1 to manufacture a pair. The read model preserves contested rows, keeps native score units in source cells, displays ordinal confidence and reads verbose details lazily. Claims that every inline group is shown, every unknown is eliminated or every matched pair is unchanged contradict this layering. [Source: `facts/{channels,irchannels,verdict,refacts}.py`, `read_model.py`, `read_text.py`.]

`keys.py`/`compute.plan_identity` bind artifacts, ProgramIR digests, source refs, manual/config/limit/policy identities. `store.py` stages and deeply verifies manifest/row/fact parts before pointer publication; decompressed content hashes avoid gzip-build differences. `pipeline.py` owns project-thread prepare/publish and worker orchestration; damaged/stale data is not silently reused. Secondary caches additionally bind engine version/argv and artifact pair. Correct cache identity cannot certify producer semantics: Rizin's wrong side labels can still arrive under correctly ordered caller hashes. [Source: `store.py`, `exchange.py`, `pipeline.py`, `worker.py`, `secondary/runs.py`; 07.]

Calibration is an existing subsystem, not a missing R2 rewrite. Runtime loads strict JSON rather than executable models; policy cannot override contested status and remains ordinal without passing domain/gates. Development tools implement lineage grouping, feature missingness, CV, calibration, intervals, thresholds, leakage audits and one-use locked-test control. Tier R fetch/build/label/engine/evaluation tooling already exists, with real/natural/adversarial/indeterminate distinctions and scope restrictions. R2 did not train a model, spend a locked test, or duplicate R1's corpus framework. Open persistence/A/A/preregistration reconciliation is recorded in 00; implementation completeness and adequate training evidence must be assessed separately. [Source: `calibration/*`, `tools/calibration/{train,gates,guards,lineage,run_locked_test}.py`, `tier_r/`, `evalcore/`.]

## Current native and acceptance boundary

[native-ghidra.json](results/native-ghidra.json) records Ghidra 12.0.4, pyghidra 3.0.2, Java 21.0.12, ghidriff 1.0.0 and twelve native extraction sides for six seed-zero cases. [native-ghidra-current.json](results/native-ghidra-current.json) replays the **same preserved IR** under matching/2 without repeating extraction. All six replay manifests complete: constant/condition changes match with review facts; added-check remains candidate/material; moved matches/unchanged; split and merged each retain an entry pair plus two one-sided tiny W helper observations. There are **zero automatic N:M groups** in these cases. Exported-name P03 anchors, tiny functions and authored source relations prevent interpreting this as split/merge recognition or representative accuracy. No Ghidriff/manual/secondary atoms are mixed into those ladder-only computations.

The real primary Ghidriff attempt and native extraction are different evidence from that replay. The primary attempt completed but returned `modified_funcs_len=0` on the constant-edited fixture; successful execution must not be renamed a correctness pass. Rizin's 22+5 native outcomes remain as 07 reports, including twenty rejected initial runs and conditional reversal. No R2 native BinDiff/Diaphora/BSim benchmark fills the remaining comparison cells.

Baseline workflow reconciliation in 00 reports **NOT READY** despite an advisory green workflow: no evaluated whole-pipeline outcomes, missing A/A/mutant/precision/determinism evidence and pending largest-pair/facts/UI/frozen checks. Current full Linux validation and Windows/new-head release gates belong to the integration report; they were pending when this inventory was written. Portable tests, six tiny native replays and bounded cost experiments establish useful executable behavior, while broad matching correctness, calibrated confidence and release readiness remain unverified.

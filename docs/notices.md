# PatchTrace dependency notices and distribution inventory

This is an engineering inventory based on the repositories and revisions recorded in [reuse-matrix.md](reuse-matrix.md), checked 2026-10-11, plus the current project manifest and Windows build script. It is not legal advice. The actual shipped inventory depends on locked package versions and what the Windows build collects. No release installer or build artifact has been inspected.

## Distribution recommendation

Ship PatchTrace's Windows desktop UI as the product package. Treat the binary-analysis worker as a separately versioned component. For the first beta, the simplest auditable path is to require or guide installation of a compatible Ghidra/JDK/Python environment and invoke the pinned ghidriff CLI as a supervised process; do not silently download an unpinned `latest` container. A managed installer can provision the worker/runtime separately after their licensing and compatibility are reviewed. If PatchTrace redistributes ghidriff, Ghidra, Python packages, or a JDK, include the applicable licenses, notices, source/license links and any required corresponding-source materials for that distribution. A separate process boundary does not itself decide license obligations; obtain a distribution review before shipping a bundled GPL component. The full bundle is gated by the policy table below.

The inspected ghidriff source is GPL-3.0 and the recommended engine is its CLI. Ghidra is Apache-2.0, but its release contains a separate third-party license inventory. Keep the source projects separate and retain upstream notices. Do not treat “open source” as one combined license. Re-check every selected exact version at packaging time.

## Full-bundle licence policy (policy gate, not a legal finding)

The product rule allows no GPL-family code beyond Ghidriff (GPL-3.0) as a separate, unmodified, out-of-process program. The full backend bundle also contains components that rule does not cover on its face. `tools/backend_pin.json` therefore carries an explicit `license_policy`, enforced by `tools/check_backend_pin.py`, `tools/build_backend_bundle.py` and the attach step of `tools/build_linux.py` / `tools/build_windows.py` (code `PT-BUNDLE-LICENSE`). Any component whose SPDX is GPL, LGPL or AGPL and that is not listed, with an identical SPDX, is refused. This is an engineering gate. It is not a statement that the distribution is legally compliant.

## Release artifact inventory to generate

For every beta build, create and review these records against the actual installer contents:

1. **`THIRD_PARTY_NOTICES.txt`** — component name, exact version, copyright holder, license identifier, source URL/revision, bundled/external status, and path to the included license text.
2. **`licenses/`** — complete required license/notice text for every distributed component. Preserve upstream NOTICE files (PatchWatch's inspected snapshot includes one, though PatchWatch itself is not selected). Include Ghidra's release-specific `licenses/` tree if shipping Ghidra.
3. **SBOM** — machine-readable inventory of direct and transitive dependencies, exact versions, hashes, source URLs, and detected license expressions. Generate from the final resolved build/install environment, not from this high-level proposal.
4. **Runtime manifest** — PatchTrace version; Ghidriff revision/version; Ghidra release; Python; pyghidra; Java vendor/version; worker arguments; optional model/provider identity. Case records should store the analysis subset needed for reproducibility.
5. **Source and compliance archive** — retain upstream source archives/revisions and build metadata for each redistributed artifact. Make required source corresponding to redistributed GPL components available according to the applicable license and delivery method.

## Packaging gates

- Run a license scanner against locked Python/Rust/Java/native dependencies, then manually review ambiguous and dual-license entries.
- Inspect the exact Ghidra release ZIP (including `licenses/`, `GPL/`, and nested JAR metadata); do not rely only on the Ghidra root license.
- Verify the compatible Ghidra, pyghidra, JDK, Python, and ghidriff matrix on clean Windows 11 x64 machines.
- Verify that offline/local comparison works without a cloud key. Keep remote AI off until the user selects a provider and sees what data will be sent.
- Rebuild notices and SBOM after every dependency lock or installer change. An upstream project license does not license its external disassembler, commercial graphing libraries, JDK vendor bundle, or model weights.

## Qt SVG runtime for the owner mark (WIN-1 candidate)

`patchtrace.app_icon` uses QtSvg from the existing pinned PySide6 6.12.0 distribution to render the packaged owner mark. Windows and Linux builds must retain replaceable Qt SVG libraries and ship `third_party/notices/qtsvg-6.12.0/` with the existing Qt/PySide notices. The pinned upstream record is Qt `qtsvg` tag `v6.12.0`, commit `883a58532078d003cefef0a549bfe9f885ce41f5`; its provenance, exact license texts/REUSE metadata and source copyright/SPDX headers are retained. LGPL-3.0-only is the selected Qt library redistribution alternative; the BSD source-header notices are retained too. This source inventory does not substitute for inspecting the exact frozen Windows/Linux package. The candidate must pass frozen icon self-test and executable-resource read-back before its new packaging gate is accepted.

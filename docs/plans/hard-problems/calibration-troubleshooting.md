# Calibration troubleshooting (symptom, cause, confirm, fix)

Date 2026-10-14. Companion to `calibration-plan.md`. Math notes (tagged V/M) in `docs/research/phase-c/matching-calibration-ground-truth.md`. Rule for every fix: never re-tune on locked-test; a fix after a locked-test look needs preregistration v2 and the v1 result stays in the report.

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| **ECE unstable** across folds/seeds or just above the gate | Plug-in ECE is biased upward even for a perfect model; few effective samples (weights shrink n); equal-width bins with most mass in the top bin; bin count sensitivity | Run a null simulation: draw y ~ Bernoulli(p) from your own predictions with the same weights and clusters, compute ECE 1000 times. If observed is inside the null band, there is no miscalibration evidence. Compute effective n = (sum w)^2 / sum w^2 per bin. Vary B in {5,10,15,20} and equal-mass bins | Gate on `observed - null mean` and the cluster-bootstrap CI, not on an absolute number; add debiased l2 error, slope, intercept; merge bins with effective n < 30; report equal-mass ECE; do not reduce B to pass |
| **Isotonic overfit** (val Brier worse than Platt, p of exactly 0 or 1, staircase reliability) | Too few positives or negatives, sparse score regions, weights up to 20x, calibrator fit on in-sample scores | Compare inner-CV Brier and log-loss of isotonic vs Platt; count knots vs effective n; inspect min/max output; check calibrator input is OOF only | Platt unless isotonic wins by the one-SE rule; clip to `[1/(sum_w+2), 1-1/(sum_w+2)]`; merge knots with effective weight < 20; test Venn-Abers; confirm the calibration set is separate from base-model fit data |
| **Leakage suspected** (CV metric much better than locked-test; near-perfect AUC; dev precision 0.999) | Same function in several candidate pairs across folds; duplicated bodies across lineages; symbol-derived features paired with symbol-derived labels; calibrator stats fit outside the fold; ICF-folded bodies | (1) Compare grouped vs random CV: the gap should be large when dependence exists. (2) Count identical relocation-masked body hashes shared by train and test. (3) Shuffle labels within lineage: AUC must fall to 0.5. (4) Fit on the label-only features (size, name provenance) to see if they predict y. (5) Permute the `P.symbol_provenance` feature | Union-find over function endpoints plus lineage; remove or stratify shared bodies ("seen-body"); fit standardisation, C and calibrator inside training folds; drop symbol-derived features from the headline; add a unit test reproducing the leak |
| **Label disagreement** (kappa < 0.80, symbol label vs human mismatch > 2%, ICF noise) | Guideline ambiguity (split/merge/inlined, large rewrites), label source flaws (static names not unique, ICF, thunks), annotator anchoring on engine score | Per-subtype kappa with CI; confusion of symbol-derived vs human; list the 30 worst disagreements and tag cause; check whether annotators saw engine output | Revise guideline `g1`, relabel the batch (keep the old one in the report); key symbols by (name, file, line); add subtype for ICF; adjudicate with a third pass; demote the source to `weak` at > 2% error; keep `indeterminate` counted with a worst-case bound |
| **OOD false alarms** (hard flags on many correct matches, coverage collapses) | Mahalanobis on a few heavy-tailed features, covariance estimated from few rows, categorical level unseen only in this engine build, soft/hard threshold too tight | Risk ratio of error rate for flagged vs unflagged with cluster CI (must exceed 1 to justify a flag); per-feature contribution to d2; flag rate per lineage and per engine version | Log-transform size features; raise shrinkage; demote to range/unseen-level checks only when the ratio CI includes 1 (preregistered fallback); handle new engine-version level as a soft flag; never loosen after locked-test |
| **Engine version drift invalidates a model** (scores shift after BinDiff/Ghidra/rizin update, flag rate jumps) | Engine scores are algorithm-specific; a version changes feature distributions without changing code | Re-run a frozen Tier R canary set under old and new engine builds; compare score distributions (KS statistic, per-feature mean shift) and the reliability curve; read `calibration_domain.engines` | Model expires on engine major version (SPEC-28 sect. 12); fall back to L0; refit using Tier R canary + a new local Tier W sample; keep per-version buckets; pin engine versions in CI and the frozen EXE; never apply an old model silently (the version mismatch is a soft OOD flag at minimum) |
| **Tiny strata** (n below 30-200, wide intervals, stratum "insufficient") | Rare subtypes (N9-N11), few lineages per family/toolchain, quota under-sampled | Table of n, effective n, groups contributing per stratum; precision CI width; check the committed sampling list quotas | Report as `insufficient`; abstain by default there; pool only by a rule written beforehand; oversample in a **new** preregistered batch (never based on test results); use exact (Clopper-Pearson) bounds with design-effect n, not normal intervals |
| **Non-determinism** (report SHA changes between runs/platforms) | Unordered dict/set iteration, `random` state, `sum` instead of `math.fsum`, threads, locale/float formatting, differing engine output order, timestamp in report | Run twice on Linux and Windows, diff `report.json` by key; set `PYTHONHASHSEED`, compare; check float repr; check fit iteration counts | Sort by stable ids; `det_uniform` (53-bit fix); fixed iteration counts; round to 12 significant digits before serialising; no wall-clock fields inside hashed content; canonical JSON |
| **Fit does not converge / Hessian not SPD** | Near-separable data, collinear features (e.g. B and R similarity), zero-variance column | Condition number of H; coefficients exploding; feature correlation matrix | Increase ridge (smaller C); drop one of the duplicated features; step-halving; error out rather than continue silently |
| **Coverage-precision looks good dev, fails locked-test** | Tau chosen on same OOF scores (winner's curse), too few lineages, shift | Compare dev bootstrap CI with locked CI; jackknife worst lineage; shift-test result | Choose tau with lower-bound margin (0.96) or fixed-sequence Learn-then-Test; report the failure; no retune |
| **Gate flips pass/fail by one lineage** | Influential lineage dominates accept set | Leave-one-lineage-out precision and coverage | Report as `fragile`; require the lower bound to hold in the jackknife worst case; add lineages |
| **Isotonic and Platt disagree around tau** | Non-sigmoid score distortion or sparse region | Plot both on the same OOF set; count items between the two thresholds | Choose by preregistered rule (one-SE); if unclear, abstain in the gap band |

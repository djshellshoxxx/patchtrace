# BinExport2 troubleshooting (symptom -> cause -> confirm -> fix)

Date 2026-10-14. Evidence labels: [M] measured 2026-10-14 (protobuf 7.36.2 upb, Linux, CPython 3.13); [D] from primary docs (see research note); [H] hypothesis, confirm first. Context: `binexport2-plan.md`, `docs/specs/binexport2-support.md`.

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| `pip install` of protobuf fails or wants to compile (win/arm/musl/3.15) | No abi3 wheel for the platform; sdist chosen [H] | `pip download protobuf==7.36.2 --only-binary=:all: --no-deps -d X`; list wheel tags (7.36.2 ships `cp310-abi3` win_amd64 + manylinux2014_x86_64 + pure `py3-none-any` [M]) | Platform without abi3 wheel: feature reports `unsupported(protobuf_missing)`; do NOT accept the pure wheel silently (it installs fine but is the 85x DoS path). Add platform to the "unsupported" list in docs |
| Pip picks `py3-none-any` wheel; `Type()` prints `python` | Pure wheel installed on unsupported platform, or `_message` removed | `python -I -c "from google.protobuf.internal import api_implementation as a;print(a.Type())"`; `pip show -f protobuf \| grep _upb` | Reinstall with `--only-binary=:all:` on a supported platform; otherwise unsupported. Never relax the assertion |
| upb not active though wheel is abi3 | `PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python` set; or `_message` import error (missing VC runtime, bad frozen collect) which protobuf downgrades to a **warning** and falls back [D api_implementation.py] | Run with `-W always`, look for "Falling back to the python implementation"; `python -c "import google._upb._message"` shows the real ImportError | Remove env override; install VC++ runtime / fix freeze; remember `PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=upb` does not make fallback an error, only the `Type()=='upb'` assertion does |
| Frozen app: `ModuleNotFoundError: google._upb` or `Type()` is python | PyInstaller missed the C extension; or one-file extract path blocked by AV [H] | Inspect `dist/.../_internal/google/_upb/_message.*` (Linux `.abi3.so`, Windows `.pyd`); run `--self-test` | `--hidden-import google._upb._message`; for AV: build onedir (current layout); record in `docs/qa.md` |
| Frozen app: `ImportError` for `google.protobuf` generated/`runtime_version` | Gencode newer than frozen runtime (only if fallback B is used) [D runtime_version rule] | Compare gencode header version to `google.protobuf.__version__` | Private-pool path avoids this; otherwise regenerate with protoc <= pin |
| `descriptor_mismatch` / golden-field-table test fails | Descriptor regenerated from a different .proto, or runtime changed field semantics | Compare `PROTO_SHA256` (`e8e4943d...`) with `sha256sum binexport2.proto`; diff golden table | Regenerate with `tools/gen_binexport_descriptor.py` from the pinned commit only; never edit the base64 by hand |
| "Not a valid BinExport" on a real export | Strict rule false positive (vertex order, duplicate thunks, entry block, empty block, md5 id, singleton duplicates) [H] | Reason slug in error; run `inspect_binexport` in-process with `warn_only` for that rule; check `unmatched`/counts | Downgrade rule to warning + regression test with the golden (spec U3); do not add override flag |
| `executable_id_md5` / `executable_id_empty` rejection | IDA exporter falls back to MD5/empty id (spec §1) | `summary.executable_id` length 32 or 0 | Use `accept_unbound` with user confirmation; shown as 'asserted' |
| `executable_id_mismatch` | Ghidra project imported a different copy than the artifact; or file reused | Compare SHA-256 of artifact with id | Re-import from the exact artifact path (spec §8 item 7) |
| `utf8_invalid` never fires, or checker crashes with `AttributeError: 'bytes' object has no attribute 'encode'` | upb returns **bytes** for invalid UTF-8 in proto2 string, pure Python raises instead [M] | `list(x.s)` shows `bytes` element | Check `isinstance(s, bytes)` first; add test with `b'\xff\xfe'` string |
| Valid file reported as parse failed / `INPUT` under memory cap | Cap hit during parse: upb raises `DecodeError: Arena alloc failed`, not `MemoryError` [M] | Retry same file with higher cap; compare `ru_maxrss`/PeakProcessMemoryUsed to cap | Classify as `worker_oom` when peak >= 0.9*cap (plan S7); raise `memory_bytes` |
| Windows worker dies at start / `worker_crash` with memory cap | `ProcessMemoryLimit` limits **committed** bytes; interpreter + DLLs + frozen bootloader commit more than RSS [D basic_limit_information; H on size] | Run plan W1 idle-worker case; read `PeakProcessMemoryUsed` | Raise floor (>=512 MiB, >= 4x idle commit); do not use `JobMemoryLimit` unless one process per job |
| Windows: no cap enforced | Flag `0x100` not set in `LimitFlags`, or struct size mismatch with `SetInformationJobObject` class 9 | Query back with `QueryInformationJobObject`; check `sizeof(ExtendedLimits)` | Set `0x2000|0x100`, fill `ProcessMemoryLimit`; test child over limit |
| Windows: `AssignProcessToJobObject` ACCESS_DENIED | Process already in a job on Windows < 8, or CI job blocks nesting [D assignprocesstojobobject] | Windows version, `IsProcessInJob` | Win8+ nests jobs; on older, unsupported. Limits: most restrictive wins |
| Linux cap ignored or deadlock at spawn | `preexec_fn` in a threaded GUI process (documented unsafe [D subprocess.rst]); or `prlimit` set after the worker allocated | Check `/proc/<pid>/limits` for "Max address space" | Use launcher script that sets `RLIMIT_AS` then `execv`, or `prlimit` before releasing worker from stdin wait |
| `MemoryError` on Linux import/start with small caps | AS cap lower than interpreter + upb footprint; upb imported at 64 MiB in [M] but Python + libs vary | Lower-bound by running worker with decreasing caps | Floor `memory_bytes` at 512 MiB; AS ~= RSS + 10..60 MiB for upb [M] |
| Timeouts (`worker_timeout`) on large files | Pure-Python checker passes slow, or pure-Python protobuf active, or slow runner/AV scanning the snapshot | Time each stage (prescan/parse/check); check `Type()`; compare with W3 table | Raise `wall_seconds` only with evidence; fix pass complexity; confirm upb; exclude private dir from AV only by documenting, not silently |
| `file_changed_during_read` or `too_large` on big exports | Exporter still writing, file on network share, or size > 256 MiB cap | `os.stat` twice | Wait for export end; keep cap until live evidence (spec U1) |
| Hostile stderr/log content in UI | Worker stderr tail includes file strings | Inspect `res.stderr_tail` | Sanitise, diagnostics only (spec T6) |
| Ghidra headless: no `.BinExport` produced | Wrong invocation: script run as `-postScript` or without prior `-import`; missing `BinExport.properties`/args; extension not installed or built for another Ghidra (zip targets 11.0.3) [D README] | Check log for script not found; Ghidra `Install Extensions` list; ensure project contains the program | Use README recipe: `-process <file> -propertiesPath <dir> -preScript BinExport.java -noanalysis` (or positional args after script name); install matching extension |
| Ghidra headless exit 0, no file | Script prints failure without throwing (spec claim, **[H]** not verified) | File exists check after run | Success = exit 0 **and** file accepted by `accept_binexport` |
| Ghidra export has unexpected addresses (all RVA) | "Subtract Imagebase" chosen in one export only | `address_basis` in summary | Same options for both files; `address_basis_mixed` rejects |
| Ghidra output missing operand trees | Ghidra exporter has no operand trees [D java/README] | `operand` count 0 | Expected; only warnings, do not reject |
| Ghidra menu entry not found | Upstream docs name it "Binary Export (v2) for BinDiff" (main) vs "Binary BinExport (v2) for BinDiff" (java) [D] | Look at Export dialog format list | Match by substring "BinDiff" in docs; do not code UI automation against the label |
| IDA export fails/old IDA | BinExport supports IDA Pro 9.4+ only [D] | IDA version | Use Ghidra or upgrade; IDA headless: `-OBinExportAutoAction:...` before file names; output name derived from database |
| Atheris will not install on Windows | Atheris supports Linux/macOS only [D README] | pip error / docs | Run nightly fuzz on Linux; Windows uses hypothesis only |
| Differences in behaviour between Linux and Windows CI | Different abi3 wheel build, commit-limit vs AS, path/permission rules (`O_NOFOLLOW` absent) | Compare `docs/qa.md` rows; run W1/W2 | Platform-specific expectations in tests; never mask with skips without a qa row |
| BinDiff rejects an accepted file / accepts a rejected one | Validator gap or false reject (spec U12) | Run `bindiff` on both snapshots | Add regression test; tune rule |

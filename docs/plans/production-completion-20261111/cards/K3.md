# Slice card K3 - the KB and CVE dock must work for the project the desktop holds (KBB-01 / D-DEF-01, severity high)

Evidence and design: `jq '.actionable_now[] | select(.id=="D-T01")' docs/status/inventory/D.json`,
`jq '.features[].defects[]? | select(.id=="D-DEF-01")' docs/status/inventory/D.json`, feature row D-F12.
Specs: docs/specs/kb/store-threading-spec.md (rule R1: the project store is owner-thread only),
docs/specs/kb/leads-dock-lifecycle-spec.md, docs/specs/kb-cve/31-F-workflow-ui-persistence.md.

## Defect
src/patchtrace/kbcorrelation/panel_qt.py (about lines 45-52): the dock's production loader calls
`leads_outcome(build_service(ws), RealEngine(), project_dir)` on a worker thread, which opens the ALREADY OPEN project a
second time. The project lock refuses that, so the dock shows "the project cannot be opened" for every project the desktop
holds. The analyst reproduced it on main with the sample project. Existing tests pass because they inject a fake loader.

## Required behaviour
The dock reads the open project through a snapshot taken on the owner (GUI) thread - the facts the leads computation needs
are captured from the already-open ProjectService on the GUI thread and handed to the worker as immutable data; the worker
never opens the project. The CLI path (RealEngine.read by directory in cli_leads.py) must keep working unchanged for
`patchtrace kb leads`.
Read first: how other docks solve the same problem on main (for example the Leads dock in src/patchtrace/ui_leads.py and
the unified panel - `grep -n "snapshot" src/patchtrace/ui_leads.py src/patchtrace/ui_unified.py src/patchtrace/gui/qt/*.py | head -40`)
and reuse that pattern rather than inventing one.

## Red test (must fail on main for the real reason)
tests/test_ui_kb_panel.py: hold `ProjectService.sample(tmp_path/...)` open (as the desktop does), drive the real
KbController / dock with its DEFAULT production loader (no injected fake), wait with qtbot.waitUntil (no fixed sleeps),
and assert the state becomes ready or no-advisory - never failed; assert by monkeypatch that no second
`ProjectService.open` (or ProjectStore open) happens while the project is held. Add a second test that the worker path
performs no project-store access off the GUI thread (record threading.get_ident() in a wrapper around the store read
method).

## Constraints
- Every project-store read stays on the GUI thread; the snapshot must be cheap (bounded) - if it can be large, say what
  bounds it.
- Do not edit ui.py, panel_manifest.py or tooltips.py (frozen); the dock is created through the panel registry - if the
  host must pass the open service to the dock, find the existing hook the other docks use and report the exact one-line
  change under "Integrator asks" only if no hook exists.
- Qt teardown is delicate in this codebase: run your new tests 20 times in a row
  (`for i in $(seq 20); do ... -q -x; done | grep -c passed`) and with
  `cd <worktree> && QT_QPA_PLATFORM=offscreen PYTHONPATH=<worktree>/src python tools/qt_gate.py --help`
  check whether qt_gate can target a single file with --repeat; use it if so.

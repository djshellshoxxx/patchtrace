## Goal
The 87-case L1 corpus has never been run through PatchTrace's advisory join: no runner exists. Build
`tools/research_qualification/l1_run.py` and a subcommand `python -m tools.research_qualification l1-run MANIFEST --months DIR --out RECEIPT`
that, for every case in a FROZEN rq-l1-manifest/1 manifest, asks the product's own offline join (the kbcorrelation
reverse index / KbService built over an imported CVRF month directory, exactly as `patchtrace kb index import` and
`kb search` do - use the public service API, do not re-implement the join) for:
  (a) is the expected CVE -> KB edge found, (b) is the expected product scope found, (c) is the expected file resolvable
  for that KB/product when a file index is supplied (optional `--winbindex DIR`),
and writes a receipt per the existing receipt convention with per-case outcome PASS / FAIL / BLOCKED and the reason, plus
counts. Cases marked `facts: unverified` are listed and excluded from every count that could be read as accuracy. A
manifest that is not frozen (freeze hash absent or wrong) is refused for a scored run (exit 2); a `--dry-run` may list
what would be asked. A month that is not present in --months makes its cases BLOCKED (not FAIL).
The runner reports per-layer L1 only and prints the Clopper-Pearson bound over independent products only if
tools/research_qualification/sample_size.py already provides it - do not invent statistics code.

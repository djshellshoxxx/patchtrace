## Verified as correct (no finding)

- Credentials: `ProviderConfig.api_key` is hidden from `repr` (verified). `ui.py:2862-2864` persists only kind, endpoint and model. The key lives in the `ProviderConfig` closure, and transport errors are fixed text (`providers.py:169-182`).
- No silent send: `request_completion` is reached only from `interpretation.interpret`, which the UI calls after `ContextDialog` is accepted. The payload sent is `context.payload`, the same string previewed (`interpretation.py:78-80`, `:257`).
- Endpoint rules: userinfo, query, fragment, whitespace and control characters are refused; mapped IPv6 loopback is refused on every interpreter. Redirects, proxies and oversize responses are handled.
- Series paths: `PairRef` rejects absolute, drive-qualified, `..` and backslash paths; `staleness`, `DiskPairReader.read` and `read_raw_matches` check containment after `resolve()`.
- `series.json` import: size is checked before read, duplicate keys and non-finite numbers are rejected, unknown fields are refused, and build hashes and the series id are verified.
- Calibration display: no calibrated number reaches any UI or export (`PolicyResult.p` and `shown_p` have no consumer outside `calibration/`). Display stays `ordinal` with no artifact (verified by `display_level()`); dev override is forced to `experimental` and `display=none`.
- Calibration artifact loader never raises and rejects duplicate or ambiguous profiles.
- Chain orientation: pair projects are validated against ordered hashes (`graph.py:58-62`), and a swapped pair is refused.

## Suspicions (not findings; no repro)

- `series.py:131` skips symlinked siblings with `is_symlink()`. On Windows, junctions are not symlinks; `Path.is_junction()` would cover them. Needs a Windows run.
- `view_model.py:165` `_derive_state` marks `stale` only when no pair is `ok`. A single bad pair in a multi-pair series therefore shows `partial` while its chains are stale. This matches the spec's wording but may read as too mild. Owner decision.

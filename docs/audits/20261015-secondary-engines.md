### Checked and not a defect

- `_input_path` (`backend.py:343-356`) looks unsafe with an unresolved root, but its only caller passes a root resolved at `backend.py:486`. No false rejection in production.
- `reconcile.py:88-100` counts one-sided secondary records as `disagreement`. The spec defers this verdict to SPEC-31 U-04 (`multi-engine-evidence-calibration.md:8`), so it is tracked, not a new defect.
- BinExport prescan (`binexport_prescan.py:37-111`: varint and length bounds, field 0, wire-type checks), snapshot (`binexport_snapshot.py:30-70`: `O_NOFOLLOW`, `fstat` on the handle, exclusive create), and checker (`binexport_check.py`: iterative cycle and depth checks, index bounds, coverage amplification) found no defect.
- BinDiff argv allow-list (`bindiff_run.py:63-74`), `shell=False` (`jobs.py:274`), env allow-list (`engine_env.py:36-53`), SQLite hardening (`bindiff.py:55-78`), output guard (`bindiff_run.py:97-116`), and "preserve before parse" (`bindiff_run.py:258`). No defect.
- rz-diff strict JSON (`rzdiff.py:103-137`): duplicate keys and NaN are rejected; stdout is capped at 64 MiB.
- Evidence display sanitization (`evidence_view.py:101-110`) strips bidi and control characters.

### Suspicions (not counted; no repro)

- `bindiff_inputs.copy_and_hash` (`:152-162`): `lstat` then `open` follows symlinks. The source is the 0400 accepted snapshot, so impact is low.
- `binexport_pipeline.alloc_failure` (`:55`): uses process-wide VmPeak, so a malformed file can be reported as `worker_oom` after a large earlier allocation.
- `backend._output_scan` (`:367-378`): bounds only `*.json`; other Ghidriff output is bounded only by the timeout.
- `bindiff_probe.probe_report` cache (`:147-160`): keyed by (path, mtime, size); a same-size replacement with preserved mtime serves a stale capability.
- `RzDiffAdapter.probe` (`registry.py:67-71`): resolves `rz-diff` via PATH by design; Windows cwd search behaviour not verified here.

# QA-FUZZ: hostile-input audit of importers and parsers (2026-10-15)

Scope: the completed importers and parsers that consume untrusted bytes. Tests live in `tests/stress/test_fuzz_*.py`
(Hypothesis, `deadline=None`, `database=None`, 120 to 200 examples per property, every file well under 30 s).
Nothing executes a target binary, nothing opens a socket, and nothing is extracted to disk: archives and PE images
are built in temporary directories and parsed as bytes.

Run: `QT_QPA_PLATFORM=offscreen python -m pytest tests/stress -q -p no:cacheprovider`

Result at commit time: 107 passed, 4 xfailed (strict), 0 failures; the slowest file is about 2 s. Ruff clean on
`tests/stress`.

## Bugs

Each xfail is `strict=True` with a `QA-FUZZ-n` reason, so it turns into a failure as soon as the defect is fixed
and the marker is removed.

### QA-FUZZ-2 (Low): hostile ZIP escapes the typed error contract

- Repro: take a valid offline bundle whose member `docs/café.txt` carries the UTF-8 name flag. Replace `caf\xc3\xa9`
  with `caf\xc3\x28` in both the local and central headers. `inspect_offline_bundle` raises `UnicodeDecodeError` from
  inside `zipfile` instead of `OfflineBundleError`.
- Cause: `src/patchtrace/offline_bundle.py` `_READ_ERRORS` (lines 36-37) lists `OSError`, `EOFError`,
  `BadZipFile`, `LargeZipFile`, `RuntimeError`, `zlib.error`, `NotImplementedError`, but not `UnicodeError`.
- Impact: no code execution and no extraction. The job runner (`jobs.py`, which catches `BaseException`) is expected to
  report a generic failure instead of the actionable `PT-OFFLINE` message; the UI path was not exercised.
- Test: `tests/stress/test_fuzz_archives.py::test_invalid_utf8_member_name_is_a_typed_offline_error`. The random
  byte-corruption property excludes this one exception, with a comment that points here.

### QA-FUZZ-3 (Low): advisory text keeps invisible format characters

- Repro: `kbcorrelation.products.clean_text('​CVE-2099­-1﻿')` returns the input unchanged. Zero-width
  space, soft hyphen, BOM and tag characters (category Cf) survive.
- Cause: `_BIDI` in `src/patchtrace/kbcorrelation/products.py` lists only the bidirectional marks. The shared rule in
  `src/patchtrace/hostile_text.py` (bidi, zero-width, BOM, soft hyphen, tag, surrogate) is not applied.
- Impact: invisible characters can split an identifier visually or in matching (for example a CVE token) while
  looking identical on screen. Advisory text is data, so this is a display and matching integrity issue, not
  execution.
- Test: `tests/stress/test_fuzz_text_fields.py::test_advisory_text_removes_every_format_character`.

### QA-FUZZ-1 (Low): NFC and NFD spellings of one JSON key are not duplicates

- Repro: `strict_json('{"é": 1, "é": 2}')` and `load_json_strict` both accept the document. The duplicate
  check compares code points only.
- Context: ZIP member names are NFC-folded for collision detection (`offline_bundle._zip_entries`), so the JSON layer
  is inconsistent with the archive layer. A consumer that NFC-normalises keys would silently keep the last value.
- Test: `tests/stress/test_fuzz_json_importers.py::test_nfc_and_nfd_spelled_keys_are_duplicates`.

### QA-FUZZ-4 (Low): Winbindex loader accepts an overflowing float literal

- Repro: `winbindex.parse(b'{"k": {"fileInfo": {..., "x": 1e999}}}', 'kernel32.dll', date, compressed=False)` does not
  raise (the entry is only skipped for its missing required fields). `persistence.strict_json` rejects the same
  literal through its `finite_float` guard.
- Cause: the module-local `strict_json` in `src/patchtrace/acquisition/winbindex.py` (around lines 70-82) handles
  NaN and Infinity tokens through `parse_constant` only; `1e999` never reaches it.
- Test: `tests/stress/test_fuzz_feeds_and_ir.py::test_winbindex_rejects_overflowing_float_literals`.

## Properties that held (no defect found)

- Strict JSON: duplicate keys, NaN and Infinity tokens, digit-limit integers, lone surrogates and deep nesting are all
  refused by `strict_json`, `load_json_strict`, `parse_json_line`, and the CSAF and KEV loaders.
- ZIP guards: traversal, absolute and backslash names, symlink and special-file modes, directory entries, exact and
  case-folded duplicates, NFC/NFD collisions, reserved Windows names, unlisted files, bzip2 and encrypted entries, and
  the per-member compression ratio all refuse the hostile archive before extraction. Declared-size lies are bounded
  by `_verify_stream`, which stops reading one chunk past the manifest size.
- Winbindex gzip: the 64 MiB compressed and 256 MiB decompressed caps hold (checked with small monkeypatched caps).
- PE overview: no exception for mutated, truncated or noise images; no hostile character reaches an output string.
- BinExport prescan: no non-typed exception on arbitrary bytes; all listed refusals hold.
- CVRF XML: entity expansion is refused.

## Not covered, and why

- No tar extraction exists in the product. `tarfile` appears only in `tools/verify_backend_pins.py`, a developer tool,
  so no tar-guard tests were written.
- capa and FLOSS are fuzzed through their result parsers on mutated golden documents. Their subprocess argv, exit
  classification and stderr handling were not fuzzed (no execution is allowed in this slice).
- BinDiff import (`secondary/bindiff.py`) is covered only through the BinExport prescan, not the full importer.
- Hypothesis example counts are bounded for CI time. Longer soak runs are a separate decision.

## Observations (not defects)

- `persistence.strict_json` is annotated `-> dict` but returns any JSON value; its callers depend on the returned
  type, so the annotation should be corrected when the module is next touched.
- `persistence.strict_json` accepts bytes input through `json.loads` encoding detection (UTF-16 and UTF-32 bodies
  parse). All current call sites pass decoded `str`, so this is latent only.

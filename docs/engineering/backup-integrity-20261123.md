## Source boundaries

The project has one supported database and snapshot version. Two historical fixtures cover version 1. SQLite may checkpoint a newer database's committed WAL when normal open refuses that version. The test preserved its logical data and observed the change in physical database and sidecar bytes. [Machine receipt](evidence/backup-integrity-20261123/project-schema-compatibility-receipt.json)

Staged verification checks the current project snapshot, referenced raw records, and immutable inputs. Auxiliary directories such as exports can contain independent files without snapshot hashes. A WAL-mode copy can acquire empty WAL/shared-memory sidecars during a read-only connection. The tested backup reopened with the latest committed data. Public CLI verification still respects another user's project ownership. [WAL fixture](evidence/backup-integrity-20261123/staged-backup-wal-probe.json)

The backup destination must have a stable parent and an ordinary private staging directory. Windows uses its native non-replacing rename. Linux requires libc and filesystem support for `renameat2(RENAME_NOREPLACE)`. An unsupported platform or filesystem receives a refusal. The historical full PRs, their other consumers and their merge holds remain separately owned.

The baseline Windows artifacts passed 123 automated accessibility, theme, layout and keyboard checks. A real operator's screen reader, physical keyboard navigation and monitor scaling remain release gates. The most recent published beta's 18 manual Windows checklist entries were all unrun. The separate full disconnected runtime still lacks a qualifying Windows receipt.

## Fresh adversarial finding and narrowly complete correction

The prior `WorkspaceFileIndex._record` admitted a normal file; if a competing
actor replaced that pathname with a **directory after scan**, Python's
`open(..., opener=no_follow_open)` raised `IsADirectoryError` (POSIX
`errno.EISDIR`) *before* the new descriptor `fstat` could reject it.
Generation 17 mapped every `OSError` except `ELOOP` to `PT-KBC-INPUT`,
contradicting its contract that matching nonregular source objects fail
with `PT-KBC-SOURCE`. No foreign bytes were read in this reproduction.
The original POSIX behavior was independently reproduced using the same
standard-library open/opener flags: errno 21 (EISDIR).

SPEC-31-D was extended **before code** to cover this narrow post-selection
condition. The patch maps `errno.EISDIR` to `PT-KBC-SOURCE` with the existing
"not regular" wording, preserving `ELOOP` as alias and every other I/O failure
as `PT-KBC-INPUT`. It does **not** prevent a regular-file substitution or
make lookup atomic. New actual-repository tests stage a post-scan directory
swap (POSIX EISDIR contract) and guard nonblocking FIFO swap rejection
(host capability conditional).

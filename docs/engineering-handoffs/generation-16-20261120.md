## Two original failure reproductions

An **isolated standard-library mirror** of the existing method, using a synthetic
25-byte JSON file and deliberately stale file-size metadata (4 bytes), accepted
the over-budget body rather than rejecting it. The same adapter retained a
`skipped=2` counter after that source was removed and `rows_for` returned no
rows. This exercise did not import the full project or execute binaries. It is
not the repository's required pytest acceptance run.

The repository regression file
`tests/test_kbc_winbindex_read_budget_20261120.py` checks both behaviors on
actual `WorkspaceFileIndex`: an open stream is capped at the configured limit
plus one sentinel byte even when pathname metadata is stale, and removing a
formerly partially rejected record reports `((), 0)` on the same adapter.
The test uses synthetic JSON and a test-local reduced `MAX_COMPRESSED`, with
no networking or real targets. The source change only adds a bounded
`handle.read(MAX_COMPRESSED + 1)` and clears old per-filename skipped counts
before each read. Valid current skips and `index_rows` rejects remain counted.

An independently invoked **isolated standard-library repair mirror** returned
`PT-KBC-LIMIT` on the stale-size control and changed the missing-record count
from one to zero. This is a model of the edited algorithm, not a reported full
repository pass. At this source checkpoint there is **no actual repository

## Original defect and uniqueness

In `kbcorrelation.acquire.row_for`, matching only the binary SHA and basename returned the *first* source row. When a single build has BASE and KB records, the BASE entry is often first in the parsed source order. An exact pair `window_id=index:10-22H2:KB5030500` then persisted a BASE row as the **newer** source entry, despite the selected target being the KB. The pre-change synthetic control returned null KB. This is an evidence/membership defect, not a binary verification failure. The exact first-match routine occurs in main, PR325, the PR335 parent and retained `work/winbindex-publication-20261105`; the selected-window requirement is absent from all inspected versions. This scoped comparison does not complete 154 historical semantic reviews.

In the consented `KbService.acquire` route, the **newer** normalized row must now match that KB and version key, including an alias only if explicitly listed in `other_versions`. Native version-key bodies win over inherited copies, matching lineage's existing precedence. Missing/malformed anchors refuse `PT-KBC-INPUT` before planning, consent, network or project creation.

## 1. Principles
1. ONE comparison window (D-18): `MainWindow` keeps one navigator, one pair of code panes, one evidence dock. The unified result is a VIEW MODE of the same window, never a new top-level window; the read-only `SeriesWindow` (N-way) is unchanged and out of scope.
2. The UI is a thin view over `read_model.py` (Qt-free); widgets hold no analysis state.
3. Native per-source values appear only in that source's own column with units; decisions and verdicts are words + ASCII glyphs; display level stays `'ordinal'` (calibration/policy.py:44) until a validated artifact exists.
4. Defaults never hide evidence of disagreement: contested rows sort first; `unchanged` and structurally proven `cosmetic` rows (UNCH/1, COS-ADDR/1, COS-LAYOUT/1) are collapsed by default with a visible count (U-03), one click shows them; COS-PSEUDO/1 rows are listed after `review`.

## 4. Read model (`read_model.py`, Qt-free; contract for the view)
```python
@dataclass(frozen=True, slots=True)
class SourceCell:  source: str; kind: Literal['value', 'pairs-elsewhere', 'no-record', 'not-run']; text: str; sort_key: int | None
@dataclass(frozen=True, slots=True)
class UnifiedRowView:
    row_id: str; function_label: str; address_label: str
    decision: Decision; decision_text: str; glyph: str
    materiality: Materiality; materiality_text: str; classes: tuple[str, ...]
    cells: tuple[SourceCell, ...]; ghidriff_match_id: str | None
    sort_keys: tuple[int, ...]       # (decision priority, severity rank 05 s2.6, attention order, rva) precomputed
    search_key: str                  # lowercased names + hex rvas, <= 512 chars
@dataclass(frozen=True)
class UnifiedViewModel:
    project_id: str; run_id: str | None; revision: int
    state: Literal['U0','U1','U2','U3','U4','U5','U6','U7','U8']; state_text: str
    sources: tuple[SourceInfo, ...]; rows: tuple[UnifiedRowView, ...]
    counts: Mapping[str, int]; warnings: tuple[str, ...]; stale_reason: str | None; display_level: str
def load_unified(req: UnifiedLoadRequest, cancel: Callable[[], bool]) -> UnifiedViewModel   # reads pointer row + verified parts
def filter_rows(rows, *, decisions, materialities, classes, sources, search) -> Sequence[int]   # indices, like evidence_view
def row_detail(vm, row) -> str            # plain text detail for the dock tab (fixed section headers)
def provenance_block(vm, rows) -> str     # deterministic, <= 16 KiB, banned-word clean
def explain_context(vm, row) -> ContextFragment   # for the existing context preview only (D-30)
```
Rules: every user-visible string passes `secondary.evidence_view.sanitize_text`; the banned-word sweep (`evidence_view.BANNED`, whitelisted negations) runs over every string the read model can produce (`test_unified_banned_strings_never_appear`); rows are built once, verbose text lazily; `load_unified` never raises for data problems (it returns U5/U6 with a reason).

## 6. Run, progress, cancel
`Run unified` is enabled only when a project is open, no Ghidriff job and no engine run is active (C-11), and the feature flag `unified/enabled` (QSettings, default OFF, D-20) is on; the reason is in the tooltip `Availability`. Stages shown: extract older, extract newer, ingest, match, change facts, decompile review pairs (S3b, U-11), publish; counts come from `progress.json` (03 s3) or are indeterminate. Cancel sets the shared event: children are killed with their tree; the previous result stays current; state returns to the previous one with "Cancelled; earlier results unchanged." Closing the window or switching project cancels and waits (`shutdown()`), no `terminate()`.

## 7. Filters, sorting, keyboard, persistence
Filters: decision (multi-select), change (default `material + review + not-applicable + unknown`), class, source present, search (debounced 150 ms; names, hex RVAs with or without `0x`). Keyboard: Up/Down/PageUp/PageDown/Home/End; Enter = show in code panes; Ctrl+C = copy provenance; Ctrl+Shift+U = toggle Primary/Unified (free on `cb25132`: MainWindow uses Ctrl+E/I/N/O/R/S, F1, F5; the dock uses Ctrl+Shift+E). The hidden `_worker` is hidden by registering it WITHOUT a `help=` argument (argparse prints `help=argparse.SUPPRESS` of a nested subparser as `==SUPPRESS==`, which C3's `_binexport-worker` still does in `secondary --help`; not touched here). `run` without `--no-extract` adds the warning `extraction is not available in this build; the result uses stored engine outputs only (no instruction-level facts)`. `run` options in S0b: `--no-extract` (S0 mode, the only mode), `--no-decompile` (accepted, no effect), `--sources` (comma list of ghidriff, bindiff, rz-diff, manual; default all; unknown -> exit 2), `--isolate` (default: worker child through `jobs.run_process` with C3's `worker_argv()`, the allow-listed `worker_env()` without the protobuf variable, L-42 memory cap and C3's OOM classification) or `--in-process`, `--timeout` (L-34, 60..86,400), `--fail-on-none` (exit 4 when no material or review row). ## 13. S4a notes (2026-10-14; the Qt-free read model and the `show` / `explain` polish)
Built: `unified/read_model.py` (view model, `load_unified`, states, default order and filter, columns, the owner-thread request) and `unified/read_text.py` (vocabulary, lazy validated records, detail / provenance / context text); `unified show` and `unified explain` now print what the Unified tab shows. Not built (S4b, after the GUI host exists): `ui_unified.py`, the `ui.py` seam, the dock tab, tooltip registration (the ids are data: `read_model.TOOLTIP_IDS`, `TOOLTIP_TEMPLATE_IDS`, `source_tooltip_ids()`), accessible names, threads and the Qt tests of s11. Tests: `tests/test_unified_read_model.py`, `tests/test_unified_cli_show.py`, builders in `tests/unified_read_support.py`.
1. Layers (deviation from the one file of s4 and 01 s2): `read_text.py` sits below `read_model.py` and holds everything that is words and plain text (decision / change / tier vocabulary, `atom_line`, `facts_lines`, `detail_text`, `provenance_block`, `context_fragment`, `ContextFragment`) plus `SidecarRecords`; `read_model.py` holds the view model and implements `row_detail`, `provenance_block` and `explain_context` of s4 on top. Neither imports Qt, `pipeline` (except the lazy import inside `request_from_service`), `jobs` or a network module.
2. Load flow. `request_from_service(service)` (OWNER thread, the only database access) returns the immutable `UnifiedLoadRequest` (project, run, revision, the `LoadedResult` of `pipeline.load_current`, the changed `result_key` inputs, an optional owner-side error, `extraction_configured`, an optional read-only `attention` map). `load_unified(req, cancel)` (any thread) reads only the verified parts through the strict `store` readers (facts first, then rows) and returns the model; it raises only `Cancelled`. A damaged, unreadable or newer result is state U5 with `<code>: <message> [<reason>]`. Rows are built once (about 750 bytes each, flyweights for identical cells, texts and sets) and sorted once. Measured on synthetic results with two atoms per row on a shared 4 vCPU box (load average 4.6-5.9): 3.4-4.7 s for 20,000 rows (2.4 s when the box was idle) and 17.6 s for 100,000 rows; a profile at 5,000 rows puts about two thirds in the store's strict validation (pydantic, JSON, the row-id check) and a fifth in the model's own row building. Loading is therefore a background job with progress and cancel (`progress_text`, the `cancel` callable), not part of the filter and sort budgets of L-35; the first-paint gate belongs to S4b.
3. States. U0 no project; U1 no result; U5 owner-side error, unusable pointer or any read problem; U6 stale (the reason names the changed `result_key` inputs, `STALE_REASONS`); U4 partial (reasons = the degrading limitations); U3 ready (the status line is the summary). Precedence U5 > U6 > U4 > U3. U7 is a notice, not a state: `banners` carries it when the result has no ProgramIR and extraction is not configured. `banners` lists every notice, highest first, so a stale partial result shows both. U2 and U8 come from the controller: `progress_text` / `progress_model` and `display_state(vm, shown)` (U8 above L-33 rows after filtering).
4. Row and model fields beyond s4: `UnifiedRowView` gains `change_text` (the Change column: "Material: constant"), `proof`, `tier`, `flags`, `source_ids`, `edit_group`, `collapsed`; `sort_keys` is the 6-tuple (group, library, trace-argument, severity, attention, rva). `SourceCell` gains `spoken`. `UnifiedViewModel` gains `result_id`, `manifest`, `banners`, `absent_sources`, `evidence_classes` (rows per evidence class, never a score; `evidence_summary(vm)` is its one line of text), `edit_groups`, `records` and `error`. `counts` keys: `rows`, `hidden`, `decision/<d>`, `change/<m>`. `explain_context` returns None when the records cannot be read; `ContextFragment` (which s4 names without defining) is a frozen record of kind, row id, title, text (at most 4,000 characters) and what was left out.
5. Cells. One cell per present source (registry order, then unknown ids sorted; D-08). The strongest atom of that source ON the row's pairing gives the value in the source's own words (Ghidriff the strongest match type, `+n` for the others; BinDiff `sim 0.97  algo <step>`; rz-diff `byte sim 0.88`; Diaphora category and ratio; pt-ladder / pt-bytes `P05 masked-exact (A)`; manual `correction`; an unknown id `<step> (<tier>)`). An atom that pairs one of the row's endpoints with another function is NOT on the pairing: with no on-pair atom the cell reads "pairs elsewhere", with both it reads the value plus "(also pairs elsewhere)", with none "no record". `sort_key` is that source's own similarity in milli units, or None; it is never compared across sources. The kind `not-run` is reserved and never produced (a source is a column only when it is an input of the result or contributed an atom).
6. Order (s7). Groups, first match wins: 0 contested, 1 material, 2 review, 3 cosmetic with COS-PSEUDO/1 (or no proof), 4 tentative / candidate / ambiguous, 5 one-sided, 6 matched without a change signal (S0 mode: most rows), 7 cosmetic with a structural proof, 8 unchanged. A contested row never leaves group 0, whatever its change. Inside a group: library rows after first-party rows (F16), trace-argument rows last (F17), then the severity list of 05 s2.6, then attention order, then RVA, then the row id. Reading choices where 05 is not exact: F17 says "sorts last inside its verdict" while 2.6 says "ties", the stronger reading is used (one index in `sort_keys` changes it); `unknown` ranks between `string` and `frame`, `layout-only` last; a `constant` delta whose instruction starts with cmp, test, and, or, shl, shr, sal, sar, rol, ror or a bit-test counts as "in a compare, test, mask or shift context" (the size-argument context needs call-site facts S3 does not yet provide). Columns can be re-sorted with `sort_rows(rows, indices, column_sort_key(vm, column), descending=...)`: stable, None last in both directions.
7. Default view and the U-03 count. `unchanged` and structurally proven `cosmetic` rows (UNCH/1, COS-ADDR/1, COS-LAYOUT/1) are `collapsed` and counted; COS-PSEUDO/1 rows are listed after `review`; only a matched, tentative or candidate row can collapse. The "default change filter material + review + not-applicable + unknown" of s7 is shorthand for "everything except the collapsed rows": `filter_rows(materialities=None)` is that default view, `show_collapsed=True` or an explicit materiality (which always lists its rows) lifts it. `decisions=None` and the other filters mean "no restriction", an empty collection means "nothing".
8. Edit groups (F10, view only). Rows with the same canonical semantic deltas (class, old text, new text) in at least three rows get a group id in display order; no row is merged, hidden or re-ranked (`filter_rows(edit_group=n)` lists a group, the detail says "may all be induced by one edit").
9. Lazy text. `row_detail`, `provenance_block` and `explain_context` read the records of the rows they are asked for from the sidecar in one pass over the part (raw lines, only the matching lines are parsed and checked against the row id); about 45 ms at 20,000 rows and 100 ms at 100,000 rows for one row, 56-85 ms for the 200 rows of a clipboard block. Call them off the GUI thread for large results. They never raise for data problems (a sentence says what could not be read). `SidecarRecords` currently uses the store's private line reader `store._lines` and `store._parse` so that the caps and the strictness stay in one place; a public alias is an integrator request.
10. Detail text sections (`read_text.SECTIONS`): Function, Decision (with the reason), Change, Support by component, Evidence classes (atoms per class: two atoms corroborate only across components AND classes), Contest, Atoms, Change facts, Limitations, Provenance, then the footer of s3.

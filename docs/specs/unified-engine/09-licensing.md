## 1. Reuse methods
- **Port with attribution**: we derive code from reading Apache-2.0 source. Obligations (Apache-2.0 s4): (a) give recipients a copy of the licence (`third_party/notices/bindiff-v8-<sha7>/LICENSE`, shipped in both builds); (b) each derived file carries a prominent notice that it was changed ("re-expressed in Python for PatchTrace, <date>"); (c) keep the copyright and attribution notices of the source files consulted ("Copyright 2011-20xx Google LLC" exactly as in the pinned files); (d) a NOTICE file would have to be reproduced, but none exists (R02 at `v8`, [own] at `main`), so (d) is void unless the pinned tag differs. s6: no trademark use ("BinDiff-style", never "BinDiff engine"). s3: the patent licence covers the Contributors' patent claims infringed by their Contributions "alone or by combination with the Work"; whether a re-expression is covered is a legal question, hence U-01 [inf; no patent review done].
- **Clean-room**: implemented from documentation, papers or observed behaviour only; no source of that project open while writing.
- **Runtime use**: we call a tool's API or CLI in a separate, user-installed process; nothing of it is distributed by PatchTrace.
- **Ideas only**: concepts named in research notes; neither code, SQL, tables nor thresholds copied; our own thresholds come from our evaluation (08).

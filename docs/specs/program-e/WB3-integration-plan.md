## 1. Verdict and scope
- Build a pure `patchtrace.strings` layer on the **already built** FLOSS adapter (the workbench spec's "not landed" is stale): compact per-side `StringTable`, settings-aware comparability, per-type delta, function links in tiers (L1, L4, L5 usable now; L2, L3, L6 when SPEC-31 IR or capa deliver), content cues and ordinal review tiers (no scores), advisory-anchor join, WB1 search rows, read-only CLI, one Strings tab in the single window.
- The value is the join, not the extraction (F4, F11): string <-> matched function pair, string <-> advisory/CVE text, imports (dynamic-API cue), build facts, rule seeds, series. FLOSS alone cannot say which function uses a static string (F5).
- FLOSS runs only through the shared `intel-tools` runner (one execution path), never automatically. Static strings need no emulation; stack/tight/decoded stay consent-gated emulation (F6) with time and memory caps. The target is never executed: it is data, copied read-only as `artifact.bin`.
- Recommended, owner decision Q1: also ship a ~100-line built-in byte scan that reproduces FLOSS 3.1.1 static semantics (F4). Reasons: the panel is otherwise empty on a fresh Windows install; the FLOSS bundle is 31.9 MB with an end-of-life CPython 3.8.10 (F8); it cannot be pip-installed wheels-only (F9). It is labelled "Built-in scan", never "FLOSS".
- Deliberately not built: Python FLOSS import, a second FLOSS parser, auto-download, JSON import (v1), the unreleased master/3.2 schema (F2), numeric scores, "fixed/vulnerable" wording, strings as a function matcher, FLOSS tags until released, graph drawing (a badge port only), any automatic run on project open.

**Charter check (roadmap s3)**: 1 pair-aware: link tiers, pair status, orientation on every record (S4, S5). 2 delta not inventory: Differences is the default scope; missing is `?` or not-compared, never a negative vote (7.1). 3 anchors in and out: section 4. 4 triage: review tiers R1-R7 with reasons; no score, no averaging with function attention, shared origin counted once (`lineage_group`). 5 one click to code: Open function with line reveal, Open in hex. 6 provenance: `StringBasis.parts` (tool pin, executable sha, options digest, consent hash, raw sha, artifact sha) and staleness through `WindowPort.key()`. 7 offline-first: the built-in scan needs nothing; FLOSS and emulation are optional with blocked states; nothing runs automatically. 8 teachable: `TEACH` hooks (section 7). 9 synergy test: `SYN-WB3-1`.

Workflows: W1 "which new messages does the patch add, and in which modified function?"; W2 "does the advisory wording occur in either build?"; W3 "which API names appear as strings but not as imports (possible dynamic resolution)?"; W4 "what changed in this function's strings?" (select a function, see added/removed/edited); W5 "was this string found by emulation?" (heuristic, absence is not evidence); W6 "give me the facts for a rule seed".

**Link tiers** (strongest first; shown as a label, never combined into a number). **L1 ghidra-xref**: Ghidriff `strings[].calling` names the function; the string joins FLOSS by RVA (Ghidra address minus the PE header ImageBase as `FunctionPairing` does; exact start, else unique containment); the name resolves only by the `evidence._related` rule (F19). **L2 ir-xref**: SPEC-31 IR `str` row (site RVA, function), after UE-S1. **L3 capa-feature**: CAP string-feature instruction RVA, only if CAP emits it. **L4 decompiled-literal**: each literal body in `FunctionRecord.code` is cut at every escape except `\t \\ \" \'` (FLOSS 3.1.1 ends a string at CR, LF and any other non-class byte, so `"bad header (%s)\n"` yields the segment `bad header (%s)`); a FLOSS value links when it equals a segment of the same width class (`L"..."` only with UTF-16LE); a segment ending in the TRUNCATED marker matches by prefix and is marked; text is compared in the escaped domain (F13), never unescaped. **L5 floss-frame**: stack/tight `function` VA equals a project function start. **L6 floss-call-site**: decoded `decoded_at` inside exactly one function range (needs IR ranges); `decoding_routine` is the decoder, never the consumer. No link is ever inferred from name similarity or by a model; an unlinked string stays unlinked.
**Edited pairs**: inside one modified function pair, a removed and an added string with difflib ratio >= 0.6 (mutual best, deterministic ties, at most 64x64 candidates) become one Edited row with a kind: `format-spec` (differences confined to `%` specifiers, for example `%s` -> `%.64s`), `case`, `digits`, `punctuation`, `wording`. A change of format precision is a review cue, not a verdict.

### 7.1 Basis rules (comparability)
| difference between sides | handling |
|---|---|
| source or FLOSS build differs, same static `semantics_id` | comparable on static; both sources shown; language and emulation types need the same executable sha |
| `min_length` differs | harmonized to the larger value (shorter strings dropped from both, as FLOSS's own reload filter does); banner says so |
| requested types differ | intersect; a type run on one side only is `not-compared`, never "removed" |
| language detection differs | `language` not compared; static unaffected |
| emulation on one side only, or different consent hash | emulation types not compared |
| a side truncated or a stage failed | statuses for that type become `?`/indeterminate |
| semantics id differs (future FLOSS or scanner change) | blocked with reasons and a re-scan action |
| artifact hash, run id, raw sha or orientation changed | `PT-STR-STALE`, nothing navigates |

### 7.2 Run cost, caching, provisioning, failures
- **Provisioning**: users fetch the pinned zip themselves (pins above) and choose the absolute executable path (never PATH; `PATCHTRACE_FLOSS`); PatchTrace never downloads or writes there (Q9). The setup row shows the expected zip and executable SHA-256, then a Probe that hashes the file and runs `--version` and `-H`. Pin status, in text: `pinned build`, `3.1.1 other build` (allowed with a banner), `untested 3.x` (allowed with a warning), `unsupported`, `not set up`. The executable is re-hashed before every run and a mismatch with the probe is `PT-TOOL-STALE`. Windows: Mark-of-the-Web, SmartScreen or AV may delay or block a downloaded onefile exe [unverified; owner machine]; extraction happens inside the run's private scratch `tmp` (not the user's temp), removed with retries (a killed run leaves `_MEI*` there, F10); FLOSS `return -1` appears as exit 255 on Linux and presumably as 0xFFFFFFFF on Windows (`exit_text` prints codes above 255 in hex; confirm on the Windows leg with a fake exe) [unverified]; stdout is ASCII (F3). Linux: same zip layout, member `floss`.
- **Cost**: built-in scan linear in file size (target >= 100 MB/s, measure in S3) [unverified]; FLOSS static about 1 s fixed plus size (F14) [real size unverified]; emulation seconds on tiny files, minutes on real ones [unverified]; two sides run sequentially (T-track default), the panel shows "n of 2", elapsed time and Cancel. Tables and deltas: budgets above. A series reuses the cached run of every shared middle build.
- **Caching**: raw run key = T-track `cache_key` (artifact, tool identity, options, contract); table and delta keys above; a hit is re-validated; an incomplete or failed run is never a hit; normalized content, not raw bytes, is compared (timestamps and timings differ, F3).
- **Failures** (run status / code; the user sees the code plus one sanitized line, never stderr, and "Earlier results were not changed"):
| outcome | status / code |
|---|---|
| spawn error / cancel / timeout / stdout over limit | failed `PT-TOOL-RUN` / cancelled `PT-TOOL-CANCEL` / timeout `PT-TOOL-TIMEOUT` / failed `PT-TOOL-LIMIT` |
| exit 255 with "not PE" text | unsupported `PT-TOOL-UNSUPPORTED` |
| emulation run on a file above 16 MiB (nothing printed, F5) | unsupported `PT-TOOL-LIMIT` with the `-L` consent path; the static baseline is a separate part and stays |
| memory cap hit | failed `PT-TOOL-LIMIT` "memory" (S1b classification) |
| exit 0, empty stdout | `none-found` for static only (F5) |
| invalid JSON, unknown keys, wrong version (a master build) | failed `PT-TOOL-OUTPUT` |
| artifact changed or hash differs | failed `PT-TOOL-ARTIFACT` |

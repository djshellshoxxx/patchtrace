## 1. Verdict and scope
- **Build**: a small pure `kev/1` package plus one dock in the main window. Consented whole-catalog fetch (about 1.8 MB; no CVE ID or KB is ever sent), file import, content-addressed offline snapshots with SHA-256 and explicit staleness, an exact-wording CVE join, snapshot delta, a project-attached `kev-context` row and report block, and shared badge/filter/sort/detail widgets that the KB/CVE result views embed.
- **KEV is CVE-level context in its own lane.** It is never added to `attention/1` or `ContextualRanking`, never shown on a function row, never averaged with MSRC, SSVC, NVD or engine values. Its only ranking use is an opt-in, explained CVE reading order ("KEV-listed first", stable).
- **Do not build**: a catalog browser (standalone duplicate), a bundled catalog (section 7), CSV import (no release metadata), KEV text in the CWE lexicon or hypothesis rules (shared origin), EPSS, NVD `cisa*`/SSVC lanes (evaluated in section 3, deferred), auto-refresh, auto-delete, any numeric score.
- **Design drivers measured today**: 1,741 entries, 12 fields of which 4 optional; `forensicTriage` and BOD 26-04 wording are new (2026-06); no Microsoft entry names a KB, so the CVE ID is the only join key; 86% of Microsoft entries added since 2024 carry no CWE that a B1 detector covers, so the UI must abstain explicitly.
- **Biggest risks**: the canonical `www.cisa.gov` feed URL could not be verified from this sandbox (gate K6); the KB/CVE views are not built yet, so the dock ships first and KB integration is a port plus shared widgets.

## 3. Standalone baseline versus PatchTrace value
**Alone** (CISA page and feeds): a filterable list of all 1,741 entries, JSON/CSV/schema downloads, the 12 fields. It knows nothing about KBs, builds, files, functions, a project, orientation or what you already examined, and cannot answer "which CVEs of this KB are listed".
**Inside PatchTrace** (workflows this enables):
- **W1 Patch Tuesday triage.** KB -> CVE edges come from MSRC/CSAF; KEV supplies status by CVE ID; the KB view marks listed CVEs, offers the opt-in reading order, and shows under each CVE its expected-change hypotheses and candidate functions. KEV decides which CVE to read first; the engines decide where in the code.
- **W2 N-day timeline.** "Added to KEV 1 day before the update was released" from the KB `released_at`, only when the pair orientation is verified. Standalone KEV cannot produce it.
- **W3 Catalog delta.** After a refresh: "7 new, 1 changed, 0 removed since catalog 2026.10.06" (a changed line can read "Known ransomware campaign use was Unknown, now Known"); projects whose recorded context differs show "KEV data changed since recorded" (not listed -> listed is the headline).
- **W4 Air-gapped.** Import file plus explicit age; the same views and wording.
- **W5 Honest abstention.** For a listed CVE whose CWE has no B1 detector the panel says an empty candidate list is unknown, not negative.
- **W6 Reproducible report.** As-of KEV block (snapshot id, SHA-256, dates) in exports.

**Charter check**: 1 pair-aware via KB edge plus verified orientation (timeline only); 2 delta = snapshot delta and the time relation (KEV is not a code delta, by design); 3 CVE anchor in and out; 4 CVE reading order only, never a function score; 5 delegated: KEV is context, not a finding, so its action is a signal to the KB/PIL views, which own the one click to code; 6 provenance and staleness everywhere; 7 offline-first, per-operation consent; 8 `kev/teach.py` hooks (section 4); 9 section 5.

**Evaluation of EPSS and extra NVD fields (recommend, do not build)**
| candidate | value | noise or risk | verdict |
|---|---|---|---|
| EPSS | prediction of exploitation activity; could order large non-KEV sets | answers a different question than KEV (prediction versus present state, F16); a daily-changing probability invites false precision; second network source; no meaning at function level; KB sets are small (tens of CVEs) | Defer. If ever built: separate lane, percentile plus date, never default sort, never combined |
| NVD `cisa*` fields | same facts as KEV | derived copy (shared origin), lags, no ransomware flag, adding them changes `NORMALIZATION_VERSION` and every snapshot id | Do not add |
| NVD `ssvcV203` (CISA SSVC, already in fetched bodies, F17) | Exploitation none/poc/active for CVEs outside KEV; "poc" helps n-day work | only CISA-enriched CVEs; time-stamped analysis; "active" is KEV echoed (F15); invites over-reading | Later optional lane read from bodies already fetched (no new consent), shown verbatim with its date, never merged with KEV |

## 7. Contracts
Package `src/patchtrace/kev/` (pure: no Qt; sqlite only in K5). Records are strict, frozen, `extra='forbid'`, `contract: Literal['kev/1']`; identity through `enrichment.identity.domain_id`. The input parser is a hand-written tolerant mapper (unknown fields reported, not fatal); stored models are strict.
| model | fields |

- **Errors** `PT-KEV-{INPUT,CONSENT,NETWORK,PROVIDER,LIMIT,FORMAT,VALIDATE,SHRINK,STORAGE,UNSUPPORTED,NOTFOUND,CANCEL}` as `KevError(code, message, recoverable)`, messages redacted. Exit codes: INPUT, CONSENT, UNSUPPORTED -> 2; NETWORK, PROVIDER, LIMIT, FORMAT, VALIDATE, SHRINK, STORAGE -> 3; NOTFOUND (no catalog) -> 4; CANCEL -> 5.
- **Limits**: download and import 16 MiB (9.4x today, about 59 years of growth at 250 entries per year); 20,000 entries; connect 10 s, request 60 s, plan 120 s; 3 attempts on 429/502/503/504, Retry-After at most 60 s; 2 same-host redirects; 5,000 CVEs per lookup, 256 per project row (row at most 256 KiB); freshness fresh <= 3 d, aging 4-14 d, stale >= 15 d (about 12 new entries per 14 days, F6); parse plus validate ceiling 1.0 s on CI (target 0.2 s).
- **Transport** (`kev/transport.py`, shape of `intelligence/csaf/transport.py`): `KevConsent(urls)` built only from a displayed `KevPlan`; `check_url` admits the two fixed URLs (`cisa-site` per F11; `cisa-github` = `https://raw.githubusercontent.com/cisagov/kev-data/main/known_exploited_vulnerabilities.json`, verified F1/F12) and same-host https/443 redirects without userinfo or query; injectable `opener(url, headers, timeout)`, clock, sleep, now and cancel; reuses `netutil.interruptible`, `Cancelled`, `TooManyAbandoned`; environment proxies ignored; request announced before it is sent; one GET per fetch, so no NVD-style pacing; 64 KiB chunks under the 16 MiB cap and a deadline; fixed headers `Accept: application/json`, `User-Agent: PatchTrace` (no browser spoofing); no conditional GET (1.8 MB); returns `Fetched(url, final_url, body, sha256, retrieved_at)`. Operation-specific consent: one fetch, one consent, nothing remembered. Parsing happens only afterwards in `service`.
- **Store** (outside the project and git): `<kev dir>/snapshots/<raw_sha256>.json.gz` (decompressed bytes hash to the name; decompress capped at 16 MiB), `meta/<snapshot_id>.json`, `current.json` {snapshot_id, raw_sha256, date_released, set_at}. Install order snapshot, meta, pointer, each tmp + fsync + `os.replace` with a 3-step retry for Windows sharing violations. Damaged pointer or file -> fall back to the newest valid snapshot and say so. Never replace `current` with an older `date_released`. Deletion only by `kev prune --keep N --yes`; warn above 256 MiB.
- **Bundling decision: do not bundle.** A shipped catalog is stale from the day it is built and invites reading "Not listed" as current; embedding it couples release builds to a third-party fetch (a build must never fail on it); import already serves air-gapped analysts; CC0 (F8) makes bundling legal, so this is reversible. If wanted later: an optional build step that never fails the build, labelled "bundled", aging immediately.
- **Project**: enrichment-store kind `kev-context` (small JSON row, no sidecar, not in `DERIVED_KINDS`), guard = Guard(project_id, "", "", domain_id of cves plus snapshot_id); published on the owner thread through `EnrichmentStore.publish`, like every other row; stale when the loaded snapshot has different facts for a recorded CVE.
- **Cache and identity keys**: snapshot_id and content_digest as above; in-memory lookup key domain_id("kev-lookup", 1, {content_digest, sorted cves, join_version}); context_id as above. Wall-clock time is never an input.
- **Versioning**: additive only; new upstream fields land in `unknown_fields` until promoted to optional fields with defaults; `kev/1` never changes meaning.

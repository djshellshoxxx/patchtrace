Status: research plan, documents only. Date 2026-10-14. Base: `prep/program-e` d972125 (this worktree was fast-forwarded from 1560531, which predates the brief and roadmap). Card WBQ. Spec under review: `docs/specs/workbench/04-quickwins.md` (QW3, QW4, QW6, QW8). QW5 (QCompleter) belongs to WB1 and QW7 (DOT) to WB2: neither is planned here.

The scratch scripts behind the numbers are not delivered (one-file rule); every measurement below states its input so the owning slice can re-run it as a test.

## 1. Verdict and scope
1. **Build**, in this order: (a) stdlib PE metadata readers inside `pe_overview` (resource tree, VERSIONINFO, manifest, Rich header, export RVAs, import API delta) with old/new deltas; (b) a pure `codetext` package: in-house tokenizers using the unified engine's operand vocabulary, a windowed `QSyntaxHighlighter`, and address-masked token marks that are lexical hints, never proof; (c) a pure `symbols` decoration parser giving "same qualified name, different decoration" signature facts, with native readable names only behind process isolation.
2. **Decided against, with measurements (section 2):** pefile and Pygments as runtime dependencies (both stay dev-only test oracles); imphash (replaced by an import API delta); any change to `alignment.py` (shared with SPEC-07 ranking); in-process native demangling (a 121-character name makes LLVM's demangler emit 122 MiB); Rich-header product or Visual Studio names (undocumented format, unlicensed community tables).
3. **Dormant until data exists:** assembly token diff. Ghidriff persists only `hash(tuple(instructions))`, so `FunctionRecord.assembly` is usually None; text arrives with SPEC-31 S1 (`insns.text`) or a PatchTrace-owned launcher. The decompiled-C path has real data today.
4. **Value rule:** every output is old/new aware, source-labelled, plain text, and marked either lexical (display) or observed (fact). Nothing here says "fixed", "cosmetic" or "vulnerable".
5. **Looks valuable, fails the charter:** generic Pygments colouring and imphash (standalone duplicates), Rich role or Visual Studio names (false precision, unlicensed table), "address-only means cosmetic" (false precision), matching functions by demangled name (false identity), an assembly diff before assembly text exists (no data).

## 3. Standalone baseline versus PatchTrace value
| feature | tool alone | PatchTrace context adds | workflow it enables |
|---|---|---|---|
| Code colours | Pygments: generic C and assembly colours | classes follow unified `vkind` and Ghidra auto-names, so colour means the same in panes, evidence panel and reports; address-derived names muted; text alternative for screen readers | read a 5,000-line function and see which tokens are registers, constants or addresses |
| Token marks | difflib: character or token diff | address-masked (cosmetic shifts muted, `FUN_` targets resolved through the run's matched pairs), decompiler-temp renames kept apart from real edits, similarity gate, one-line summary | step through only real token changes (F8) instead of every shifted line |
| Version, manifest, Rich | pefile dump of one file | verified bytes, old/new by (language, key), contradictory blocks kept, toolchain delta tagged shared-origin with DiE, file version joins KB/Winbindex and CSAF identity | "linker build 33134 -> 36248, expect cosmetic noise"; "requested elevation changed" |
| Import API delta | none (imphash is one hash) | per-DLL added or removed names, joined to WB2 callee deltas by exact name | "this modified function now calls a newly imported API" |
| Export signature facts | undname: string to string | same qualified name, different decoration tail across builds, with export RVA for navigation | "exported function widened `unsigned long` to `unsigned __int64`" |
| Readable names | undname, c++filt | search aliases (WB1) and graph labels (WB2); the mangled original stays the identity; backend and version recorded | search `ParsePacket`, land on the exact function |

Already extracted by `pe_overview` (do not duplicate): headers, sections and entropy, DLL and function import names (ordinals as `#N`), export names, overlay, certificate table, RSDS, packer hints, resource directory presence only. New: resource tree, VERSIONINFO, manifest, Rich, export RVAs/ordinals/forwarders, API delta. `csaf/identity.py::read_version_info` is a second private walker; it stays untouched in the first slices and moves onto the shared reader later (amendment 7).

Existing diff code inspected (the card's first instruction): `alignment.py` runs `SequenceMatcher` over whole lines (exact up to 2,000 lines, popularity filter above, prefix/suffix only above 10,000) and returns `DiffHunk` ranges; `ui.render_match` pads replace hunks positionally and paints one full-width `ExtraSelection` per hunk (`_highlight_hunks`); `enrichment/views.py` also calls `diff_hunks`, and `enrichment/pipeline.py:75-81` folds the `alignment` module's constants into the pinned `signals` stage digest (`tests/fixtures/algorithm_digests.json`): a new constant there invalidates derived caches and fails `test_algorithm_digests.py`, and a behaviour change would silently change SPEC-07 signals. Nothing below line level exists. Decision: an intraline overlay is needed, because address shifts turn every touched line into a replace hunk (section 5: 4 hunks where 2 are real), and it is built as a consumer of the displayed rows; `alignment.py` stays untouched.

**Corrections to `04-quickwins.md` (wrong or thin):**
- QW4 builds `pe_overview/version_resources.py` on pefile: contradicts the stdlib-only `pe-overview.md` and `test_package_has_no_qt_or_third_party_pe_imports`; pefile's hostile cost is unbounded in practice (section 2). Its depth cap of 32 is pefile's, Windows uses three levels. It never says DOCTYPE must be rejected before parsing.
- QW3 caps highlighting at 64,000 characters but the panes allow `MAX_VIEW_CHARS = 200_000`, so larger functions would lose colours exactly where they matter; Pygments speed was never measured (0.69 MB/s) and its assembly lexers are not operand-aware (`ptr` becomes a variable); the PyInstaller hook ships all 263 lexers.
- QW6 pairs lines "from existing hunks" but rows inside a replace hunk are paired by position, so an inserted line pairs unrelated lines (measured: similarity 0.62 and 0.71 still produced misleading marks). A masked-token similarity gate is required.
- QW8 omits that the native demangler is exponential on a 121-character name (section 2) and that dbghelp is single-threaded and version-dependent.
- QW3 and QW6 omit that assembly text is usually absent, so their assembly paths have no data today.

Lead candidates for FAB (labelled facts, never vulnerability claims, no scores from WBQ): exported signature changed; modified function calls a newly imported API; manifest elevation or supportedOS changed; embedded PE resource added. "Toolchain build changed" is a noise attribution that demotes address-only differences, not a lead.
Teach hooks (E-5): every fact carries a `teach_id` (`wbq.version.changed`, `wbq.rich.toolchain`, `wbq.manifest.elevation`, `wbq.api.added`, `wbq.signature.changed`, `wbq.mark.address_only`) with two English default strings (what it means, what to check next). Example for `wbq.mark.address_only`: "This value differs only because code moved; the target was not checked." / "Open the evidence panel and see whether the engines pair the two callees."

## 5. Synergy test (SYN-WBQ-1, synthetic, no Microsoft binaries)
Builders: `tests/pe_rsrc_builder.py` (new `.rsrc` writer over `pe_builder.build_pe_ex`), `rich_header()` from `tests/test_intel_tools_pe.py`, committed LF fixtures `tests/fixtures/wbq/syn1_{old,new}.c.txt`. Older -> newer: file version 10.0.19041.1 -> .2; manifest gains `longPathAware`; Rich linker build 33134 -> 36248; import `ntdll.dll!RtlULongAdd` added; export `?ParsePacket@CParser@@QEAAJPEBEK@Z` -> `...PEBE_K@Z`. The 14/15-line decompiled body shifts every `FUN_`/`DAT_` name by +0x40, renumbers `uVarN`/`lVarN`, changes `param_2 < 0x20` to `0x40`, and inserts `RtlULongAdd(param_2,0x10,&param_2);`.

The other 7 rows are identical.

## 6. Traps and guards
| trap | guard |
|---|---|
| "address-only" read as "cosmetic" or "unchanged" (false precision) | masked only: auto-names and numeric operands with positive address evidence (image range, RIP base, branch target); always drawn, never hidden; wording "address-only difference, target not verified"; `TargetOracle` returns mapped, unmapped or conflict from matched pairs and a conflict is a `callee` change; no proof words |
| mispaired rows (the display pairs by position; an inserted line inside a replace hunk) | masked-token similarity gate 0.8, else "paired by position only"; marks never computed across hunk edges |
| decompiler temp renumbering versus a real variable swap | `rename-maybe` (dashed underline), counted separately, upgraded only by a `canon/1` oracle |
| named symbols (`CreateFileW`, `strcpy`) differing | never masked: a real callee change |
| assembly absent (hash only) | feature dormant; the existing "[Assembly unavailable ...]" text stays; no fabricated disassembly |
| colour as the only carrier | changed = bold + yellow single underline; address-only = italic + dotted; rename = dashed; plus a text "Line changes" label, because Qt's UIA provider exposes none of the formatting |
| highlight freeze on large functions | windowed highlighter, constant block state, never `rehighlight()`, token work only for the window |
| hostile code text (bidi controls, zero-width characters, U+2028, U+0085, U+000B) | `ShowDefaultIgnorables` on code panes, per-line note "contains N bidirectional control characters", plain text only; row model must equal document blocks (`splitlines` versus Qt rules tested) |
| stale marks after Swap orientation, mode switch, project change | model replaced and window set BEFORE `setPlainText`; generation counter |
| pefile or Pygments DoS, size, licence | not runtime dependencies; dev oracles guarded by `importorskip` |
| hostile resource trees (cycles, shared DAGs, 4,096-entry fans, huge names, giant `Size`) | iterative walk with a global visited set, 20,000-node and depth-4 caps, name cap, reads clipped by the section map, 2 s monotonic budget, `cancel` polled per directory |
| packed or stub PEs (`packer_hints`) | resource facts labelled "file may be packed; these describe the stub"; absent resources are unknown, not removed |
| API delta read as "every API the binary uses" | wording "static import table only": delay-load and bound imports are not parsed by `pe_overview` and runtime-resolved APIs are invisible (FLOSS and capa cover those); unreadable imports make the delta `unavailable`, not empty |
| VERSIONINFO trust | a file version describes the file, not the Windows build or authenticity; all blocks kept; contradictions listed; primary block = lowest name then language (parity with CSAF identity) |
| Rich header: forgeable, strippable, absent for lld and GNU ld, shared origin with DiE, role names unverified | raw `(prodid, build, count)`, checksum flag, no role names; absent is unknown (never a toolchain-change vote); counted once with DiE |
| manifest XML | reject any `<!DOCTYPE` or `<!ENTITY` (UTF-8 and UTF-16) before parsing, 2 MiB cap, one-shot parse, no schema, no network |
| export to function mapping when Ghidra rebased the image | map only when the PE image base equals the Ghidriff address base (the SPEC-31 IR design refuses `image-base-mismatch` the same way, `03-extraction.md` s5); otherwise unknown |
| demangler blow-up or crash | never in-process on untrusted names; worker with 1 GiB cap, 5 s timeout, 3 restarts, culprit skipped; display capped at 1,024 chars and treated as untrusted text (string-literal symbols decode to arbitrary text) |
| demangled name used as identity or compared across backends | identity is the original; `(backend, version, norm)` stored; old and new displays compared only when equal, else "not comparable" |
| LLVM accepts trailing garbage (`nUsed` unchecked in the wrapper) | pre-filter: known prefix, charset, length <= 512; `__imp_`, `@ILT+n(...)` and `@N` suffixes stripped by our code |
| signature deltas caused by an STL or toolset bump | annotate with the Rich or DiE toolchain flag: "decoration differs; toolchain also changed" |
| dbghelp: single-threaded, version-dependent, not redistributable | opt-in Windows backend, global lock, System32-only load, labelled `dbghelp <file version>` |
| UI deception from file-derived strings | `PlainLabel`, `template()` escaping, plain `QTableWidgetItem` text, 200-char caps |

## 7. Contracts
Pure parsers keep the `pe_overview` style: frozen slotted dataclasses, no Pydantic import. Records that cross tracks (`BuildFact`, `ApiChange`, `SignatureChange`) become Pydantic v2 strict frozen models once the FAB contract exists; their field lists here are its input. Additive only: new optional `PeOverview` fields default to `None`, `ExportsInfo.entries` defaults to `()`, new comparison rows are appended after the existing ones. Contract names: `pe-meta/1` (CLI result), `codetext/1`, `sym-norm/1`, `sym-display/1`.
- `ResourceLimits`: `max_nodes=20_000`, `max_depth=4`, `max_dir_entries=4_096`, `max_name_chars=256`, `max_version_bytes=65_536` (at most 16 blocks), `max_manifest_bytes=2_097_152`, `max_hash_bytes=16_777_216` in total, `max_rich_entries=256`, `max_exports=20_000`, `time_budget_s=2.0` (`time.monotonic()`, compared with `>=`).
- `ResourceLeaf(type_id, type_label, name, lang, rva, size, codepage, offset|None)`; `ResourceInventory(leaves, by_type[(type_label, count, bytes)], embedded_pe (MZ sniff), truncated)`.
- `FixedFileInfo(file_version, product_version, flags_mask, flags, os, type, subtype)`; `VersionString(lang_codepage, key, value, truncated)`; `VersionBlock(leaf, fixed|None, strings, translations, status, warnings)`; `VersionInfoSet(blocks, primary_index|None, contradictions)`.
- `AssemblyIdentity(name, version, arch, token, type)`; `ManifestObservation(leaf, sha256, execution_level, ui_access, supported_os (sorted GUIDs), dpi_awareness, long_path_aware, active_code_page, identity, dependencies, files(name, hash, hashalg), warnings)`.
- `RichEntry(prodid, build, count)`; `RichHeader(key, entries, start, end, checksum_ok|None, clear_sha256, warnings)`; `ExportEntry(name|None, ordinal, rva|None, forwarder|None)`; `ApiChange(dll, name, kind: name|ordinal, change: added|removed)`, computed in compare and invalid when either side's imports are `truncated`.
- `BuildFact(kind, side, artifact_sha256, key, value, origin_family, assessment='observation', teach_id, provenance, pointer)`.
- `codetext`: `Token(kind, start, end)` with kinds `ws comment string char number keyword type auto_name temp ident op mnemonic register size symbol punct other`; `OperandClass = address|stack|memory|scalar|register` (identical strings to unified `vkind`); `Mark(side, start, end, state: changed|address-only|rename-maybe, label)` where `label` is a unified `ChangeClass` value or `token` (a test asserts the subset); `RowMarks(row, old, new, similarity, gated, summary)`; `FormatSpan(start, length, style_key)`. Protocols: `OperandSource`, `TargetOracle` (`NullOracle`, `MatchPairOracle`), `RenameOracle`.
- Text-path operand rules (positive evidence only, as in unified `03-extraction.md` s6): `address` = a Ghidra auto-name (`(EXT_)?(thunk_)?(FUN|SUB|LAB|DAT|UNK|OFF|PTR|BYTE|WORD|DWORD|QWORD|ADDR)_<4-16 hex>`), a number inside `[image_base, image_base + size_of_image)`, a direct call or branch target, or a RIP-relative displacement; `stack` = displacement in a memory operand whose base is RSP, RBP, ESP or EBP; `memory` = any other bracketed displacement; `scalar` = any other number; `register` = registers; a named operand (`->KERNEL32.DLL::CreateFileW`, plain identifiers) is `symbol` and never masked. Decompiler temps for `rename-maybe`: `[a-z]{1,3}Var<n>`, `local_<hex>`, `param_<n>`, `in_<REG>`, `extraout_*`, `unaff_*`, `*Stack_<hex>` (the `canon/1` examples in unified `05-fusion-and-noise.md` s2.4).
- `symbols`: `Decoration(kind: msvc|itanium|rust|rtti|string-literal|plain, original, qualified_name|None, tail|None, complex)`; `DisplayName(original, display|None, backend, backend_version, status: demangled|unchanged|invalid|rejected|timeout|unavailable, truncated)`; `SignatureChange(qualified_name, old_tail, new_tail, old_display|None, new_display|None, toolchain_changed|None)`.
- Decoration rules (S10; pure, bounded to 512 bytes, never raises): strip `__imp_`, `@ILT+n(...)` wrappers and a trailing `@N`; kind by prefix (`?` msvc, `_Z` itanium, `_R` or `..17h<16 hex>E` rust, `.?AV` or `.?AU` rtti, `??_C@_` string-literal, else plain).
- For msvc, the components are the `@`-separated names up to the first `@@` (reversed they are the scope chain) and `tail` is everything after that `@@`. Any component starting with `?$` or `??` (templates, operators other than `??0` and `??1`) sets `complex=True` and no qualified name is derived. Rust legacy displays keep a per-build `::h<16 hex>` suffix, which is stripped from comparison keys only.
- Known answers (from the verified run): `?x@@3HA` -> `int x`; `?ParsePacket@CParser@@QEAAJPEBEK@Z` -> `public: long __cdecl CParser::ParsePacket(unsigned char const *, unsigned long)` with qualified name `CParser::ParsePacket` and tail `QEAAJPEBEK@Z`; `??0CFoo@@QEAA@XZ` -> `public: __cdecl CFoo::CFoo(void)`; `??_7Foo@@6B@` -> ``const Foo::`vftable'``; `.?AVFoo@@` -> ``class Foo `RTTI Type Descriptor Name'``; `?f@@YAXP6AXH@Z@Z` -> `void __cdecl f(void (__cdecl *)(int))`; `_ZN3Foo3BarEi` -> `Foo::Bar(int)`; `__imp_?Foo@@YAXXZ` and `@ILT+1005(?f@@YAXXZ)` return `""` until our wrapper strips the prefix.
- Warning codes (lowercase, as in `pe_overview`): `resource_dir_unreadable`, `resource_depth_over_cap`, `resource_nodes_over_cap`, `resource_cycle_skipped`, `resource_name_truncated`, `version_block_malformed`, `version_over_cap`, `version_key_mismatch`, `manifest_dtd_rejected`, `manifest_over_cap`, `manifest_encoding_unsupported`, `manifest_xml_invalid`, `rich_malformed`, `rich_checksum_mismatch`, `export_table_over_cap`, `metadata_time_budget`, `internal_error_<stage>`.
- Error codes: `PT-PEMETA-INPUT`, `PT-PEMETA-SOURCE` (wraps `ArtifactBytesError.code`), `PT-PEMETA-CANCEL`, `PT-SYM-BACKEND`, `PT-SYM-WORKER`, `PT-SYM-LIMIT`, `PT-CODETEXT-LIMIT` (GUI status only).
- Storage: no new enrichment-store kind and no project write in v1 (metadata costs under 5 ms and is recomputed from verified bytes; results carry the artifact SHA and `parser_version='pemeta/1'`). Readable names: `DerivedCache` stage `sym-display` (valid under the `[a-z][a-z0-9-]{0,31}` rule), key `sha256(canonical_json({contract, backend, backend_version, norm, names_sha256}))` with `names_sha256` over the sorted unique originals; disposable.
- Other limits: tokenizer line 4,096 chars, 256 tokens per marked pair, window <= 400 blocks, 200 pairs per refresh, similarity gate 0.8, LRU 4,096 lines. Symbols: input <= 512 bytes (the existing name cap), batch <= 100,000 unique, worker memory 1 GiB, 5 s per batch, 3 restarts, display <= 1,024 chars.

## 8. CLI and GUI
**CLI** (logic in top-level `cli_pe_meta.py`, 6-line hook in `cli.py`, hidden worker like `_binexport-worker`): `patchtrace pe-meta PROJECT [--json] [--side older|newer|both] [--facts version,manifest,rich,resources,imports,exports] [--names plain|decoded]` prints a `pe-meta/1` result in the `enrichment-cli/1` envelope (per-side facts plus the delta). Exit 0 for ok, and for `status: partial` with the warnings listed (a limit truncated a fact; same as `correlate`); 2 invalid input; 3 when either side fails byte verification or a stage crashes (same as `series create` with failed pairs); 4 only when neither side is a PE; 5 cancelled. `--names decoded` needs the optional worker (status `unavailable` otherwise; exit code unchanged). The hidden `_demangle-worker` reads a request file and appends `jsonl` results, because `jobs.run_process` gives the child no stdin.

**Highlighter architecture** (existing two `QPlainTextEdit` views in `MainWindow._build_code`; no new window or dock). Measured at 6.5k / 65k lines (the 65k case exceeds the 50k-line stress target):
| option | cost | verdict |
|---|---|---|
| full `QSyntaxHighlighter` | `setPlainText` +99 ms / +1,046 ms (synchronous, freezes the GUI) | rejected |
| windowed `QSyntaxHighlighter` | +11 ms / +150 ms (empty-callback crossing, about 1.1 us per block); 4.5 / 7.9 ms to re-format 121 blocks on a scroll jump | **chosen** |
| ExtraSelections for syntax | 19 / 15 ms per scroll for 80 lines; `setExtraSelections` replaces the whole list and would fight hunks and WB1 hits | rejected |
| custom item delegate | panes are documents, not item views; a rewrite loses selection, caret, `centerCursor`, copy | rejected (a `QAbstractScrollArea` painter is the fallback for a future 500k-line view) |
| worker-thread tokenizing | not needed at 5.9 MB/s with lazy windows | rejected |
- Mechanics: `CodeHighlighter(QSyntaxHighlighter)` is created once per pane in `_build_code` and parented to the document (a Python-only reference can be collected and abort the process; attaching to a non-empty document queues a one-off full rehighlight, `qsyntaxhighlighter.cpp:307-311`); block state is always `-1` (a state change cascades through every following block); per-block formats come from a pure `CodeTextModel`; window = visible blocks +/- 80, refreshed on `verticalScrollBar().valueChanged` with `rehighlightBlock` for the window only; model and window are installed BEFORE `setPlainText`; merged `QTextCharFormat` objects (syntax x mark state) are cached per theme because `setFormat` replaces. Existing `_highlight_hunks` ExtraSelections stay (composite measured above); hunks and WB1 hits go through one `compose_selections()`.
- Language by mode: 0 -> C-like, 1 -> assembly, 2 and raw modes 3-5 -> none. Function header rows (`// name · address`, located through `_function_offsets` and then `_line_maps` to the padded row) and the truncation notice use a `chrome` style. `MAX_VIEW_CHARS = 200_000` stays; lines over 4,096 chars stay plain.
- Multi-line `/* ... */` state comes from one linear regex pass per text (about 3 ms per 290k chars), not from Qt block state.

**Theme, contrast, colour-blind safety.** `Palette('dark')` is bound to `DARK_STYLE` (base `#10151c`; replace hunk `#263a43`; insert/delete `#33392b`).
- Text colours with contrast on the base: text `#D9E1EC` 13.9; keyword/type `#56B4E9` 7.9; number/scalar `#E9A93A` 8.9; string/char `#4FD1A5` 9.6; comment `#93A7BD` italic 7.4 (4.81 on the replace hunk, the minimum); address and auto-name `#E08FBF` 7.7; register `#7CC4F0` 9.6; stack/frame `#6FD8B4` 10.6; named symbol `#F0E442` 13.9; size keyword `#A9B8C9`; decompiler temp `#C7D2E0`; mnemonic bold text.
- Marks: changed = bold + single underline `#F0E442` (8.98:1 on hunks, WCAG 1.4.11); address-only = italic + dotted `#93A7BD`; rename-maybe = dashed `#93A7BD`. No background tint: a tint is 1.33:1 against the hunk and pushes class colours below 4.5:1.
- Colour-blind check (CIEDE2000, Machado 2009): scalar versus address >= 35.6 under protan and deutan, 8.4 under tritan; register versus address >= 10.3. No class depends on colour alone (lexical form plus underline styles).
- A light palette (`#1B2733`, `#005A8C`, `#8A5A00`, `#00694C`, `#4D6075`, `#9B2F6C`, `#00598A`, `#6B5D00`; >= 4.70:1 on white and light hunks) is computed but inactive until the app has a light theme.
- Runtime guard: a colour below 4.5:1 against the live `QPalette.Base` or hunk colour falls back to the default text colour. "No syntax colours" sets `QTextOption.Flag.SuppressColors`; underline, bold and italic survive. Forced-colour or high-contrast support is app-wide and out of scope, but the guard keeps WBQ from making it worse.

**Controls (no new top-level UI).**

## 1. Verdict and scope
- **Build** (six deliverables): (1) finish SPEC-32 into a runnable Tier R corpus: 14 recipes (zlib exists, 13 new) in 3 tranches (+7 reserve), 25 mutation operators in 3 layers, A/A and nuisance controls, a pinned MSVC Windows leg, CLI, nightly workflow; (2) one shared evaluation core `tools/calibration/evalcore` that scores rz-diff, Ghidriff, BinDiff, `attention/1` and the unified engine against labels (per-label, "which changed function is the fix" rank metrics, lineage bootstrap, native-score curves, shift/OOD) and is reused by Tier W; (3) a Tier R training run that ends at G1 plus an `experimental` artifact; (4) honest scope: additive artifact fields, `validation-ledger/1`, a status line and "Evidence limits" in the Evidence dock and in reports; (5) the owner's one-command Tier W runner; (6) label packs for strings, capabilities, build environment, rules.
- **Verdict on numbers**: Tier R alone can never lift `display_level()` above `ordinal` (`gates.G0_MIN` needs >= 6 Tier W families spanning kernel, driver, user-mode DLL). With the owner defaults (O1 local-only, O2 no second annotator, O4 no budget) the ceiling is L1 bands, reachable only if the owner personally completes a ~150-item audit and a test-retest (8.5); L2 is unreachable (G3 needs a second annotator). The product value is measured and gated claims, regression gates for the unified engine and the channels, and UI text that says what was and was not tested.
- **Not building**: any percent or probability display; learned lead-list weights (about 20 real-fix cards in 13 lineages); a labelling campaign or HTML labelling front-end; universalmutator or Mull as dependencies; a C++ LLVM pass plugin; a C++/WDK Tier R tranche (deferred, section 11); anything Microsoft-derived in git or CI.

## 3. Standalone baseline versus PatchTrace value
- **Standalone**: BinKit/TikNib (ELF, MIT scripts, data licence unknown), Assemblage/DeepHistory (PE recipes, no pair labels), Winbindex (GPL-3.0 metadata), universalmutator/Mull (mutants), `llvm-pdbutil` and `opt` (truth and transforms), Ghidriff/BinDiff/rz-diff (diffs with engine-native scores). None answers "how often is this PatchTrace output right, and on what kind of files".
- **PatchTrace adds**: explicit older/newer orientation and stripped-image discipline through the production adapters (the numbers describe what the analyst runs); one label store for pairing, change class, cosmetic noise, fix localisation and channels; regression gates (A/A, planted) shared by the unified engine and every channel; series (three consecutive pairs per project feed the N-way chain checks of G-U4 and per-hop attention); claims that travel with the product (artifact fields, ledger, Evidence limits, reports); an owner-run Tier W that keeps Microsoft data local yet can feed a reviewed ledger entry.
- **Workflows**: W1 a developer changes ranking or an engine and the nightly report shows deltas per lineage with intervals plus A/A and planted gates (advisory first). W2 an analyst opens the Evidence dock, reads the order-only line, expands Evidence limits and exports a report carrying the same text. W3 the owner runs `tier_w all`, reviews the aggregate and opens a ledger PR. W4 SPEC-31 S6 computes G-U1..G-U7 from the same labels. W5 channel owners (CAP, WB3, DIE, YRX) run their label pack, pass or fail the channel gate, and the ledger state follows.
- **Charter check (roadmap s3)**: (1) pair-aware: every label and report row is an (older, newer) pair and the evaluator verifies orientation; (2) delta not inventory: truth is about changes between sides, and missing, contested or unknown output is abstention, never a wrong or negative vote; (3) anchors: section 4; (4) triage: rank metrics on the shipped lead list, no averaging, shared-origin channels (`D_ghidra`) counted once and listed by `independence_index`, no number shown; (5) one click to the code: the new `Validation:` line sits in the detail pane beside the existing "Go to match" action, while the status line and dev reports have no code location by design (N/A); (6) provenance: report SHA, tool versions, recipe digests, consent flags, ledger expiry; (7) offline-first: the shipped part is pure and offline, dev network only in `fetch`/Tier W with explicit consent, no target is executed; (8) teachable: `meaning` and `next` text ids per scope id and state; (9) synergy: section 5.

## 7. Contracts
### 7.1 Evaluation core (`tools/calibration/evalcore`, dev-only) and `tier-r-report/1` (additive)
- Naming: `tools/calibration/evaluate.py` (exists) scores calibrated models per profile; `tier_r/evaluate.py` is the thin engine evaluator over `evalcore`; Tier W calls the same core; all use `bootstrap.py`.
- Protocols (shared with SPEC-33 s10): `TruthLabelLike`, `EngineMatchLike`; new `EnginePair(old_rva, new_rva, flag, native, order_key)` and `EnginePairs(engine, version, symbols, pairs)`. Sources: `rz-diff` via `registry.build_registry` + `scheduler.run_engines` (`ProjectRef`, cap 2 parallel); `ghidriff` via `ProjectService.create` + `cli._run_pair` (symbols off, one Ghidra at a time); `bindiff` only from supplied `.BinExport` pairs (C3 `accept_binexport`) or imported `.BinDiff`; `attention` = enrichment signals + `ranking.rank` (the shipped lead list); `unified` = `unified-result/1` rows.
- Flag mapping: Ghidriff `category == 'modified'`; rz-diff and BinDiff `similarity_milli < 1000`; unified `material` and `review` flag, `cosmetic` and `unchanged` do not, `unknown` abstains. Unified identity: `matched`/`tentative` paired, `candidate`/`contested`/`ambiguous`/`unknown` abstained (never counted wrong), `older-only`/`newer-only` unpaired.
- Per truth record: identity outcome `paired-correct / paired-wrong / unpaired / abstained`; for correctly paired same-identity records, flagged or not. Truth `ambiguous` is counted aside.
- Rank: fix set = `case.declared_changed` (cards) or the mutation target (`case.mutation`); no change to `known-answer-labels/1`. Per pair and source the ordered flagged list (Ghidriff and rz-diff by ascending native similarity then name; `attention` by `RankingEntry.rank`; unified by materiality, change-class count, RVA), midrank ties. Populations `real-fix` (cards) and `planted` are never pooled; the resampling unit is the lineage (`bootstrap.draws`, B 2,000, 500 in smoke); paired deltas reuse identical draws.
- Curves (descriptive, never shipped): 15 equal-width native-score bins to empirical pairing precision per engine; unified per-tier (M/A/B/C) precision; model reliability from `metrics.reliability`. OOD: with a model under test, `calibration.ood.ood_flags` runs on every row and the report gives flag rate and the flagged/unflagged error ratio (`ood_fit.risk_ratio`, lineage interval); without a model, descriptor flags (function size outside the Tier R 0.1..99.9 percentile range, thunk, N9) are counted, never used to abstain.
- Pydantic additions in `tier_r/contracts.py` (strict, frozen, `extra=forbid`):
  - `Interval(point, lo, hi, undefined, anti_conservative)`; `LabelCell(paired_correct, paired_wrong, unpaired, abstained, flagged, rate: Interval)`
  - `RankBlock(population, pairs, lineages, pool_median, found_in_pool, hit_at{1,3,5,10,20}, mrr, mean_rank, ndcg10: Interval, tie_rule='midrank')`
  - `CurveBlock(kind, engine, bins: (lo, hi, n, precision))`; `ShiftBlock(descriptors: name -> (n, q05, q25, q50, q75, q95), shares, n_lineages)`; `CoverageRow(engine, stratum, attempted, completed, blocked, failed)`
  - `TierRReport` optional fields: engine Literal gains `unified`, `attention`; `labels[stratum][engine][truth_label]`, `rank[stratum][engine]`, `curves`, `shift`, `coverage`, `lineages`, `scope_ids`. `report_sha256` stays canonical-JSON SHA-256, no timestamps, byte-identical on re-run.

### 7.3 Training run (`tools/calibration/train.py`, `shift.py`; dev-only)
- **Inputs**
  - `calibration-corpus/1` from `tier_r/manifest.py`: tier R binaries with source pins and recipe digests, lineage = project, `family` from the recipe, split salt `c9-v1`, shift-test lineages declared before the first look (all `msvc`-profile lineages plus one family).
  - `calibration-labels/1` (`source: synthetic-exact`) from `tier_r/annotate.py`: natural stratum = every engine candidate of release, CVE and control pairs (`p_incl` 1; `sample.sample(budget_per_pair=20000)`, so only larger pairs carry weights); adversarial = mutation, noise and identity-negative suites.
  - Per pair engine outputs: Ghidriff (symbols hidden, stripped image), rz-diff, BinDiff when a BinExport pair exists.
  - `ExtractionContext(symbol_provenance='none', arch='x64', toolchain=mingw-gcc:'gcc', mingw-clang/msvc-free/clang-cl:'clang', msvc:'msvc', binexport_producer='ghidra' or 'none')`.
- **Rows**: `features.extract_all` in `feature_names(profile)` order (features/1, 63 columns for G+B+R); `y = 1` iff A = same, no-counterpart 0; ambiguous and indeterminate excluded and counted (the zlib pair already shows 9 of 128 ambiguous: expect the release stratum to be flagged and bounded as worst case); groups from `lineage.identity_groups(hub_max_lineages=3 [inf])`, hub bodies reported as `seen-body`. Profiles G and G+R first; G+B and G+B+R once BinExport pairs exist.
- **Models and CV**: M0, M0b, M1, M2, M3 per profile; M4 ablations (leave-one-family-out, drop `D_ghidra`, drop `D_symbols`); no M5. `CVConfig(k_outer=5, k_inner=5, c_grid=(0.01, 0.1, 1, 10), seed=1)`, grouped by lineage and function identity, calibrator on natural out-of-fold rows only, `choose_tau` = fixed-sequence Learn-then-Test. For G1 every Tier R lineage is dev (14 recipe + 24 suite lineages = 38, about 37 after libpng/zlib merge, above the `n_groups >= 30` check of `gates._level`); Tier R is never used for G2/G3.
- **Shift ladder** (report block `shift`): (1) grouped CV inside one toolchain; (2) leave-one-toolchain-out (gcc/clang to msvc); (3) leave-one-family-out; (4) Tier W rung `not-run` in cloud, owner only. Each rung reports precision at the frozen tau, coverage, ECE excess over null and OOD flag rate, with degradation deltas and lineage intervals, plus "forced" accuracy with OOD abstention off to show what ignoring the flag costs.
- **Outputs**: `calibration-report/1` with `claim = TIER_R_CLAIM` ("Measured on test builds of open-source code; says nothing about Windows system files") and `dataset.tier = 'R'`; G1 pass/fail/insufficient; G0, G2, G3 `insufficient-data` by construction (missing `tier_w_families`, `tier_w_kinds`, audit, kappa); artifact `experimental`, display `none`, never bundled (dev override only). Train key = SHA-256(manifest sha, label-set sha, engine-run digests, `features/1`, config digest, preregistration sha).

### 7.4 Exact conditions for `display_level()` to leave `ordinal`
1. A bundled artifact for the profile passes `parse_artifact`: strict JSON, digest, `features/1`, <= 512 KiB, unexpired (<= 366 days).
2. `status` is `bands-ok` or `numeric-ok`, `policy.display` consistent, and `evidence.gates` G0 and G2 are `pass` (G3 too for numbers).
3. G0 (`G0_MIN`): >= 12,000 natural; >= 3,000 locked natural with >= 150 weighted-effective negatives; >= 40 lineages, >= 10 families; locked >= 12 lineages and 5 families; **>= 6 Tier W families covering kernel, usermode-dll and driver**; >= 2 toolchain profiles; >= 1 shift lineage; kappa >= 0.80 or single-annotator test-retest; indeterminate <= 0.05; symbol-audit error <= 0.02; N1..N11 >= 30 each.
4. G2: precision >= 0.95 (CI low >= 0.90, width <= 0.10), LTT certified, coverage >= 0.40 (low >= 0.30), Brier skill low > 0, FDR reduction low > 0 against the best of M0/M0b/M1/M2, worst stratum low >= 0.85, OOD validated or reduced, ablations reported.

8. L2 also needs G3 (second annotator O2, reproducibility, frozen-EXE smoke, independence caveat), shift precision >= 0.90, and a deliberate UI amendment (the `%` ban in `tests/test_evidence_view.py` stays until then).

### 7.6 Channel label packs (`tools/calibration/channels/`) and how labels reach the lead list
| channel | truth | metrics | blocked by |
|---|---|---|---|
| strings | `string-literal` operator + image-level `.rdata` ASCII/UTF-16LE (>= 4 chars) delta from the debug image; source containment gives function truth for a future xref channel | delta precision and recall; A/A false adds must be 0 (except `__DATE__`-style); `representation-changed` misflags | FLOSS runner/store (T track) |
| capabilities | `api-use` operator + expected-rule table (8 behaviours, recall only); invariant "truth-unchanged function is never `newly-introduced`" | violation rate (0 on correct pairing), A/A deltas, localised-entry precision | capa runner |
| build environment | `BuildInfo` per side: `toolchain_changed` true for gcc/clang and msvc-free/mingw noise pairs, false for A/A, opt-only and layout pairs | flag recall on noise pairs, specificity on A/A, `packed`/`protected` false everywhere, `environment-unknown` rate, lead-list pool purity in flagged vs unflagged pairs | none (types exist) |
| rules | lineage matrix: a rule from the fix diff must match the unpatched build and not the patched ones, across toolchain variants; 0 hits on unrelated lineages | TP/FN by variant, FP over all other images | YRX spec |
- **Flow into the lead list**: channels add detectors to `attention/1` profiles (`STR`, `CAP`, `RULE`; `ENV` is a pair-level warning with no weight). A detector joins the default profile only if on dev lineages (i) its flagged set has precision above the corpus base rate with a lineage interval, (ii) its A/A false-lead rate is <= 0.1 %, (iii) hit@10 with it is not below hit@10 without it (paired lower bound > -0.02) and improves at least one slice. One locked-test confirmation per preregistration SHA. Weights stay on the existing integer grid and are authored, never fitted. A pass sets ledger `synthetic-validated`; a Tier W pass `windows-validated`; otherwise `unvalidated`, and the evidence is shown without ranking influence.

### 7.7 Error codes, keys, limits, versioning
Dev tools: `PT-KA-BLOCKED`, `-NORECIPE`, `-LICENCE`, `-PIN`, `-REPRO`, `-ORIENT`, `-LEAK`, `-EVAL`, `-LOCKED` (exit codes as SPEC-32 s12: 0 ok, 1 findings, 2 usage/contract, 3 BLOCKED). Shipped: `PT-CALIB-LEDGER`, `PT-CALIB-SCOPE`, `PT-CALIB-ARTIFACT`. Evaluation cache key = SHA-256(evaluator version, labels digest, engine + version, argv digest, older and newer image sha256, symbols mode). Limits: label doc 64 MiB / 200,000 functions, wrong-match list 5,000, report 64 MiB, engine deadline 1,800 s, bootstrap B 2,000, <= 20 mutants per operator and lineage by default, scope text <= 4 KiB, aggregate cells n >= 30. Persisted contracts change additively only; `features/1` is untouched (a `features/2` unified family waits for unified results on this corpus). No enrichment-store kind and no project sidecar: the ledger is package data, labels and reports are dev files under `PATCHTRACE_CALIB_ROOT` outside any project, and `evidence_scope` in an export is computed at export time.

### 7.8 Claims: what a synthetic Tier R distribution licenses and what it does not
| licensed (stated with lineages, tool versions, tiers) | NOT licensed |
|---|---|
| The pipeline is correct: grouped CV, Learn-then-Test, ECE null and gates recover known answers (G1) | Any absolute accuracy, precision, coverage or calibration claim for Windows system files (ntoskrnl, win32k, drivers, system DLLs) |
| Engine behaviour on source-controlled changes in permissively licensed C code built by clang/lld, mingw gcc/clang and, when the Windows leg runs, MSVC `cl` (stripped x64 DLLs, O2, `/OPT:NOICF`): per-label pairing precision and recall, address-noise false-lead rate, planted-change recall per operator class | Transfer to code built with whole-program or profile-guided optimisation, control-flow guard, ICF, hot/cold splitting, or C++ with WIL/STL; to Windows function-size and call-graph distributions; to servicing updates with hundreds of changed functions |
| The A/A noise floor of an engine and toolchain pair; reproducibility facts | A probability or percent for any user pairing (display stays ordinal; artifact gates 7.4) |
| Relative statements between engines or lead-list variants, worded "on test builds" | Any statement about flaws or exploitability: "fix function" means a function the upstream commit changed |
| Falsification: a failure on Tier R is evidence of a defect (necessary, not sufficient) | That engine ordering or lead-list gains carry over to Windows files (a hypothesis for Tier W); channel value such as DiE false-lead reduction or capa rule coverage; packed or obfuscated code, other CPU types |
- **Stating the shift**: it is shown to the analyst through `scope_ids` and the limits text, measured by the shift ladder (7.3, Tier W rung `not-run` until the owner runs it), and recorded in every report as `TIER_R_CLAIM`. Allowed wording: "Tested on test builds of open-source libraries (N code sets, compilers, tool versions). Not tested on Windows system files." Forbidden: "accurate", "validated for Windows", any percent.

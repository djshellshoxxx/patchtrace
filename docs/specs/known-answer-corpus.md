# SPEC-32: Known-answer corpus factory (Tier R, dev-only)

Status: PARTIALLY BUILT (Phase D wave 0, builder D, 2026-10-14; see s16 for built vs deferred). Implements the Tier R / A-A / planted-mutation corpus that
`calibration-corpus-and-model.md` (SPEC-28 C9) sections 3, 4, 5 and `unified-engine/08-evaluation.md` (SPEC-31 Tier R, A/A,
planted mutations, gates G-U1/G-U2/G-U6) require. Nothing here ships: `tools/` is excluded from the Windows package. No
numbers in this file are results; results live in reports recorded by SHA-256 in `docs/qa.md`.

## 1. Purpose and non-goals
Produce older/newer Windows x64 PE pairs whose answer is known exactly, without human labelling, so every PatchTrace
engine (rz-diff, BinDiff, Ghidriff, the future unified engine) can be scored and calibrated.
- Answers per function: identity (`same`, `no-counterpart`, `ambiguous`) and change (`unchanged`, `changed(kind)`,
  `cosmetic(kind)`, `ambiguous`), plus a relocation/address-masked body-equality fact measured on the images.
- Never guess: when the evidence disagrees or is incomplete the record is `ambiguous` with a reason (section 7).
- Non-goals: vulnerability truth, exploitability, Microsoft binaries (Tier W stays in SPEC-28), shipping any of it.
- SPEC-31 S6 planned `tools/unified/{corpus,mutations}`; it consumes this factory instead of re-implementing it.

## 2. Placement, ownership, safety
- Code: `tools/calibration/tier_r/*` (factory, labeller, evaluation) and `tools/calibration/mutations/*` (planted
  mutations). Hook: `python -m tools.calibration.corpus known-answer ...` dispatches to `tools.calibration.tier_r.cli`.
- Contracts and schemas: `known-answer-labels/1`, `tier-r-recipe/1`, `mutation-case/1`, `tier-r-report/1`; generated by
  `tools/calibration/tier_r/schemas.py` into `docs/schemas/corpus/` with valid and invalid examples (`examples/`), checked by a
  regenerate-and-compare test. `tools/generate_schemas.py` is not touched.
- Large data lives only under `PATCHTRACE_CALIB_ROOT` (default `~/.patchtrace-calibration/`, must be outside the work
  tree) in `known-answer/`: `src/<project>/<commit>/` (fetched, read-only), `build/` (scratch, deleted after each build),
  `images/<sha256>/<file>` (content addressed), `labels/<pair_id>.json`, `runs/`, `reports/`. The repository holds only
  recipes, pinned-source catalogues, label metadata and tiny synthetic C sources. No PE/ELF image is ever committed; the
  existing `corpus guard` keeps passing and is run in CI.
- Rules: Qt-free; stdlib + pydantic. Network only in the explicit `fetch` subcommand: git over HTTPS to an allow-listed host
  (`github.com` by default), fetch of one pinned 40-hex commit, verified by `git rev-parse` equality, plus the SHA-256 of the
  pinned licence file. Fetched sources are untrusted: `core.symlinks=false`, no hooks, no submodules, size/file-count caps,
  never a build script (`configure`, CMake, make, Python, Tcl) is executed: recipes are explicit compiler argv over a pinned
  file list. Compilers/linkers/inspectors run through `jobs.run_process` (absolute executable, `shell=False`, private cwd,
  minimal allow-listed environment without credentials or proxies, timeout, bounded output). Built images are never
  executed. Every unavailable tool is reported as `BLOCKED: <reason>`, never skipped silently.

another. Outputs per image: the debug image (symbols + debug info, used only for truth), a stripped engine image
(`llvm-strip`/`strip --strip-all`; code bytes and RVAs identical, asserted), the PDB when one exists. Limits: 64 MiB per

{argv per object without scratch paths, link argv, tool versions}.

## 5. Ground truth from the image
5.1 Function inventory per debug image (all addresses become RVAs = VA - ImageBase read from the PE header):
- DWARF (`llvm-dwarfdump --debug-info`): every `DW_TAG_subprogram` with code (`low_pc`/`high_pc` or `ranges`); concrete
  out-of-line instances resolve `DW_AT_abstract_origin`/`specification` for name, `decl_file`, `decl_line`; inline-only
  (`DW_AT_inline` without code) functions have no address and are listed as `inlined-away`.
- PDB (`llvm-pdbutil dump --symbols --section-headers -l`): `S_GPROC32`/`S_LPROC32` (name, seg:off, code size); the file
  is the line-block file containing the entry; the module (object) disambiguates statics.
- COFF symbol table (`llvm-nm`): linkage names at entry RVAs, used to name compiler clones and split parts (`foo.cold`,
  `foo.constprop.0`, `foo.part.0`, `foo.isra.0`): their record key gets `variant` = the suffix.
- Origin: `project` when the (prefix-mapped) file is inside the recipe's source tree, else `runtime` (CRT, libgcc, system
  headers). Only `project` functions get label records; runtime functions are counted in the summary.
- Identity key = (file, name, variant), file = project-relative path with `/`. A key that occurs twice in one image
  (static functions of one header emitted by several objects, ICF) is qualified by the object/CU; if still not unique the
  records are `ambiguous` (identity).
5.2 Body facts per function: `raw_sha256` over the exact code bytes [entry, entry+size) read from the PE sections, and
`masked_sha256` over the disassembly (`llvm-objdump -d --no-show-raw-insn --no-leading-addr --symbolize-operands -M intel`)
of the same range with address-dependent operands normalised: every `<symbol>` annotation that is not a function-local
`<Ln>` label becomes `<A>`, `rip +/- disp` becomes `rip+D`, absolute branch/call targets become `A`, and 64-bit immediates
covered by a base relocation become `R`. `body` fact of a pair: `identical` (raw equal), `address-only` (masked equal,
raw different), `different`, `n/a` (a side is missing). Masked hashes are only compared within one disassembler version.
5.3 Source spans: a brace/comment/string/preprocessor-aware C locator (`tier_r/csrc.py`, shared with the mutations) finds
the definition containing `decl_line`: span = first line of the top-level declaration chunk to the line of the matching
closing brace. Source change of a function = comparison of the token streams (comments and whitespace dropped) of its old
and new span: `same-text`, `layout-only` (tokens equal, text differs) or `token-change`; `unknown` when no span is found.

## 6. Contract `known-answer-labels/1` (one strict JSON document per pair)
Top level: `contract`, `pair_id`, `stratum` (`release|cve|control|mutation|aa|noise|authored`), `method`, `project`,
`lineage`, `family`, `older`/`newer` (`ImageSide`: `sha256` of the stripped engine image, `debug_sha256`, `pdb_sha256|null`,
`size`, `file_name`, `image_base`, `source` {`git`|`suite`, `commit`|`version`, `ref`, `license_spdx`}, `build`
{`profile`, `compiler`, `compiler_version`, `opt`, `recipe_digest`, `link_order`}), `label_source` (default of the file),
`functions` (records below, sorted by (old_rva, new_rva, name)), `summary` (counts), `case` (method-specific provenance:
card id, CVE ids, mutation case, suite pair intent), `notes`, `digest_sha256` (canonical JSON without this key). No
timestamps: two runs on the same inputs produce byte-identical files.
Function record: `name`, `file`, `variant`, `old_rva`, `new_rva`, `old_size`, `new_size`, `identity`, `label`,
`change_kind`, `body`, `label_source`, `check` (`ok|disagree|unchecked`), `taxonomy` (N1..N12, optional), `notes`.
Invariants (validator): identity `same` <=> both RVAs and label in {unchanged, changed, cosmetic, ambiguous};
`no-counterpart` <=> exactly one RVA and label `no-counterpart`; identity `ambiguous` => label `ambiguous`; `changed` and
`cosmetic` need `change_kind` (`^[a-z0-9-]{1,48}$`), `unchanged`/`no-counterpart` have none; RVAs unique per side;
`older.sha256 != newer.sha256` except stratum `aa`; at most 200 000 records, 64 MiB per document. Loader: size cap, strict
JSON (duplicate keys, NaN rejected), pydantic strict `extra=forbid`, digest check.
`label_source`: `source-diff` (M1 and found release cards), `fix-diff` (M2 and found fix/control cards),
`planted-mutation` (M3), `same-source` (M4), `authored-truth` (I4).

## 7. Label derivation (decision table; evidence = identity join, source change, body fact)
| Method | Rule |
|---|---|
| release / cve / control | identity by key; `same-text` + body identical/address-only -> `unchanged`; `layout-only` + masked equal -> `cosmetic(comment-whitespace)`; `token-change` + body different -> `changed(source-diff)` (or the card's declared kind for that function); `token-change` + masked equal -> `ambiguous` ("source changed, code identical": inactive `#if`, dead code); `same-text` or `layout-only` + body different -> `ambiguous` ("induced": header, macro, inlining); span unknown -> `ambiguous`. Declared `changed_functions`/`unchanged_controls` of a card are cross-checked: a declared function that is not `changed`/`ambiguous`, or a control that is `changed`, sets `check=disagree`. |
| mutation | the target function gets the operator's label (`changed(op)` or `cosmetic(op)`); a semantic mutant is accepted only if the target's masked body differs (else the next site is tried, rejections recorded); other functions: `unchanged`, except under a semantic operator a function whose masked body differs becomes `ambiguous` ("induced by <target>", e.g. inlining); planted helper functions are `no-counterpart`. |
| aa / noise | all project functions `unchanged` by construction whatever the body fact (that is the noise being measured); functions present in only one image (inlined away, IPA clones) are `no-counterpart` with a note. A/A rebuild additionally reports byte reproducibility (differing sections). |
| authored (I4) | the suite's label maps: `same` -> `unchanged`, `changed` -> `changed(kind)`, `cosmetic` -> `cosmetic(cosmetic)`, `moved` -> `cosmetic(moved)`, `renamed` -> identity same (from -> to) `cosmetic(renamed)`, `added`/`removed` -> `no-counterpart`, `inlined` -> `no-counterpart` (note "inlined into X"), `split`/`merged` -> identity `ambiguous`. Cross-check (`check`): every named function present with an RVA (absent `inlined`/`static inline` targets excepted); `same`/`cosmetic`/`moved`/`renamed` expect masked-equal bodies; `changed` expects a different body; `added`/`removed` expect absence on the other side; a failed expectation is `disagree` with the reason, the authored label is kept and the pair summary counts disagreements for human review. |

## 8. Planted mutations (M3, `tools/calibration/mutations/`)
Operators work on tokens inside one function body located by `csrc.py` (never a blind regex over the file):
semantic `cmp-flip`, `const-change`, `bounds-check-insert`, `bounds-check-remove`, `call-add`, `call-remove`, `arg-swap`,
`loop-bound`, `off-by-one`, `int-width`; cosmetic `ws-comment` (moves DWARF/PDB lines), `dead-code` (`if (0) {...}`),
`reorder-defs` (swap two adjacent definitions: layout shift), `local-rename`, `macro-rewrite` (identity macro around a
returned expression), `inline-toggle` (add/remove `inline` on a static function). `call-add` plants a `noinline` helper
writing a volatile sink so it works in freestanding code. Determinism: candidate sites are ordered by
`det_uniform(seed, operator, file, function, site)` (SPEC-28 s7.3); a case (`mutation-case/1`) records base source, operator,
seed, target (file, function), site (line, column, before/after text), attempts and rejections, so it is reproducible
byte for byte. A mutant that does not compile is rejected and the next site is tried (bounded attempts).

## 9. A/A and toolchain noise (M4)
(a) Rebuild the same source twice in two different scratch directories with the same flags: the pair must be byte-identical
(reproducibility check lists differing sections otherwise) and labels are all `unchanged`. (b) Same source at O0/O1/O2/O3/Os
and gcc vs clang: identity `same` for functions present in both, no semantic change; measures toolchain-noise false
positives. (c) Layout: reversed and rotated object/link order (and `reorder-defs` mutants) give address-shift-only pairs.

## 10. Evaluation (`tools/calibration/tier_r/evaluate.py`)
Engines: rz-diff through the production secondary adapter (`registry.build_registry` + `scheduler.run_engines`, pinned
rizin); BinDiff from `.BinDiff` files (existing importer) and Ghidriff from raw JSON (existing normaliser) placed per pair
by the user; when neither the tool nor imported results exist the engine is `BLOCKED` with the reason. Default input is the
stripped engine image (symbols hidden, SPEC-28 s5.2); `--symbols visible` uses the debug image and is reported separately.
Scoring per engine and stratum (micro over functions, plus per pair): identity precision = correct predicted pairs /
predicted pairs touching a labelled non-ambiguous function; identity recall = correct / truth `same` pairs; changed-set
precision/recall on correctly matched pairs (engine "changed" = rz-diff type != COMPLETE or similarity < 1.000, BinDiff
similarity < 1.0, Ghidriff `modified`); false-positive rate = flagged / correctly matched `unchanged`+`cosmetic`
functions; cosmetic and `ambiguous` counts reported apart; the wrong-match list (bounded, sorted) names truth and predicted
counterparts. Output `tier-r-report/1` JSON (deterministic, `report_sha256` over canonical JSON) and Markdown rendered from it.
Mocked/synthetic engine output in tests is never live evidence (AGENTS.md).

### Normalized output retention (LBL-31, November 1, 2026)

The `evaluate` CLI retains every successful normalized engine response whose
canonical byte SHA-256 appears in its report. Each evaluation exclusively creates
a fresh directory under the selected store's `outputs/<run-token>`; `--outputs`
may select another **nonexisting** directory. Existing directories, including
empty ones and links/reparse points, are never reused. Filenames bind the validated
pair id and engine, and JSON binds ordered image hashes, symbol mode and producer
version. A provider may not return a different engine identity; duplicate provider
owners are rejected before execution. The report's existing label digests and
pair/engine keys remain the reference contract, without adding paths or random
run tokens to its deterministic bytes.

Normalized JSON is strict, canonical and capped at 64 MiB while serializing. A
staged file is flushed/fsynced, then published with an atomic no-overwrite hard
link; unsupported filesystems or publication errors fail that pair with no output
digest, metrics or successful-run credit. No overwrite fallback is permitted.
Previously completed outputs remain intact. The fresh directory's filesystem
identity is checked before and after publication; changed ownership is a failure,
not successful evidence under another run. This does not claim a lock against an
arbitrary same-user hostile process or full power-loss durability on every OS.
An integrity failure after publication can leave an uncredited file. Transfer
consumers must verify successful report references, not adopt directory contents.

CLI JSON reports and their Markdown companions are also published without
replacement. Default filenames remain under the selected store's `reports/` and
include the fresh run token; equal evaluations retain equal report bytes/digests
but different paths. Explicit `--out` cannot replace an existing JSON/Markdown
file. A report-write failure preserves already retained engine outputs and earlier
reports. The CLI summary returns the actual `outputs` path. Library callers opt
in with `evaluate_full(..., output_dir=...)`; without it they retain the existing
in-memory evaluator behavior and must not claim file retention.

The existing `tier-r-engine-output/1` kind vocabulary gains `attention`, which
the evaluator/CLI already support. Its prediction `order_key`, already emitted by
the producer, is an optional tuple of at most 16 strict integer, finite float or
string values (at most 512 characters per string). Attention's production key is
one integer rank; the bounds cover that provider without altering its ordering.
Missing keys stay omitted in producer bytes. Validation is a check on the original
canonical bytes, never a reserialization of model defaults or coerced values.
The existing normalized-output reader must preserve the optional key when it
reconstructs predictions, so replay uses the same ranking. This does not add
attention to the calibration feature-engine set or change fitting/scoring rules.
Existing documents retain their bytes and meaning. This is an additive `/1`
vocabulary/field extension: older strict readers reject the new kind or field
safely; this is not universal reader compatibility or a numerical-confidence
claim. No `unified` producer or new engine default is added. This is a selective
adoption of preserved PR #78 (`2019a37f`, repository MIT license); its older
duplicate-scoring behavior and replace-after-existence-check writer are not
imported. Verified shard/merge artifact transfer remains a separate acceptance
task; none of this authorizes Tier W redistribution or a final evaluation.

#### Credited replay and producer validation (#157, November 1, 2026)

Every successful provider answer, with or without retention, must satisfy the
existing normalized-output field bounds before scoring. The existing in-memory
`unified` provider remains supported through a private validation shape using the
report engine vocabulary; persisted output/credit schemas retain their four
existing engines, so retained `unified` answers are explicitly refused. Names remain capped at 512
characters and versions at 200; invalid answers fail with no metrics/digest rather
than being truncated or accepted only by the in-memory path. Validate the Python
document before JSON serialization, converting only JSON array containers to
tuples for strict validation. Scalar types, code points, absent defaults and the
original accepted document are preserved. Retention's incremental 64 MiB
serialization cap remains. Changed, deduplicated predictions must have mutually comparable
effective ordering keys under the existing scorer (`order_key` or its unchanged
similarity/name fallback). Reject incompatible keys, including conflicts with a
missing-key fallback; do not impose a uniform column type, change ranking/ties,
or add attention to training's feature engines.
The same text bounds apply wherever accepted metadata is copied: `tier-r-report/1`
wrong-match names allow 4,096 characters and `tier-r-feature-rows/1` engine-run
versions allow 1,024. Evaluation reports and training rows preserve those values
without truncation.

A fresh `OutputStore` publishes `.tier-r-output-run.json` with contract
`tier-r-output-run/1` before any output. After evaluation/report assembly,
`finalize(reports)` publishes `output-credits.json` (`tier-r-output-credits/1`)
exclusively. It embeds the validated, digest-checked reports and one record for
each successful pair/engine reference, binding report digest, pair id, engine,
exact canonical output SHA-256, ordered image hashes, symbol mode and producer
version. Duplicate/ambiguous references and inconsistent report ownership fail.
Finalization rechecks run ownership and the referenced bytes; a failure leaves
the run incomplete and cannot return a successful evaluation report. Failed or
unreferenced raw artifacts are preserved but never credited.

The aggregate credit manifest has its own explicit 64 MiB byte budget, unchanged
from the previous effective limit. It is independent of the 64 MiB per-output
limit; no pair-count estimate substitutes for exact bounded serialization.
`preflight_credit_manifest(reports, output_records)` checks the complete report
batch and retained-output metadata without filesystem writes, using the same
builder and budget as finalization. Transfer writers with a complete batch call
it before creating their destination. Reports and successful credit wire formats
are unchanged.

Before publishing credits, finalization exclusively publishes
`.tier-r-output-incomplete.json` (`tier-r-output-completion/1`, `status: incomplete`).
The reader refuses any presence of this sentinel, including malformed files or
broken links. All credit and owner verification finishes while it remains;
removing the owned sentinel is the final success transition. Removal failure is
failure, with no subsequent validation after successful removal. A crash before
credits leaves an incomplete run; a crash after credits but before sentinel
removal also leaves an incomplete run. Started or completed stores cannot be
finalized again. Existing successful `MANAGED_FILES` remains the original two
files. These rules do not add an OS-wide lock or power-loss durability claim.

If credit finalization fails after evaluation has assembled its report, the
library raises `EvaluationRetentionError`, retaining that complete report and
the original failure even if diagnostic persistence fails. It attempts exclusive
publication of `uncredited-report.json` (the unchanged report, bounded at 64 MiB)
and `evaluation-failure.json` (`tier-r-evaluation-failure/1`, `status: failed`,
`credited: false`, report filename/digest and bounded error text). These are
diagnostics outside ordinary report discovery, never training success evidence.
Either diagnostic filename also blocks managed or legacy credit loading.
Diagnostic writes cannot overwrite an existing file or mark a prior completed
run failed. The CLI reports exit 1, `status: failed`, `credited: false`, exact
attempted and retained diagnostic paths, and each persistence error. If report
retention fails it includes the assembled report in `report_data`; it never
publishes that diagnostic through the ordinary success-report path. This is a
runtime completion failure, distinct from exit-2 usage/contract errors.

The public `write_raw(pair_id, engine, raw)` retains exact validated canonical
bytes; `finalize(reports)` and `MANAGED_FILES` also support the separately owned
verified-transfer writer. A transferred run uses the same reader contract, with
the parent transfer manifest additionally binding the managed metadata files.

`train.load_outputs` recognizes managed markers with no-follow checks (including
broken links), requires a valid completed credit manifest, and rechecks every
successful reference's exact bytes and metadata before reconstruction. A missing,
unreadable, linked, incomplete or inconsistent managed record is an error, never
a fallback to legacy loading. Selecting a parent containing managed runs is
ambiguous and refused. Legacy loose output folders remain an explicitly
**unverified compatibility path** for existing callers: schema validation and
duplicate-key rejection do not establish report credit, transfer ownership or
final-evaluation acceptance. This includes output directories created before
this amendment: their missing markers cannot retroactively prove success.
`load_outputs(..., allow_legacy=True)` emits `LegacyOutputWarning` whenever it
uses this path; `allow_legacy=False` refuses it. No existing directory is silently
stamped as managed or assigned inferred credit.
Removing all managed metadata by the filesystem
owner is outside the local integrity/authenticity claim. No signature, hostile
same-user lock, model change or final-run permission is implied.

## 11. Lineage, roles and existing tooling
Lineage = project (`L-<project>`; suites `L-ours-<suite>-<project>`); mutants, A/A and noise pairs inherit the lineage of
their base source so grouped CV (SPEC-28 s4) never splits a function identity across folds; `family` comes from the recipe.

lineages) that `corpus verify` and `lineage.assign_roles` accept. `tier_r/annotate.py` converts labels plus engine
candidates into the hash-chained annotation log (`label.AnnotationLog`, annotator `known-answer/<label_source>`, phase
`blind`, guideline `ka-1`) and through `label.consolidate` into `calibration-labels/1` (`source: synthetic-exact`).

## Inputs and processing
Accept only validated advisory facts (SPEC-28), artifact-hash-matched and orientation-checked Ghidriff/BinDiff/rz-diff evidence, plus versioned capa/FLOSS/DiE results (SPEC-29), and optional future Ghidra p-code/CFG data. Invalid pair or stale run => abstain. Merge by canonical artifact + module-relative address and verified function ID, never names alone. Resolve competing matches first; classify contests as review-required, not wrong by majority.

Build immutable provenance graph nodes for Advisory, CVE, CWE, Product, Binary, Function, BasicBlock, Operation, Capability, String, Toolchain, Match, PatchHypothesis. Edges such as matched-to, calls, contains, produces-value, guards-sink, exhibits-capability, references-string, contradicts and derived-from must carry source, raw ID, version, artifact SHA, location and a shared-lineage group. No causal link from string similarity alone.

Derive weakness hypotheses from CSAF CWE and scoped advisory language using versioned declarative rules. Expected mechanisms express source -> transformation -> sink -> guard rather than arbitrary words: memory write/bounds, arithmetic/range, authentication decision, path normalization, lifetime and concurrency. Match known differences against rules. Distinguish direct p-code/data-flow proof obligations from weaker decompiled text signals. Compare capa capabilities as localized supporting context; FLOSS extracted strings as potential anchors, not proof; DiE toolchain/packer signatures as quality flags for compiler noise, not positive evidence of vulnerability.

## Scoring contract
Maintain distinct dimensions: function identity correctness, structural change reliability, patch mechanism support, and actual vulnerability verification. Do not average Ghidriff/BinDiff/rz-diff upstream scores. Evidence lineage deduplicates correlated observations. Current output uses ordinal labels corroborated/contested/unassessed for identity and strong/moderate/tentative/unexplained/contested for mechanism support. Missing data is not contradiction. Contradictions include mutually exclusive function pairings and wrong product identity. Out-of-distribution, tool error and unsupported packer signatures require explicit uncertainty. Keep unclassified/unmatched function queue to avoid filtering novel fixes.

## Pure modules
intelligence/graph.py owns evidence model and canonical graph traversal; intelligence/rules/contracts.py + compile.py + evaluate.py own versioned predicate DAG and CWE rules; intelligence/fusion.py joins deduplicated evidence by lineage; intelligence/quality.py handles toolchain noise flags; intelligence/ranking.py returns deterministic stable ordered candidates; intelligence/calibration/{features,train,evaluate,predict}.py are OPTIONAL and must only load models trained on independently labeled outcomes; intelligence/reports.py exports JSON/Markdown/HTML with sources and limitations. UI and CLI call a single service facade. Bounded depth, complexity budgets, cancellation, immutable derived state, transactional persistence, no Qt imports in domain modules.

## Proposed outputs
Versioned PILOT/1: assessment(project, old/new SHA256, advisory SHA256, ruleset SHA256, engine versions, candidates, unmatched, failed steps). Candidate(match ID, CWE hypothesis ID, identity-status, mechanism-support, evidence references with RVA/JSON pointers, counterevidence, unknowns, alternate explanations, nuisance flags, stale state, analyst review). Avoid numerical vulnerability confidence claims without empirical calibration.

## Evidence-calibration research contract
Create human-reviewed truth labels for same-function identity, true patch-bearing function, correct changed-block correspondence, mechanism correctly supported, and actual vulnerability verification separately. Split training and test by product/build families, not random functions from one executable. Evaluate Ghidriff-only, multi-diff baseline, plus CSAF, plus each tool alone and together. Metrics: precision@K, recall of verified patch-bearing functions, false leads per verified finding, abstention coverage, Brier and expected calibration error for any calibrated probability, runtime and memory. Leave-one-tool-out ablation guards against a tool that adds only cost or noise. Proposed adoption gate: statistically supported >=20% fewer false leads at nondecreasing recall on held-out corpus; tune before release, not a claimed result. Calibrated logistic regression then isotonic/Platt if sufficient labels; otherwise maintain explainable ordinal ranks. Publish confusion matrices, calibration population and uncertainty.

## Critical negative tests
A newly added error string cannot prove remediation; DiE packer heuristics cannot prove encryption; missing capa rule is absence not contradiction; contradictory function matches block localization; aliases and interprocedural unknowns prevent claimed full data flow; CVE product mismatch blocks applicability claim; shared Ghidra origin is correlated evidence; compiler-only rebuilds should not generate spurious high-confidence mechanisms. Tool failures and partial results must preserve earlier project revisions. Test these before implementation with complete fixtures and reproducible expected outputs.

## Release gate
Only implement after multi-engine adapters stable. Add tests first, clean CLI JSON, GUI evidence/limitations view, offline-capable no-execution mode, performance bounds and Windows PE fixture end-to-end. Numerical probability and automated suppression remain disabled until independent held-out calibration. Keep manual analyst overrides and historical source provenance.

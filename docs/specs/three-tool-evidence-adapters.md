## Tool selection after review
**capa** (https://github.com/mandiant/capa): choose. Behavior/capability signatures localized to functions and instructions; Ghidra/PyGhidra backend documented, versioned rule corpus and JSON. Capability added/removed does NOT prove a vulnerability fix; signatures can shift under optimizer, symbol quality and rules. Pin engine, backend and rules hash. 
**FLOSS** (https://github.com/mandiant/flare-floss): choose. Extracts static, stack, tight, decoded and language-specific strings, with JSON output and locations when available. Deduplicate and map static file offset/RVA and recovered function addresses; do not attribute decoded string to a specific function when extractor cannot provide trustworthy location.
**Detect It Easy console 'diec'** (https://github.com/horsicq/Detect-It-Easy): choose as *quality gate* ONLY; its compiler, linker, packer, protector and file-type signatures flag comparisons likely distorted by toolchain or packing. It is not positive evidence for a security mechanism. Use bounded result source/heuristic and mark unknown if weak. Research showed an upstream 2026 issue where GUI and CLI differ; test exact pinned CLI/signature DB version before accepting results.

Rejected/deferred: QBinDiff and Diaphora = additional whole matching systems, duplicating phase-3 engine work, high memory/setup; pefile/LIEF/llvm-readobj = excellent supporting PE parser for preliminary inspector but not one of the three hypothesis agents; YARA-X = valuable custom-rule layer but largely shares source rules and strings so count as *derived*, not independent evidence; TLSH/ssdeep = compiler/noise sensitive; pe-sieve = dynamic process memory not relevant to no-execution static phase; Sigcheck proprietary and signature checking belongs to existing Windows trust adapter. Tool 3 remains subject to a value gate: if DiE's quality flags do not reduce false positive work on held-out corpus, exclude from default profile despite technical integration.

## Clean module contracts
intelligence/tools/common.py: immutable ToolManifest{engine,version,cli_path,capabilities,license,rules_sha256,backend_version}; ToolRun{input_artifact_hash,config_digest,started_at,elapsed,status,error,stderr_digest,stdout_digest}; CapabilityEvidence{rule_id,namespace,scope,address_space,address,location,kind,source_run_id}; StringEvidence{value_hash,display_value,encoding,type,source_location,confidence_class,extraction_method}; EnvironmentEvidence{category,toolchain,packer,protector,detector_rule,heuristic,source,certainty}; EvidenceLink{tool_run_id,artifact_sha256,function_id,RVA,file_offset,source_fragment}. 'none found' is separate from 'tool absent/error/unsupported'.
intelligence/tools/capa.py: version/probe, supervised subprocess with JSON output, Pydantic parser, optional Ghidra backend, rule pack pinning; preserve all matching feature locations and scopes; prohibit confusing whole-file matches with function-specific matches.
intelligence/tools/floss.py: version/probe, supervised bounded JSON output and deobfuscation runtime, categorized strings; redact secrets in default reports, preserve hashed/source positions, map only verified offsets.
intelligence/tools/diec.py: version/probe, query signatures (including DB hash), strict output parsing, identify high-level compiler/packer transformations, optional low-confidence noise flag.
intelligence/tools/runner.py: user opt-in profiles (basic=capa; context=capa+FLOSS; full=capa+FLOSS+DiE quality gate); scheduler, timeout, cancellation, stdout/stderr separation, bounded outputs, per-engine sandboxed scratch, error isolation and cache key (artifact+engine+rules+backend+options).
intelligence/tools/normalize.py: convert locations into canonical module-relative RVA and compare older/newer; reject mismatched SHA, ambiguous RVA, stale output, wrong parser contract.
intelligence/tools/delta.py: calculate added/removed/unchanged capabilities and string evidence; distinguish newly detectable vs genuinely newly introduced behavior, unlocalized entries, changes caused by packing/decompiler shift.
No import from Qt; all files independently testable; no engine may modify matching, original binary or existing evidence record.

### T2. Records (`common.py`; frozen Pydantic, `extra='forbid'`, strict types, additive changes only)
- `ToolManifest`: `engine` (`capa`|`floss`|`diec`), `version`, `version_text` (sanitised, <= 120), `cli_path` (resolved absolute; local only, reports show the basename), `executable_sha256`, `capabilities` (sorted option tokens the probe verified, e.g. `json`, `backend:vivisect`, `backend:ghidra`, `deobfuscation`, `database`), `license`, `rules_sha256` (capa: digest of an explicit rule directory; diec: digest of the signature database directory; else null), `rules_source` (`directory`|`embedded`|`none`), `signatures_sha256` (capa explicit `-s` directory), `backend` (capa `vivisect`|`ghidra`; FLOSS `vivisect-emulation` only with deobfuscation; diec null), `backend_version` (Ghidra version for `-b ghidra`), `untested_version`, `supported`, `reason`. Rules identity = `rules_sha256` or `embedded:<executable_sha256>` (the executable pins its embedded pack).
- `ToolRun` (one attempt per engine and side, never updated): `run_id`, `engine`, `side`, `input_artifact_hash`, `config_digest`, `cache_key`, `started_at` (ISO-8601 UTC), `elapsed` (milliseconds), `status` (`ok`|`none-found`|`failed`|`timeout`|`cancelled`|`unsupported`|`absent`), `error`, `error_code`, `returncode`, `stderr_digest`, `stdout_digest` (SHA-256 of the exact captured bytes), `stderr_excerpt` (sanitised, <= 4 KiB, never in default reports), `raw_sidecar`, `evidence_count`, `cache_hit`, `profile`, `options` (<= 16 short pairs), `manifest`, `anomalies` (<= 64 `code:detail`). `none-found` = the tool ran and its validated output holds zero evidence items; absent, unsupported and failed tools never yield it (missing is unknown, never a negative vote).
- `EvidenceLink`: `tool_run_id`, `artifact_sha256`, `function_id` (`rva:0x<hex>` of a function start the tool itself reported, else null), `project_function_id` (the project's `FunctionRecord.id` when exactly one record on that side starts at that RVA), `rva` (canonical module-relative RVA; the spec's `RVA`), `file_offset`, `source_fragment` (<= 200 chars pointer into the raw output), `attribution` (`function-start`|`basic-block-in-function`|`decoding-routine`|`stack-frame`|`none`).
- `CapabilityEvidence`: `rule_id` (capa rule name), `rule_sha256` (of the rule `source` in the output), `namespace`, `scope` (`file`|`function`|`basic block`|`instruction`), `address_space` (`absolute`|`relative`|`file`|`no address`), `address` (as reported), `location`, `kind` (`capability`|`library` for `lib: true`|`limitation` for `internal/limitation/*`), `source_run_id`, `attack`, `mbc` (ids, <= 32 each), `feature_rvas` (sorted RVAs of successful feature locations in the match tree, <= 64) and `feature_count`.
- `StringEvidence`: `value_hash` (SHA-256 of the UTF-8 value), `length`, `display_value` (plain text: control, bidi and non-printable characters escaped, <= 256 chars), `secret_kind` (secret-looking pattern name or null), `encoding` (`ASCII`|`UTF-16LE`|`UTF-8`), `type` (`static`|`stack`|`tight`|`decoded`|`language`), `source_location`, `confidence_class` (`verified-bytes`|`tool-reported`|`unverified-location`), `extraction_method` (`floss-<type>`), `source_run_id`.
- `EnvironmentEvidence`: `category` (`compiler`|`linker`|`tool`|`packer`|`protector`|`cryptor`|`installer`|`sfx`|`library`|`format`|`overlay`|`other`|`unknown`), `toolchain`, `packer`, `protector`, `detector_rule` (DiE signature name), `heuristic`, `source` (`diec`), `certainty` (`signature`|`heuristic`|`unknown`), `version`, `detect_string`, `filetype`, `source_run_id`.
- `ToolEvidenceSet` (row body of kind `tool-evidence`): `contract`, `run_id`, `engine`, `side`, `artifact_sha256`, `cache_key`, `config_digest`, `image_base`, `analysis` (small facts: format, arch, extractor, language, functions recovered), `capabilities`, `strings`, `environment`, `truncated`, `counts`, `anomalies`.

Persistence: kind `tool-run` (body `ToolRun`, id `run_id`) and kind `tool-evidence` (the set inline when its canonical JSON is <= 1 MiB, else a pointer `{contract, kind: 'sidecar', ...identity, sidecar, sidecar_sha256, size, counts}` to `<project>/intel-tools/<sha256>.json`). Raw stdout is preserved as `<project>/intel-tools/raw/<engine>-<sha256>.json` (atomic, content-addressed) before parsing. Guard `(project_id, 'intel-tools', artifact_sha256, cache_key)`. Neither kind is derived, so retention never deletes them; ids are attempt- or content-unique so no stored record is ever rewritten with other content. Engines never modify matching, the original artifact or other evidence.

### T4. Execution
Scratch per engine and side: `mkdtemp(prefix='patchtrace-<engine>-')` under the configured scratch root with `cwd/ home/ tmp/ programdata/ in/` (+ `rules/ sigs/` for capa, `db/ empty/` for diec). The artifact is streamed from the project's verified reader into `in/artifact.bin`, re-hashed (mismatch: `PT-TOOL-ARTIFACT`) and made read-only; tools never see the project path or the user's file name. The input path must stay <= 200 characters (Windows MAX_PATH margin; else `PT-TOOL-INPUT`). The scratch is removed afterwards.

Environment: the shared from-scratch allow-list of `secondary/engine_env.py` (the private-workdir layout built for BinDiff: POSIX `PATH=<exe dir>:/usr/bin:/bin`, `HOME`, `TMPDIR`, `LANG`/`LC_ALL=C.UTF-8`, `XDG_CONFIG_HOME`; Windows `SystemRoot`/`windir`/`SystemDrive` copied, `PATH=<exe dir>;System32`, `TEMP`/`TMP`/`USERPROFILE`/`APPDATA`/`LOCALAPPDATA`/`PROGRAMDATA` inside the scratch; capa needs `LOCALAPPDATA` for its rule cache on Windows [src `capa/rules/cache.py`]). Additions only from explicit configuration: diec `LD_LIBRARY_PATH` (POSIX), capa Ghidra backend `GHIDRA_INSTALL_DIR` and `JAVA_HOME`. Nothing else is inherited (no proxies, credentials, `PYTHON*`, `CAPA_SAVE_WORKSPACE`, `FLOSS_SAVE_WORKSPACE`). PatchTrace makes no network request; the tools have no telemetry.

Process: `jobs.run_process(separate_streams=True)`; stdout limit capa and FLOSS 64 MiB, diec 1 MiB, stderr 256 KiB; captured stdout above the limit is `failed`/`PT-TOOL-LIMIT`. Timeouts (10..86400 s): capa 1800, FLOSS 600 (3600 with deobfuscation), diec 120.

Outcome order: spawn error `failed`/`PT-TOOL-RUN`; cancel `cancelled`/`PT-TOOL-CANCEL`; timeout `timeout`/`PT-TOOL-TIMEOUT`; oversize `PT-TOOL-LIMIT`; capa exit 16/17/18 and FLOSS "supports the following formats" `unsupported`/`PT-TOOL-UNSUPPORTED`; capa exit 10/12/15 (rules, signatures) `failed`/`PT-TOOL-INPUT`; any other non-zero or signal exit `failed`/`PT-TOOL-RUN` with the sanitised first error line (FLOSS and diec print usage errors and `Cannot find:` on stdout [run]); FLOSS exit 0 with empty stdout is `none-found` (FLOSS 3.1.1 prints nothing when a file has no static strings [src, run]); capa or diec exit 0 with empty stdout `failed`/`PT-TOOL-OUTPUT`; then strict parsing (T5).

### T5. Parsing and normalisation
1. Strict JSON: UTF-8, duplicate keys, NaN/Infinity and nesting deeper than 96 are rejected; then Pydantic models of the pinned major contract: capa result document 9.x (`meta.version` major 9, `flavor` static, `meta.analysis.base_address` absolute), FLOSS 3.x (`metadata.version` `v3.`), diec `{detects: [{filetype, values: [{type, name, version, info, string}]}]}`. Unknown or missing top-level fields are `PT-TOOL-OUTPUT` (wrong parser contract); rule metadata and match-tree feature payloads are bounded and otherwise open.
2. Binding: capa `meta.sample.{md5,sha1,sha256}` must equal PatchTrace's hashes of the verified copy; FLOSS and diec carry no hash, so the binding is the verified private copy. Mismatch rejects the run (`PT-TOOL-ARTIFACT`).
3. Canonical RVA: capa `absolute` minus `meta.analysis.base_address`, `relative` as is, `file` through the section map, `no address` none; process/thread/call/token addresses are anomalies. Every RVA must be < SizeOfImage of PatchTrace's own `pe_overview` parse of the same bytes, else the location is rejected (`address-out-of-image`). A capa base different from the header ImageBase is recorded (`base-differs`) and capa's base is used. FLOSS static `offset` maps to an RVA only inside the headers or inside exactly one section's raw data (`< min(SizeOfRawData, VirtualSize)`); overlapping sections give `offset-ambiguous` and no RVA; overlay and slack keep the offset only. Static strings are re-read from the verified bytes at the offset: `verified-bytes`, else `unverified-location` (anomaly). FLOSS stack, tight and decoded addresses are VAs relative to `metadata.imagebase`; imagebase 0 with VA fields is `base-ambiguous` (unlocalized). Decoded strings are attributed to their `decoding_routine`, never to the caller; only `GLOBAL` string addresses are module addresses.
   Function attribution: function scope gives `function-start`; basic-block scope uses capa's `meta.analysis.layout` (`basic-block-in-function`; absent: none); instruction and file scope stay unattributed (capa does not report the containing function [src `capa/loader.py` `compute_static_layout`]; nearest-preceding-start guessing is forbidden). `project_function_id` needs exactly one project function on that side at that RVA (Ghidriff addresses minus the header ImageBase); several give `function-ambiguous` (symbol ambiguity).
4. Whole-set rejections: wrong artifact (2), wrong parser contract (1), stale output (a stored set whose `cache_key` differs from the key of the requested configuration, whose artifact is not the project's, or whose sidecar fails its SHA-256: `PT-TOOL-STALE`, a cache miss, never served).

### T6. Delta
1. Comparable only when both sides have the same engine, version, executable, rules and signatures identity, backend (+ version) and options, and both runs are `ok` or `none-found`; otherwise `comparable: false` with reasons (`PT-TOOL-MISMATCH`) and no entries.
2. Capabilities keyed by `(rule_id, scope)`, kind `capability` only (library rules are listed separately; limitation rules raise flag `capa-limitation`). Added/removed/unchanged; with the function pairing of the latest completed analysis run: added in a function that is new or paired as `modified` is `newly-introduced`; added in a function paired as `unchanged` is `newly-detectable` (same code, different detection); removed symmetrically `removed-with-code` / `no-longer-detected`; unattributed (file, instruction, unattributed basic block) `unlocalized`; no pairing or ambiguous pairing `unknown`.
3. Strings keyed by `value_hash` per type: added/removed/unchanged; a value on both sides with different type sets is `representation-changed` (static to decoded means newly obfuscated, not new content). Static strings are never attributed to functions.
4. Quality flags (informational): `toolchain-changed` (signature-certainty compiler/linker/tool differ), `packed`/`protected` (signature-certainty packer/protector/cryptor on a side), `heuristic-only`, `environment-unknown`, `capa-limitation`, `function-recovery-shift` (recovered-function counts differ by more than 2x). Flags never change a classification; with `toolchain-changed` or `packed`, `newly-introduced` and `removed-with-code` entries carry the note that the comparison may be distorted. Value gate: `value_gate: 'unvalidated'`; DiE output is never presented as reducing false leads.
5. Only genuinely localized entries (`function-start`, `basic-block-in-function`, `decoding-routine`, `stack-frame`) may name candidate functions; there are no scores.

### T7. Runner
Profiles are explicit user opt-in (CLI default `basic`): `basic` = capa; `context` = capa + FLOSS; `full` = capa + FLOSS + diec (quality gate). `--engines` must be a subset of the profile. Jobs = engines x {older, newer}; `max_parallel` 1 (default) or 2; one job's exception is that job's `failed` run; cancel is cooperative (pending jobs become `cancelled` without spawning). Cache key = `domain_id('tool-evidence-cache', 1, {artifact, engine, version, executable, rules identity, signatures identity, backend, backend_version, options, parser contract})`; a hit is re-validated (contract, binding, sidecar hash) and reused without spawning (`cache_hit`, new run record); a failing hit is a stale miss and the tool runs.

T7.2 FLOSS deobfuscation is never in a profile; it needs `--floss-deobfuscate`, which records the SHA-256 of this consent text (`EMULATION_CONSENT` in `floss.py`): "FLOSS deobfuscation (stack, tight and decoded strings) runs the vivisect CPU emulator inside the FLOSS process on this computer. The emulator interprets the target's machine code instruction by instruction in a Python model of the CPU and memory: the target is not loaded by Windows, not executed natively, and the Windows API calls it makes are answered by FLOSS's built-in stubs, not performed. Hostile code still drives a complex emulator and can take a long time or a lot of memory. PatchTrace runs it in a private scratch folder with a restricted environment and a timeout. Static strings never need it."

### T8. CLI (`intelligence/tools/cli.py`, hook in `cli.py`)
- `patchtrace intel-tools probe [--capa EXE] [--floss EXE] [--diec EXE] [--diec-db DIR] [--diec-lib DIR] [--capa-rules DIR] [--capa-sigs DIR] [--json]`

Executables come from the options or `PATCHTRACE_CAPA`, `PATCHTRACE_FLOSS`, `PATCHTRACE_DIEC` (+ `PATCHTRACE_DIEC_DB`, `PATCHTRACE_DIEC_LIB`, `PATCHTRACE_CAPA_RULES`, `PATCHTRACE_CAPA_SIGS`) and must be absolute; PATH is never searched. Envelope `enrichment-cli/1`. Exit codes: probe 0 when at least one requested engine is supported, else 2; run 0 = evidence produced by every job, 4 = all jobs `ok`/`none-found` without any evidence, 3 = partial or runtime failure, 2 = nothing runnable or invalid input, 5 = cancelled; delta 0 = comparable with changes, 4 = comparable without changes, 2 = evidence missing for a side, 3 = rejected (mismatch, stale, corrupt). Default output redacts secret-looking strings (`--show-secrets` reveals them), shows basenames instead of paths and never prints stderr excerpts or markup.

### T11. Audit amendments (2026-10-14, `docs/audits/20261014-C-tool-adapters.md`, tests `tests/test_intel_tools_audit.py`)
Additive to T1-T10; where a line below differs from T1-T10, this block wins.
- **Typed failures (TA-1).** `parse()` never lets a pydantic `ValidationError` escape: an address or offset outside the record range (`Address` 64 bits, `file_offset` < 2^40) is an anomaly (`address-out-of-range`, `offset-out-of-range`) and the location is dropped, a base outside 64 bits is `PT-TOOL-ADDRESS`, any other refused value is `PT-TOOL-OUTPUT`.
- **Exact stdout (TA-4, T4).** `ProcessResult` gains additive `log_bytes`, `stderr_bytes`, `stdout_total`, `stderr_total`; `Execution.stdout_raw` is what the tool wrote, `stdout_digest` hashes those bytes, strict UTF-8 is enforced by `load_json_strict`, and oversize is a byte count (`stdout_total > limit`), never re-encoded replacement text.
- **Bounded time and memory (TA-5, T4).** `run_process(max_output_bytes=)` stops the child (`reason: output-limit`) as soon as stdout passes the limit; `process.execute(memory_limit_bytes=)` passes the cap through (Job Object / RLIMIT_AS). Both are `failed/PT-TOOL-LIMIT`.
- **Pin enforced (TA-6, T1).** `pins.PINNED_EXECUTABLES` lists the executable SHA-256 of every verified release (same values as `tools/intel_tools_pin.json`). A probe is `supported` only for a pinned executable, or for another build when the caller sets `accept_untested` (`--capa-accept-untested`, `--floss-accept-untested`, `--diec-accept-untested`); `ToolManifest.pin_status` is `pinned|unpinned`, an unpinned accepted build is `untested_version`. diec additionally needs the pinned signature database. Immediately before every spawn the runner calls `process.verify_executable` (re-hash; mismatch `PT-TOOL-STALE`), and `capa.prepare` / `diec.prepare` compare the digest of the copied rule, signature or database directory with the probed digest (`PT-TOOL-STALE`). The hash-to-exec window is narrowed, not closed.
- **Delta (TA-2, TA-3, T6.2/T6.3).** Capabilities stay keyed by `(rule_id, scope)`, but a rule present on both sides is also compared link by link for function/basic-block/instruction scope: localized matches pair through the function pairing, matches in functions the pairing does not know cancel by count, unlocalized matches compare by count, and the remainder becomes an extra `added`/`removed` entry classified from its own links (`newly-introduced`, `newly-detectable`, ..., `unknown`). File-scope rules keep presence comparison. A truncated side cannot prove absence: `added` against a truncated older side and `removed` against a truncated newer side are classification `unknown` (capabilities) or change `indeterminate` (strings, environment) and never count as a change. Truncation keeps a sorted prefix (capa by rule, scope, address; diec by filetype, type, name).
- **Probes (TA-10).** Probes never raise (an unusable environment is an unsupported manifest); a timeout, cancel or spawn failure is reported with its reason and not cached.
- **Text (TA-8, TA-9, TA-11).** Names the tool reports about the file go through `process.tool_text` (no path scrubbing, control and bidi characters escaped); `process.sanitize` is for stderr and error text only. A capa rule name over 256 characters is shortened with a hash suffix (anomaly `rule-id-shortened`). FLOSS deobfuscation must report every requested type enabled (TA-7); a FLOSS `imagebase` that differs from the header leaves VA-based links unlocalized (`base-differs`, TA-12). `load_json_strict` rejects `1e999` (TA-16).

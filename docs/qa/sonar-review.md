Source/dataflow: icon `--out` is explicitly `type=Path`, passed by the local invoking user. The version generator likewise accepts `--out`; its `write(fields,out)` is also called by the build with repository-owned `build/windows-resources/version-info.txt`. Both make the requested parent directory, create a unique `NamedTemporaryFile` in that same parent, write generated bytes, then `os.replace(staged,out)`. No advisory, PE resource, remote data, or model response supplies the destination in these scripts. No elevated service or sandbox authority boundary was found. The final destination symlink is replaced as a directory entry rather than followed; arbitrary parent choice remains intentional CLI output selection.

Existing `tests/test_windows_build_resources.py` explicitly tests replacing the caller-selected preexisting output, preserving unrelated fixed `.tmp` files and their symlink targets, cleaning the owned random stage after failed replacement, and cleaning it after partial write. These were inspected at the exact PR head, not newly run by this reviewer. The exact-head Windows/Linux QA jobs passed, but that is not an independent security exploit reproduction.

Triage: **unproven finding; not closed as false positive**. A local user can request overwrite of another same-user-writable file through `--out`, but that alone demonstrates the advertised capability, not path traversal across an identified authority boundary. Constraining output to a new invented directory would change the existing CLI contract. Do not claim the gate is fixed, suppress the finding, or add output restrictions merely to obtain green status. Obtain Sonar's detailed flow or an actual boundary-crossing reproduction before deciding a security change. A separate no-clobber policy would require an explicit contract decision and is not established by these annotations.

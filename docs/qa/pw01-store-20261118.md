# PW-01 inventory persistence verification — 2026-11-18

## Scope

This slice implements `inventory_store.py` over the existing `WorkspaceStore`
connection and content-addressed object directory. It owns no network operation,
advisory edge, selection workflow, CLI command, or UI. Sources in these checks are
synthetic CSV and HTML. The tests prohibit sockets and do not execute target code.

The implementation follows section 5 of
[`kb-file-inventory-csv.md`](../specs/kb-file-inventory-csv.md). The lead also
approved narrow support-page retention, captured parser budgets, separate count
queries, and distinct identities for distinct acquisition receipts.

## Public interface

All functions receive an already-open `WorkspaceStore` and leave its lifetime to
the caller. Cancellation tokens expose `is_set()`, as `threading.Event` does.

| Function | Result and relevant options |
| --- | --- |
| `add_inventory(ws, raw, context, *, now, asserted_source=None, retrieval=None, limits=DEFAULT_LIMITS, cancel=None)` | `(InventoryImport, added: bool)` |
| `get_inventory(ws, import_id, verify=True, *, cancel=None)` | `InventoryImport` or `None`; raw replay enabled by default |
| `list_inventories(ws, *, limit=100, offset=0, verify=False, cancel=None)` | Immutable tuple ordered by `import_id` |
| `inventory_count(ws)` | Total row count without loading records |
| `add_support(ws, raw, page_url, *, now, retrieval=None, cancel=None)` | `(SupportImport, added: bool)` |
| `get_support(ws, import_id, verify=True, *, cancel=None)` | `SupportImport` or `None`; raw replay enabled by default |
| `list_support(ws, *, limit=100, offset=0, verify=False, cancel=None)` | Immutable tuple ordered by `import_id` |
| `support_count(ws)` | Total support row count without loading records |
| `referenced_raw_hashes(ws)` | Sorted, unique raw SHA-256 references for the existing orphan reporter |

`InventoryImport`, `SupportImport`, and `RetrievalProvenance` are strict frozen
records. Unknown properties and coercions are rejected. The inventory record
contains its `SourceDoc`, complete `CsvInventory`, optional inert
`asserted_source`, and optional exact retrieval receipt. The support record
contains its `SourceDoc`, explicit `page_url`, parser version, and
`extraction_sha256`, the SHA-256 of canonical JSON from `extract_links(...).as_dict()`.
The facade can extract typed links again from verified raw bytes for display.

`verify=False` still verifies the row checksum, strict JSON, typed record,
identity, and duplicated database columns. It omits raw-object reads and parser
replay. Selection and trusted detail operations must use `verify=True`.

## Identity and provenance

Raw objects contain the original bytes, compressed using the existing store.
Their location is `objects/<sha[:2]>/<sha>.gz`. Source identity remains the shared
`kbc.source` identity over source kind and raw SHA-256. Multiple contexts and
provenance claims can therefore share one raw object without replacing each other.

Inventory import identity additionally binds the parser inventory identity,
source provenance, optional asserted URL, and complete retrieval receipt. Captured
parser limits are already bound into the inventory identity. Local import time
does not affect the identity; a repeated local import returns the first record
and its original timestamp. A receipt's retrieval timestamp identifies the actual
acquisition event and is bound. Reusing that same receipt is idempotent; acquiring
identical bytes again at a different time creates a separate provenance record.

A local import has `origin=local-import`, `uri=None`,
`authenticity=unverified-local-file`, and `lineage=analyst`. An asserted HTTPS URL
remains a separate field and has no transport authority. Local HTML's explicit
page URL only supplies context for relative links.

Only `FetchedSource` is accepted by the new-import `retrieval` argument; a caller
cannot pass a receipt dictionary to upgrade a local import. Its exact bytes,
digest, size, kind, bounded URL chain, endpoints, timestamp, and rebuilt plan
digest are validated. Fetched sources use `origin=https-fetch`,
`authenticity=tls-allowlisted-host`, and `lineage=microsoft-support`.
`SourceDoc.uri` retains the original request URL. The receipt retains the final
URL and complete ordered chain. Fetched support HTML must use the final URL as
its `page_url` for relative-link resolution. This records transport provenance,
not a signature or vendor-authorship assertion.

An offline synthetic fetch result for integration tests can be constructed as:

```python
from hashlib import sha256
from patchtrace.kbcorrelation.sources.inventory_fetch import FetchedSource, build_plan

url = 'https://download.microsoft.com/download/a/b/c/files.csv'
plan = build_plan(url, kind='file-inventory')
result = FetchedSource(
    kind=plan.kind,
    original_url=plan.urls[0],
    final_url=plan.urls[-1],
    redirect_chain=plan.urls,
    raw=raw_csv,
    sha256=sha256(raw_csv).hexdigest(),
    retrieved_at='2099-03-01T00:00:00Z',
    plan_sha=plan.plan_sha,
)
record, added = add_inventory(ws, raw_csv, context, now=now, retrieval=result)
```

This fixture exercises the persistence seam. It does not claim that a request was
made; actual service retrieval receives `FetchedSource` from `fetch_source`.

## Transactions, replay, and bounds

The two extension tables are `kb_inventory_imports` and `kb_support_imports`.
Each row has schema version 1, import ID, raw SHA-256, raw size, full record JSON,
and the JSON's SHA-256. Append-only triggers reject `UPDATE` and `DELETE`.
Table and trigger creation occurs inside the same `BEGIN IMMEDIATE` transaction
as the first insertion. The original advisory schema and `PRAGMA user_version`
remain unchanged. Old workspaces lacking these tables return empty pages and zero
counts without migration; newer read-only workspaces remain readable and refuse
all additions.

Parsing and record validation precede raw writes. Raw bytes are written before
the row transaction, so an interruption may leave an unreferenced object. It
cannot publish half a record or half a migration. Fault hooks are
`inventory_after_object`, `inventory_before_commit`, `support_after_object`, and
`support_before_commit`. Cancellation is checked before parsing, before raw
writes, after raw writes, and immediately before commit. Existing claims survive
every tested rollback. A second writer that commits the same import first wins;
the other writer returns that immutable record with `added=False`.

Verified reads check the compressed-object bound and regular-file status before
loading bytes, then bounded decompression, exact raw size and SHA-256, and exact
parser replay with captured context and limits. Support replay compares its
deterministic extraction digest. Missing or corrupted objects are never silently
repaired by a repeated import or a new context. Symlinked object files or cache
subdirectories are rejected. The caller-selected workspace root may itself be a
link; this is not a sandbox against a concurrent process replacing parent paths.

Serialized records and a returned page each have a 64 MiB ceiling. Pages contain
at most 100 records; offsets are bounded nonnegative integers. SQLite bounds JSON
and identifier fields before returning them to Python. The workspace budget
counts referenced raw bytes once across advisory and inventory/support tables,
plus inventory/support record JSON. The budget is checked again under the writer
transaction. The parser and fetch layers retain their independent raw-byte and
time limits.

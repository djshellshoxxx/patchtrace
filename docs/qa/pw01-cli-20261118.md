The CLI does not parse CSV, retain raw objects, make selection decisions or build

the exact `kb inventory <verb>` envelope names and allows help and argument
failures without initializing service ports.

## Completed behavior

All seven specified commands are wired: `import`, `list`, `show`, `select`,
`links`, `plan` and `fetch`. The namespace supports existing workspace and JSON
options, explicit CSV dialect/locale/product/build/architecture context, bounded
pages and row filters, and explicit revision-bound selection. Import/source IDs,
raw row references, accepted/rejected/duplicate/conflict/truncation counts and
source authenticity remain in the service results.

Fetch accepts a strict standalone plan or the complete envelope produced by
`inventory plan --json`. Exact plan/host consent is passed unchanged to the
service. An unexpected redirect returns the proposed plan and preview, with an
error on the caller-supplied stderr stream; the unexpected destination is not
requested. `--offline` refuses even a consented fetch. A support-page fetch does
not follow its extracted links.

The existing generic dispatcher does not classify `SourceError`, and classifies
a store cancellation as an ordinary runtime error. This new namespace therefore
maps both source and store errors explicitly, preserving their typed issue and
details. Cancellation returns exit 5. Invalid local CSV/HTML or invalid pure
plans return exit 2; partial results and damaged/stale stored state return 3;
empty successful inspection returns 4. Error text removes terminal/bidirectional
controls through the existing text helper. Service-produced errors also respect
the supplied stderr stream instead of writing to global stderr.

error codes, missing/incorrect consent, offline refusal and support-link

DNS forbidden and asserts that no Qt package was imported.

Transport cases use authored response bytes and an injected opener while keeping
the production exact-plan/consent/redirect checks. They are CLI integration
evidence, not live Microsoft or native TLS acceptance. All ordinary test sockets
are denied.

Initial test issues were corrected without changing product assertions: replacing
the socket class with a function prevented Python's SSL class declaration in the

attempt named a nonexistent historical test file and exited 4 before collection;

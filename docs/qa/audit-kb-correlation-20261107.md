## Dispositions after the audit

- 2026-11-11 KBA-06 fixed (decision: skip identical bytes). `lineage.predecessor` passes over every earlier row that carries the target's own SHA-256; those rows stay in the window, the nearest earlier admissible build with other bytes is the older side, and none is `NO_OLDER`. Rule recorded in `docs/specs/kb-cve/31-C-product-build-pairs.md` C4. The strict xfail is now a plain test; added `test_kba06_*` in `tests/test_kbc_lineage.py` and `tests/test_kbc_resolver.py` (pair ids of the committed fixtures pinned to the pre-fix values). Evidence class: synthetic timelines only, no live Winbindex data.
- 2026-11-11 KBA-08 fixed (alias catalog version 2). `Version 2004` is a release token and the exact client names without one (`Windows 10|11 for x64-based|32-bit|ARM64-based Systems`) get the first release of their generation: keys `10-1507`, `10-2004`, `11-21H2`; LTSC/LTSB, IoT and any other wording stay unkeyed. Rule recorded in `docs/specs/kb-cve/31-C-product-build-pairs.md` C1. Scope ids change only for names with the token `Version 2004` or of that exact release-less form (the other 39 of the 41 products of the committed fixtures are pinned to the ids main derived), so a stored investigation on a changed name gets the existing "repeat the search" refusal (`test_kba08_stored_investigation_on_a_rekeyed_product_must_repeat_the_search`). Side effect: any other name with that token, such as `Windows Server, version 2004`, now derives release `2004` (no key for a server), which changes its scope id too. The strict xfail is now a plain test; added `test_kba08_*` in `tests/test_kbc_products.py`, `tests/test_kbc_resolver.py` and `tests/test_kbc_pairs_index.py`. Evidence class: synthetic and fixture tests only; the Windows 10 form occurs in the committed MSRC projection, MSRC use of the `Version 2004` and release-less Windows 11 forms is UNVERIFIED offline, and no live Winbindex lookup was run.

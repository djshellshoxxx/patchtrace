## Implemented desktop journey

The KB panel's **File inventories…** button remains available with no project
open. It opens one reusable dialog with three tabs:

1. **Saved CSV** captures a local path, KB, optional product scope/product/release/
   build/asserted source, and explicit architecture, delimiter and numeric locale.
   Import does not require an investigation. A supplied source URL remains an
   unverified assertion for a local file.
2. **Retained inventories** lists sources in pages of 20. The analyst explicitly
   chooses a source and inspects its verified retained rows. Name, architecture
   and metadata-state filters page at 200 rows. Source counts, provenance,
   diagnostics, row references and conflicts remain available in plain text.
   No first source or first row is selected automatically.
3. **Support sources** inspects saved HTML as inert local data, exposes accepted
   and rejected links, and copies an accepted link only when explicitly chosen.
   An exact request preview is separate from the unchecked consent control and
   fetch action. CSV fetches use the context entered on the Saved CSV tab.

Filename selection requires an existing investigation ID, explicit product scope
ID, and exact current revision, either supplied to the dialog by its caller or
entered by the analyst. Those values are available through the existing search,
products and components service/CLI results. The dialog never creates an
investigation, guesses a scope, chooses a pair, downloads a binary, or executes
a target. Unknown inventory-to-product mapping requires the separate explicit
scope assertion; the backend enforces scope consistency and revision freshness.
ARM64 and other ineligible rows remain inspectable, with the selection action
disabled. An eligible selection retains metadata provenance and stays tier E.

## Concurrency, cancellation and consent

Each action captures immutable JSON and a workspace path on the widget thread.
The existing TaskRunner executes it with a new KbService and worker-owned
WorkspaceStore. Formatting of potentially large result and row details also
occurs in the worker. Detail display is bounded, with explicit truncation text;
full raw data remains in the workspace.

Input edits, cancellation, project changes and dialog rejection invalidate the
generation and cancel the operation token. A closed dialog cannot accept late
results. Changing workspace clears the old workspace's source/row selection.
Changing project clears the explicit investigation target. Expected source/store
errors and unexpected worker failures retain the previous successful displayed
result; unexpected exception messages are not exposed.

Fetch consumes the currently displayed plan and its exact hosts/digest once.
Input or context edits invalidate that consent. Redirect drift presents the
service's proposed plan, enables **Review revised request**, and keeps fetch
disabled. Reviewing that proposal only generates a new preview; the analyst
must explicitly approve it before another fetch. No changed target is requested
automatically by the UI.

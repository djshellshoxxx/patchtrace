# Labelling guideline g1 (target A only)

Status: draft for C9-10 (no labelling campaign has started; decision O4 open). Versioned: any change creates
`g2` and the g1 batch stays in the report (calibration-corpus-and-model.md §5.1, §5.6).

## Question
Do the older and newer endpoints implement the **same source-level function**, one-to-one?

| Label | Use when |
|---|---|
| `same` | Same source function, tolerating compiler differences and patch-sized edits. Large legitimate rewrites of the same function are still `same` (subtype N12, "hard positive"). |
| `different` | Different source functions. Split/merge/partial-inline pairs are `different` with subtype N4. |
| `no-counterpart` | The true counterpart is absent on one side (added, removed, inlined away), so any pairing is wrong. |
| `indeterminate` | Undecidable within the 10-minute budget. Counted; excluded from fitting; worst-case bound if > 5 % of a stratum. |

Subtypes N1-N12 as in the spec §5.4 (N1 clones/templates, N2 thunks/stubs, N3 static library/CRT code, N4
inline/split/merge, N5 address-coincident, N6 similar CFG different semantics, N7 added/removed paired to
unrelated, N8 unrelated-binary controls, N9 compiler-generated helpers, N10 PGO hot/cold pieces, N11
table/jump-table dominated bodies, N12 large rewrite of the same function).

## Blinding (enforced by `label.py` `blind_view`)
Annotators see bytes/disassembly side by side, callers/callees, strings, imports and sizes. They do NOT see
any engine score, verdict, match type or name-match. Symbol names appear only in a second, `reveal` pass after
the blind label is recorded; a change after reveal is logged. No LLM output may ever be stored as a label.

## Debug-info (PDB/DWARF) truth: known pitfalls (Tier R and symbol-derived labels)
Research status: standard linker/compiler behaviour, not yet verified against primary documentation.
1. `static` / anonymous-namespace names repeat across translation units: key symbols on
   (name, source file, line), never on the name alone.
2. Identical COMDAT folding (`/OPT:ICF`) maps several source functions to one address: truth is many-to-one.
   Build one profile with `/OPT:NOICF` and keep ICF in another with its own subtype, or drop folded functions
   by a counted, pre-written rule.
3. `/INCREMENTAL` and import thunks create jump stubs (N2): build with `/INCREMENTAL:NO`.
4. `/LTCG` and PGO inline and split functions (`$cold`-like pieces): N4 / N10.
5. Compiler-generated functions (CFG dispatch, `__security_check_cookie`, SEH helpers) have no source
   identity: N9.
6. Compiler-generated names (lambdas, dynamic initialisers) differ between compiler versions.
7. Symbol-derived labels are valid only for engine runs with symbols NOT loaded (`symbol_provenance=none`);
   confirm Ghidra did not auto-load an adjacent PDB (delete it before the run).

## Valid Tier R sources (recipes and hashes only are published, never binaries of third-party code)
- Patch-tag builds of permissively licensed C libraries (adjacent release tags and CVE-fix commits), built
  with clang-cl / mingw-w64 (decision O6) or MSVC on a Windows runner.
- Microsoft-authored open-source projects built locally with MSVC (e.g. runtime native parts, terminal, WIL,
  STL): real MSVC code generation; publish source pins and build scripts only.
- Licences of every upstream pin, and of BinKit, BinaryCorp, REFuSe-Bench, Assemblage and Winbindex, are
  UNCONFIRMED until a person reads the LICENSE/data card (unknown counts as "do not use").
